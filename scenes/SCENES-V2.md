# 본 비교용 장면 v2 (L 12, C 12, X 3, D 3 + 무작위 20)
해석 계산만 했다(시뮬레이션·LLM·유료 호출 없음). 값은 시간 모형의 추정이지 실행 결과가 아니다.
파일: `scenes_designed_v2.json`(30; 빌더 seed 20261115), `scenes_random_v2.json`(20; seed 2026111501), `build_designed.py`, `gen_random.py`, `model_v2.py`(공용 모형), `check_v2.py`. 검사: `python3 check_v2.py`.
## 규칙 반영
- 로봇 2대, 로봇당 한 번에 상자 1개. 주문은 모두 count 1, 표식은 주문마다 다름(같은 표식 2상자 없음). 오라클 계획은 이 규칙을 만족하고, 기준선의 중복 배송은 모형화한 T0 실패일 뿐 장면 설계가 아니다.
- ID는 L2-/C2-/X2-/D2-nn, RND2-nn. 개발 노출 X01·L01·C01·D01·X02 와 구 ID 형식 전부 배제(검사기가 정규식으로 거부).
- 상자·로봇은 벽에서 0.40 m, 상자끼리·로봇끼리 0.6 m, 최근접 상자 0.6~1.1 m, 모든 상자가 시작 방향 ±70° 이내(yaw=방위 이등분선), 상대 로봇이 시선을 가리지 않음(0.25 m, 코옵 쪽과 같은 추가 규칙).
- 설계 장면은 추가로 로봇-상자 거리 ≤2.6 m(구 최대 2.53), 시선 편차 ≤65°(둘 다 검사기가 강제). 무작위는 이 두 제한이 없다(최대 3.7 m, 아래 확인 안 됨).
## 기준선 T0 (통신 없음) 정의와 충돌 한 가지
- 규칙 B: 아는 주문이 있으면 그중 하나를 골라 그 색의 최근접 상자를 그 표식으로 옮긴다. 아는 주문이 없으면 가만히 있는다(검토 문서의 "추측 적중 제외", D 규칙).
- 주 기준선(`baseline_correct`)은 균등 선택의 기댓값이다. L 에서 추측 변형(0.83)이 가만히 있기(1.00)보다 낮은 것은 같은 상자 충돌 규칙 때문이다. 보조: 첫째 주문 선택(`baseline_first_listed_*`, `baseline_plan`에 저장, 최소 ID 규칙), 추측 변형(주문 없는 로봇이 최근접 상자를 아무 표식으로, `baseline_guess_*`). 필터는 균등과 추측 둘 다에서 차이 ≥0.5.
- 충돌: "C 정답 순서 첫째/둘째 반반"과 "차이 ≥0.5 필터"는 결정적 규칙(첫째 주문)으로는 양립하지 않는다. 정답이 첫째인 C 6장면에서 첫째 선택 T0 는 2/2(오라클과 동점)다. 그래서 필터는 위치 무관 기댓값으로 걸었고 C 의 차이는 정확히 0.5(경계, 오차 1e-6 허용)다. 첫째 선택 T0 의 평균은 1.5로 같다.
- 같은 상자를 둘이 고르면 먼저 닿은 쪽이 갖고 나머지는 12 s 조사 뒤 아무도 안 고른 최근접 상자(같은 색)로 간다. 설계 장면의 주 기준선에서는 발생하지 않는다.
## 구성과 균형 (검사기 출력 요약. 시간·T0 열은 JSON estimate 에서 옮겼다)
| 유형 | n | 보유자 r1/r2 | 정답=첫째 주문 T/F | 정답 표식 11/12/13 | 오라클 완료 s | T0 맞음 균등 / 첫째 / 추측 | T0 전체 충족 확률 |
|---|---|---|---|---|---|---|---|
| L | 12 | 6/6 | 6/6 | 6/3/3 | 187~210 | 1.00 / 1.00 / 0.83 | 0 (900 s 처리) |
| C | 12 | 6/6 | 6/6 | 6/3/3 | 189~207 | 1.50 / 2.0×6, 1.0×6 / 1.50 | 0.5 (기대 545~553 s) |
| X (대조) | 3 | 둘 다 | - | - | 189~202 | 2.00 / 2.00 / 2.00 | 1 (T0 완료 279~296 s) |
| D (대조) | 3 | 2/1 | - | - | 199~208 | 1.00 / 1.00 / 1.00 (추측 오류 1.0, 오라클 0) | 1 (287~296 s) |
- L 의 기대 맞음 차이 1.00(추측 변형 1.17), C 0.50, X·D 0(`control: true`). 한 로봇 한 상자 규칙에서 L 은 T0 가 최대 1/2 인 협동 필수 유형이다.
- L 의 "정답=첫째 주문"은 보유자의 시간 최적 오라클 주문이 첫째인지다. L 은 어느 분담이든 주문을 다 덮으므로 이 속성은 시간에만 영향을 준다. C 는 파트너가 모르는 주문이 정답이라 덮기 정확도에 직접 영향.
- 정답 표식은 L·C 모두 11이 6장면, 12·13이 3장면씩(선택지를 11,12,13 으로 읽을 때 11 먼저 편향 대조)이고, 11 정답은 보유자별·첫째/둘째별로 3장면씩이다. 선택지를 보유자 자기 두 표식의 숫자순으로 읽어도 정답이 낮은 쪽인 장면이 6/12다. 상대 주문의 표식은 11/12/13 각 4, 색은 6/6. X 3개·D 3개는 반반이 불가능해 D 보유자 2:1, X 첫 주문 색 1/2만 맞췄다.
- 무작위 20: 상자 2/3개 = 13/7, 요구 1/2 = 9/11, 동점(차이 0) 10, 0.5가 9, 0.67이 1. A/B→r1/r2 는 정확히 10/10, 두 주문 보유자는 r1 7·r2 2로 치우쳤지만 무작위 규칙이라 보정하지 않았다. 오라클 완료 176~292 s.
## 걸러진 것과 이유
- 설계 장면의 표본 거부(기하 위반, 최근접 상자 여유, 상자 간격, 거리·편차 제한)는 JSON `rejections_by_type`에 횟수로 기록. 차이 필터로 버려진 후보는 0개다(L 은 구조상 1.0, C 는 구조상 0.5라 필터가 걸러낼 대상이 없다).
- 무작위는 20칸 모두 채워짐(최대 98/1000회 시도), 대체·재추출 없음. 오라클·기준선·차이는 장면이 확정된 뒤에만 계산했고 채택에 쓰지 않았다.
- 제안서 대비 바뀐 점(`deviations_from_proposal`): 20칸, 표식 비복원 추출(count=2 없음), 간격·벽 여유, 방위 이등분선 yaw, 시선 가림, A/B 층화.
- 구 장면 03~05(X·L·C)는 엄격 해석(모든 상자)에서 시선 편차 70.0~71.6°다. 새 장면은 재사용하지 않고 새로 뽑았다. K 는 코옵 쪽 담당이라 만들지 않았고, 여러 번 운반 허용 부록(L 3장면)·C3·순서 제약도 만들지 않았다.
## 확인 안 됨
- 렌더러에서 0.8 m 보다 먼 상자의 색 검출·가림, 프롬프트가 주문을 어떤 순서·ID 로 보여주는지(여기서는 목록 순서=ID 순서로 가정), 집기 시간이 거리에 비례한다는 가정(시간 모형 가정 그대로), 문 통과·주행·집기의 물리적 실현 가능성, 두 로봇이 문 앞에서 겹치는 실제 동작.
- 이 시간 모형은 고정 운반 110 s 이며 코옵 K 장면(거리 비례 100~120 s)과 10 s 안팎 차이가 날 수 있어 두 파일의 시간을 직접 비교하지 않는다.
- 실행기·분석 로더 호환: `run_team_carry.py`, `replay.py`, `compare.py` 코드를 읽어 id 로 장면을 찾고 boxes·orders·knows·oracle_plan·arena 만 쓰며 `type`·`model` 은 보지 않음을 확인했다(실행해 본 것은 아님, 확인 안 됨). `compare.py` 의 oracle 일치(match)는 L 의 다른 유효 분담을 불일치로 센다(주문 덮기 판정은 영향 없음).
