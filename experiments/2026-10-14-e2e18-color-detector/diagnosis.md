# 원본에서 확인한 실패 경로

라벨은 사람 판정이 아니라 Codex가 실제 JPEG를 직접 보고 붙인 초안이다. 최초 근사 상자를 HSV 연결성분으로 보조한 뒤, 라벨 접촉시트 전체 90장을 다시 직접 확인했다. 작은 파랑 가장자리 조각 `027`은 색 띠/압축 테두리 구별이 모호하여 음성 분모에서 빼고, 직접 확인한 빈 바닥 `412`로 대체했다. `ambiguous-027.jpg`와 라벨 제외 이유를 보존한다. 검출 출력을 정답 라벨로 자동 승격하지 않았다. 사람이 확인하기 전까지 결과는 잠정이다.

- 구형 호출은 `e2e_end_colors.observe → v1.observe_beam`이다. 설치 시 `r.observe_beam`을 교체하므로 별도 `long_side_v1`의 검은 띠 검사에 다시 들어가는 구조는 아니다. v1은 라임 몸체에서 축을 잡으며, 색 검사 전에 몸체 최소점·평면·축 corridor 2.8cm 필터를 적용한다.
- v423/r2/45.3초(`064`)는 파랑 픽셀12,579개, 투영3,139점 중 corridor2,941점, 띠 길이3.672cm다. 몸체 지지는 [-6.085,+2.863]cm다. 충분한 파랑이 있어도 12cm 한쪽 몸체 지지 조건을 못 채워 `OWN_COLOR_GEOMETRY_UNRESOLVED`였다. 42.9초(`029`)도 길이3.556cm, 지지[-8.589,+2.683]cm로 같은 원인이다.
- 같은 v423의89.3초(`048`)는 기존에도 BAND_VISIBLE이다. 111.3초(`065`)는 띠 일부가 화면 아래에서 잘리고 수정 후에도 metric end 채택 불가다. 따라서 세 시점 모두 HSV 누락이었다는 해석은 틀리다.
- 실제 청록 띠(`247`,`400` 등) 색상 H 중앙84가 기존 상한83을 넘는다. 파랑 중앙120은 범위 안이다. 원거리 파랑(`355`,`417`)은 색 픽셀19/12개뿐이고 기존 기하 corridor에서는0점이다. 청록 원거리 `141`도 색 픽셀323개지만 corridor0점이다. 색상 범위 하나만 고쳐서는 해결되지 않는다.
- 기존 60양성 중 실패39: 기하 지지/길이 미결28, 잘림6, 색 corridor 미검출5. false admission은0/30이다. 기존 코드에는 독립적인 띠 존재 출력이 없어, 새 존재 재현율60/60과 기존 파지 채택21/60을 같은 성능 변화로 계산하지 않는다.

# 수정과 적용 범위

v430 `component_v3`: OpenCV HSV 연결성분 + 라임 인접 확인. 청록 H70–90/파랑112–128, S≥100/V≥35. 연결면적32pixel 미만은 제거한다. 최초6pixel 후보의 빈 바닥/빔 경계13pixel 잔상 등을 보고 DEV 기준을 조정했으므로 독립 검증 성능이 아니다. 띠 존재/영상 상자는 몸체 축 추정 실패에도 기록한다. 장면 RGBA·물리·카메라는 그대로다. grasp geometry 지지12cm는 유지한다.

v431 `component_short_v3`: 같은 검출기에 한쪽 몸체 지지4.5cm를 비교한다. 알려진 끝→띠 중심3cm보다 긴 지지를 요구하며, 양쪽 지지가 동시에 해당하면 모호함으로 거부한다. 기존 띠 길이1.5–6.5cm·평면·최소점·잘림 거부를 유지한다. 파지용 채택32/60(청록19·파랑13)으로 개선되지만90%에 미달한다. 나머지28는 기하 미결9·잘림14·corridor미검출5다.

띠 존재만으로 `Robot.beam`/station을 만들지 않는다. metric geometry가 `end_visible`을 인정해야 기존 접근기가 사용한다. 따라서 존재 검출60/60은 곧바로 미도달 감소/파지 성공을 의미하지 않는다. 원거리/잘린 관측으로 재관측 방향을 만드는 행동 개선은 이 변경에 포함하지 않는다.

# 수집과 해시

8개 실행에서 기존 인식 reason별 시간 분산 샘플590장(9,431,040byte tar 전송)을 ARM에서 개별 회수하고 프레임 원장의 SHA256과 전부 대조했다. 그중 직접 본60양성·20띠없는장면·10검정띠를 골랐다. 일부 근접 프레임의 상관성이 있고 실패 reason으로 층화한 목적 표집이다. 현재 코호트의 유병률/일반화 성능으로 해석하지 않는다. 원본은 ARM에 남고, 평가 라벨은 제어기로 전달하지 않는다.
