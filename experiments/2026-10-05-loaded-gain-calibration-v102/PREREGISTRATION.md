## 0. 범위와 정직한 한계

- 대상: HIGH 자세(`edge_view_150`)로 긴 보(`long_beam`)를 든 로봇 짝(r1+r2)의 **옆(left)·앞뒤(forward)** 정상 상태 속도 곡선, 구동 시간상수,
  정지 시간상수. 회전(turn)은 이번에 하지 않는다: fcc5215f의 HIGH 운반 구간은 회전 명령을 내지 않았다(기록된 명령 확인). v92 탐색 자료에서
  회전도 같은 모양(작은 명령에서 이득이 낮고 위로 갈수록 오름)이 보이므로 회전 운반이 생기면 같은 설계로 따로 측정해야 한다(미해결로 보고).
- 지상 진실(SIM 정답 변위)은 **오프라인 보정 산출에만** 쓴다. 제어 입력·단계 전환·성공 통보에는 넣지 않는다. 명령은 모두 미리 쓴 표이고
  물리 소유자는 중단(abort)만 할 수 있다. 학생 제어기·모델 호출·카메라 캡처 없음.
- 결과는 `DEV_PILOT`(탐색용)이다. `MEASURED_SIM`이 아니고 확증 표본이 아니다. SIM(MuJoCo) 물리에 대한 보정이며 실물 지형·하중 성능은
  주장하지 않는다. 하나의 하중(보 한 개, 같은 파지·자세)과 하나의 접촉 프로필(`cargo_noslip_v1`)만 측정한다.
- v92 적재 수집(`final-pair-v92-loaded-257953ec-20261003`)은 아래 가설을 세우는 데 **이미 본 탐색 자료**다(§1). v92 자료로 정한 규칙이
  새 자료에서 맞는지가 확증 부분이고, v92 자료는 적합에 넣지 않는다.

## 2. 가설 (확증 대상은 새 수집의 held-out)

- **H1 (게인 곡선):** 적재 쌍의 정상 상태 속도는 옆·앞뒤 각각 오프셋 있는 선형 v = g·sign(u)·max(\|u\|−u0, 0)(아핀 데드존)이고,
  현재 경사형 데드밴드(R0)는 \|u\|>0.04에서 체계적으로 틀린다(옆 0.0622에서 +6~8%).
- **H2 (지연):** 구동 시간상수 τ는 명령 수준과 무관하다(계단별 적합 τ의 퍼짐 ≤ 15%), 새로 적합한 τ가 현재값(0.966/0.968 s)의 ±15% 안이다.
  → 지연은 7.2% 편향의 원인이 아니다.
- **H3 (접촉 프로필):** 같은 접촉 프로필에서 fcc5215f 옆 leg(−0.0622, 128틱)를 새 수집이 재현한다: 새 수집의 해당 leg 이동이 fcc5215f 기록
  (0.7698 m)과 2% 안이다. → 접촉 프로필·파지·자세가 원인이 아니다. (다른 접촉 프로필에 대한 민감도는 이번에 측정하지 않는다. 두 기록의
  프로필이 같으므로 두 기록 사이의 차이를 설명하지 못한다는 뜻이다.)

## 4. 분석 정의 (고정)

- **변위:** `eval_only/r1/pose.jsonl`의 r1 기준 위치를 운동 시작(= 첫 표본 시각 + 40 s) 때의 r1 몸체 축(앞/왼)에 투영한 값 s(t). 이동 거리는
  구간 [시작, 끝 + 정지 1.5 s]의 s 변화. r2는 같은 값(부호 반대 축)으로 검산한다.
- **모형(공통):** PF `predict_to`와 같은 구조 — 0.05 s 걸음, 속도 1차 지연(명령이 있으면 축별 τ_axis, 모든 축이 0이면 공통 τ_stop),
  위치는 갱신된 속도로 적분. 정적 지도 형태 3가지(축마다 따로):
  - **R0** 현재 형태 c0=0 경사 램프: u_eff = u·min(\|u\|/u1, 1) (이득 g, u1) — PF·계약 코드 변경 없음(`DEV_PILOT_C0_ZERO_v1` 규칙 그대로)
  - **R1** 램프 + 자유 c0: u_eff = u·clip((\|u\|−c0)/(u1−c0), 0, 1) (g, c0, u1) — PF 코드 변경 없음, 규칙 키 변경 필요
  - **A** 아핀 데드존: u_eff = sign(u)·max(\|u\|−u0, 0) (g, u0) — PF·계획기·계약 코드 변경 필요
  참고용 **T**(구간선형 표: 적합 수준마다 v_ss)는 구조가 충분한지 보는 진단일 뿐 선택 후보가 아니다.
- **적합:** 역할 `fit`·`fit_duration`인 구간(네 run 모두)만. 최소제곱(`scipy.optimize.least_squares`, 경계 안, 여러 시작점), 잔차는 구간별
  상대 변위 궤적 [s(t)−s(구간 시작)] − [모형 같은 양] (0.05 s 격자, 구간 사이 모형 속도 상태 이월). 변수: 축별 (g, 형태 파라미터, τ_axis)
  + 공통 τ_stop. 모형 구간은 모든 run을 처음부터 이어 시뮬레이션한다(적합 대상이 아닌 구간의 영향은 구간 상대 변위로 분리).
- **held-out 평가:** 역할 `heldout`·`heldout_leg`인 구간(적합기가 읽지 않음, 코드가 강제). 구간별 상대 오차 e = \|D_모형 − D_실제\| / \|D_실제\|.
- **현재 모델 비교군:** `dev_refit_DEV_PILOT_C0_ZERO_v1`(fcc5215f가 쓴 값, 이득 1.3551/0.9642, u1 0.0266/0.0282, τ 0.966/0.968, τ_stop 0.0852)를
  같은 held-out에서 평가해 보고한다(선택 후보 아님).

## 5. 선택 규칙 (고정)

1. 수렴·내부해(모든 변수가 경계에서 먼 곳) 검사를 통과하지 못한 형태는 후보에서 뺀다.
2. 형태가 **합격**하려면: held-out 구간 전부(\|D_실제\| ≥ 0.10 m)에서 e ≤ 3.0%이고, 두 held-out leg(기록 재현)는 e ≤ 2.5%.
3. 합격 형태 중 선택: 코드 변경이 적은 쪽을 먼저 본다 R0 > R1 > A. 앞 순서 형태가 합격이고 held-out 상대 RMS 오차가 합격 형태 중 최소의
   1.5배 이하이면 그것을 고르고, 아니면 합격 형태 중 RMS 최소를 고른다. 동률이면 변수 수가 적은 쪽.
4. 합격 형태가 없으면 **불합격**: 보정 산출 없음. 가장 가까운 형태, 어느 수준에서 틀렸는지, 필요한 다음 측정을 보고한다.
5. 일부 수준만 틀릴 때(가장 높은 수준 몇 개만 불합격): 합격하는 수준 범위를 **적용 범위**로 기록한다. 산출 파일에 적용 범위를 넣고, 범위 밖 명령은
   보증하지 않는 것으로 표시한다(계획기·PF는 범위를 넘으면 경고를 남긴다).
6. 축(옆, 앞뒤)마다 따로 판정하고, PF·계획기 형태는 한 파일에서 축별로 다를 수 있다(코드는 `deadband`를 축별 벡터로 이미 받는다).
7. 규칙은 본 뒤에도 바꾸지 않는다. 바꾸면 README의 "사전 등록과 다른 점"에 이유와 함께 적고 규칙 변경 전·후를 둘 다 보고한다.

## 6. 가설 판정 (고정)

- **H1 지지:** 선택 형태가 A이거나(합격), R0가 불합격이고 A·R1 중 합격 형태가 있으며 A의 변수(`g`, `u0`)가 v92 탐색 값(옆 1.1746/0.00725,
  앞뒤 1.5709/0.00557)에서 각각 ±10% 안.
- **H2 지지:** 계단별 시간상수(v(t)=v_ss(1−exp(−(t−t0)/τ)) 적합, \|u\|≥0.025) 퍼짐 (최대−최소)/중앙값 ≤ 15% (축별)이고 새 τ가 현재값의 ±15%.
- **H3 지지:** 새 수집 left ±0.0622 leg 이동이 fcc5215f 기록 이동(0.7698 m)과 2% 이내(A·B, 두 부호의 크기).
- 반복성: 같은 수준·부호의 latA·latB(fwdA·fwdB) 이동 차이 ≤ 1%. 크면 보고하고 해당 수준을 해석에서 표시한다.
- v92 탐색 값과 새 값의 일치(같은 수준 0.025·0.040 옆·앞)를 보고한다(자세·시드 재현성).

## 8. fcc5215f 입력 재생 (고정, 산출을 만든 뒤)

기록된 fcc5215f(`v98-dev-probe-align_to_carry-fcc5215f`) 입력(own RGB 프레임과 자기 발행 명령)을 `replay_pf.py`와 같은 방식으로 PF에 다시 넣는다.
정답은 채점에만 쓴다.

- **구성:** (a) 기록된 보정(HEAD 그대로, `dev_refit_DEV_PILOT_C0_ZERO_v1`), (b) 산출 C(무하중만 고침), (c) 산출 C + v102 적재.
- **모드:** 전체 재생(영상 갱신 있음)과 순수 추측항법(`--nomeasure`, 모든 프레임 거부).
- **지표:** 옆 leg(seg 3–5 가운데 옆 leg 둘, 각 stop 도달 직전·직후)에서 PF 추정 위치의 옆 방향 오차(추정 − 정답)와 NEES. PF 시드 5개의 중앙값.
- **기준(고정):** 순수 추측항법에서 옆 leg 끝의 옆 방향 오차 \|추정−정답\| 중앙값이 (c)에서 20 mm 이하이고 (a)보다 작다(기록 편향은 약 52 mm).
  전체 재생에서는 (c)가 (a)보다 같거나 작아야 하며 앞뒤 leg와 다른 구간의 오차 중앙값이 (a)보다 나빠지지 않아야 한다(허용 +5 mm). NEES 중앙값은
  χ²(2) 중앙값 1.386 근처 여부를 참고로만 보고한다(합격 기준 아님).
- 재생은 개발 자료에 대한 점검이다. 다른 시작점·시드에서의 새 임무 성공은 아니다(별도 검증 필요).

## 9. 운영·안전 (고정)

- 표준 경로: `scripts/sim_cli workflow run zone-final-pair-loaded-gaincal-v102 -- ...`을 `ugrp_session.py run`으로, 조정 스크립트 `collect.sh`가
  `agent_sim_slots`로 비타이밍 SIM 슬롯을 획득한다. 한 번에 최대 2개, 부하가 높으면 1개. SIM 시간 결과이므로 wall 시간·속도 결론은 쓰지 않는다.
- 매 실행 결과에 loadavg 시작·끝과 동시 보유자를 기록한다. 시작 전 여유 공간 ≥ 10 GiB. 디스크 부족(ENOSPC)은 `HOST_ERROR`로 분류한다.
- 원본은 기본 체크아웃 `outputs/`의 새 절대 경로에 쓴다. 덮어쓰기 없음. 커밋된 SHA에서만 실행하고 소스는 수집 중 고정한다.
- 인터록이 중단하면(`HOST_ERROR`) 그 run은 완료로 세지 않는다. 같은 설계로 **한 번만** 다시 실행하고, 다시 중단하면 멈추고 보고한다.
- 불합격·중단·실행 불가도 모두 `experiments/2026-10-05-loaded-gain-calibration-v102/`에 기록한다.
