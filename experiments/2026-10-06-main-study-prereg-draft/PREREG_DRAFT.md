# 본 연구 사전 등록 초안: 자연어 대화가 다중 로봇 협업 효율에 주는 영향

작성일: 2026-10-06. **DRAFT / 미등록 / 미동결 / 실행 권한 없음.**

이 문서는 검토할 설계 제안이다. 실행 소스·모델·지도·분석 해시를 고정하거나 새 실행 번들을 예약하지 않는다. 아래 수치는 실험 결과가 아니라 표본 계획이다. 이번 작성에서는 시뮬레이션·물리·렌더·실제 모델 호출을 하지 않았다. 마지막의 **결정 필요**를 해결한 뒤 별도 최종 등록본과 독립 검토가 필요하다.

## 1. 근거와 범위

- [현재 상태](../../docs/current_status.md)는 9/30–10/1 단계 검증과 사후 봉인의 경계를 설명한다. [ROADMAP](../../ROADMAP.md)은 rule·무통신 LLM·대화 LLM 비교와 보류 seed 검증을 연구 과제로 둔다. 두 문서의 날짜별 상태를 오늘의 완주 증거로 승계하지 않는다.
- [10/5 시나리오 E2E 격차](../2026-10-05-scenario-e2e-gap/README.md)는 2대·빔 하나의 DEV 기록과 3대·여러 주문·s1–s8 완주 사이의 차이를 보여 준다. 이후 기능 PR의 병합도 정식 완주의 증거가 아니다. 모든 화물·사건·지도·심판의 준비 상태는 등록 직전에 별도 확인한다.
- 이번 대상은 [시나리오 v4](../../configs/zone_study_scenarios_v4/)의 **s1–s8 전체, 로봇 3대**, 세 조건 `rule/no_comm/peer_nl`이다. 이름이 비슷한 개발 단계 S1/S2/S3와 시나리오 s1/s2/s3을 구분한다. s1 축소판을 s1 전체 결과로 세지 않는다.
- 기존 [9/28 초안](../2026-09-28-main-study-prereg-draft/PREREG_DRAFT.md)은 4조건·6시나리오·한국어 제약·순차 검정 계획이다. 이번 초안은 **3조건·8시나리오·언어 제약 없음·고정 표본** 제안이며 이전 파일과 등록 기록을 덮어쓰지 않는다.
- [ZC3 초안](../2026-09-25-zc3-prereg-draft/README.md)의 교사 실행과 [b-v6h 문서](../2026-09-30-pair-v6h-carry/PREREG_DRAFT.md)의 기록 후 봉인은 본 연구의 새 확증 표본이 아니다. 이미 본 결과의 이름만 바꿔 사전 등록 자료로 만들지 않는다.

추정 대상은 **이 8개 고정 시나리오에서, 정해진 모델·로봇·제어기·SIM 비용 아래 대화 채널을 허용했을 때의 평균 팀 효율 변화**다. 사람 참가자는 없다. HRI의 시간 지표를 참고하지만 사람의 신뢰·만족, 실물 MasterPi 성능, 새 지도·새 작업으로의 일반화를 주장하지 않는다.

## 2. 가설과 비교 조건

**확증 가설 H1:** `peer_nl`의 실패 벌점 포함 완료 시간(PAR-2)이 `no_comm`보다 작다. 실제 검정은 양측 α=0.05로 하여 대화 때문에 느려지는 경우도 잡는다. 효과 부호는 항상 `peer_nl − no_comm`; 음수면 개선이다.

**보조 가설 H2:** 대화가 전체 주문 성공률과 배송 비율을 높이고 집결·통로 대기 및 중복 작업을 줄인다. **보조 비교 H3:** 두 LLM 조건 각각과 `rule`의 효율·성공·비용 차이를 본다. H2/H3와 시나리오별 차이는 탐색이며 H1이 실패해도 확증 결론으로 대신 올리지 않는다.

| 조건 | 고수준 결정 | 로봇 사이 대화 | 비교에서의 역할 |
|---|---|---|---|
| `rule` | 모델 없이 사전 명시한 결정 규칙 | 자유 대화 없음 | 구현된 규칙 정책의 기준선. 모델 호출·토큰은 실제 0 |
| `no_comm` | 로봇별 독립 LLM | 자연어 송수신 없음 | H1 기준 |
| `peer_nl` | 같은 모델·프롬프트 공통부·행동 목록 | r1/r2/r3 사이 자유 자연어 mesh | H1 처치. 한국어만 쓰라는 제한 없음 |

세 조건은 같은 저수준 제어기·관측·배치·작업·안전 가드를 쓴다. `rule`도 정답 위치나 전지적 중앙 배정을 받지 않는다. 세 로봇의 결정 규칙(주문 선택·역할·통로 우선순위)은 공개된 주문·로봇 ID·허용 관측만으로 정의하고 등록 전에 구현을 확인한다. 현재 [pair 계약](../../harness/pair_llm_contract.py)의 `rule`은 빔 하나·두 로봇용이므로 그대로 s1–s8 기준선이라고 부르지 않는다.

`no_comm`에도 공동 들기의 고정 enum 상태·GO 상호 확인처럼 실행에 필요한 최소 상태 채널은 남는다. 세 조건에 같은 필드·전달 규칙을 적용하고 등록 때 명세한다. 따라서 이름의 뜻은 **고수준 자연어 대화 없음**이며 모든 신호의 완전 차단은 아니다. 호스트는 메시지를 운반하고 형식을 검사할 뿐 역할·양보·경로를 대신 결정하지 않는다.

두 LLM 조건의 모델 버전, temperature, reasoning 설정, 문맥 길이, 기억 절단 방식, 출력 길이, 재시도와 공통 호출 계기를 맞춘다. `peer_nl`에만 생기는 메시지 수신·재호출·추가 토큰도 시간과 비용에 포함한다. 그러므로 H1은 **채널과 그로 인한 사고 기회를 포함한 총효과**이며 메시지 내용만의 효과는 아니다. 실제 호출 수를 사후에 같게 만들거나 호출 수로 주 효과를 보정하지 않는다. `rule` 대비는 모델 사용 여부까지 달라 자연어 단독 효과로 해석하지 않는다.

## 3. 공통 환경·입력·예산

- v4가 지정한 로봇 v3 지도, `arena_default` 시작, 표식 0개, 벽 높이 0.40 m, `cargo_noslip_v1`, weld OFF를 기본안으로 한다. 카메라 배치·FOV·로봇 외관·화물을 바꾸지 않는다.
- 연구 입력은 자기 RGB, 정적 지도·보정, 공개 주문서, 자기 발행 명령 이력, 허용된 자기 상태, 해당 조건의 메시지다. **공용 top RGB는 이 연구에서는 사용하지 않는 안**이며 평가 영상으로만 둔다. 초음파는 off를 기본안으로 하되 등록 전에 세 조건 전체에 대한 on/off를 결정한다. 명령 발행을 실제 이동·관절 상태 확인으로 취급하지 않는다.
- 실시간 정답 좌표·측정 관절·접촉·심판 성공·숨은 사건표·동료 raw 영상을 제어 입력, 호출 계기 또는 성공 통보로 사용하지 않는다. 사건 발생과 심판은 별도 평가 경로에서만 처리한다. 교사 보정·인위적 고정은 없다.
- v4의 **1800 SIM초/시행, HTTP 시도 90/시행·30/로봇, 출력 768토큰/호출**을 계획 기준으로 한다. 논리 호출도 90/시행·30/로봇 이하로 두는 안이다. 재시도는 같은 상한을 소비한다. 발화 수·입력 문맥·전체 토큰 예산은 등록 전 확정한다. pair DEV의 900초·다른 상한을 묵시적으로 가져오지 않는다.
- 시간은 작업 시작부터 모델 판단·메시지 전달·이동·집기·놓기·마지막 주문 판정까지다. 초기화·리셋 시간은 따로 기록한다. [SIM 비용 모형](../../docs/zone_sim_cost.md)의 계수·tokenizer·이미지 계산을 등록 전에 고른다. 잠정 계수라면 실측 지연이라고 부르지 않는다. wall 시간과 실제 모델 응답 지연도 기록하되 H1은 SIM 시간에 한정한다.

## 4. 시나리오와 seed 배정

아래는 v4 JSON에서 읽은 주문·물건 수다. v4는 v3의 주문·사건을 유지하고 지도 참조를 로봇 v3 지도로 바꾼 버전이다. 기존 JSON과 기존 해시를 이번에 수정하지 않는다.

| ID / v4 이름 | 지도 | 주문/물건 | 협업 부담과 사건 | 기존 DEV seed |
|---|---|---:|---|---|
| s1 `normal_mixed` | `zone_wide_door_geometry_v3` | 6/7 | 단독 화물과 2대 빔, 사건 없음; 중복 배정 | 601–603 |
| s2 `unmapped_blockage` | `zone_wide_two_doors_final_v3` | 3/4 | 크레이트 포함; 45초에 좁은 문 막힘 | 611–613 |
| s3 `late_rendezvous` | `zone_wide_door_geometry_v3` | 4/4 | 빔 포함; 12초부터 r3 주행 40초 지연 | 621–623 |
| s4 `narrow_door_standoff` | `zone_wide_corridor_final_v3` | 4/4 | 단독 화물·빔의 좁은 복도 양보, 사건 없음 | 631–633 |
| s5 `moved_dropped_item` | `zone_wide_door_geometry_v3` | 3/4 | 30초 cyan 이동, 62.5초 red 낙하 시도 | 641–643 |

| s8 `mixed_tiers` | `zone_wide_two_doors_final_v3` | 4/5 | 단독·크레이트 2대·tri_frame 3대의 배분 | 671–673 |

s5 사건은 해당 시각의 운반 상태에 따라 실제 효과가 없을 수 있다. `scheduled/triggered/applied`를 별도 기록하고 효과가 없었던 시행도 남긴다. 의도된 막힘·r3 지연·낙하는 HOST_ERROR가 아니다. s5의 주입된 낙하도 stop-ON 가드가 정지시키면 그대로 실패다. 복구를 관측하려고 가드를 우회하지 않으며, 낙하 복구라는 시나리오 의도와의 충돌은 최종 설계 전에 해결해야 한다. s6의 순서 관계가 물리적으로 필수인지는 등록 전 검증 대상이며 설계 의도를 관측 사실로 쓰지 않는다.

**블록 = (시나리오, 환경 seed), 한 블록에 세 조건 각 1회.** 시행은 로봇 한 대가 아니라 전체 3대 팀의 에피소드다. 메시지·물건·프레임·명령을 독립 표본으로 늘려 세지 않는다. 각 시나리오를 1/8로 같은 비중으로 다룬다.

- 외부 파일럿안: 시나리오 번호 s=1…8, j=1…3에 `1,000,000 + 1,000*s + j`. 24블록·72시행. 기능·분산·비용 확인용이며 확증 분석에서 제외한다.
- 본 연구안: j=1…18에 `2,000,000 + 1,000*s + j`. 예: s1 2,001,001–2,001,018, s8 2,008,001–2,008,018. **144블록·432시행**이다. 이 번호는 제안일 뿐 예약·미사용 검증을 마친 목록이 아니다. 등록 전 실행 이력과 대조하고 충돌 시 결과를 보기 전에 새 전체 목록을 만든다.
- 기존 DEV seed, 옛 초안의 10101–10618, 이미 본 placement·체크포인트·모델 응답을 확증 표본으로 재사용하지 않는다. 여기서 새 seed는 **같은 8개 작업에서 새 시행**을 뜻한다. v4의 물건 좌표는 고정이므로 새 지도·새 배치 일반화 표본은 아니다.
- seed가 실제로 바꾸는 항목(초기 로봇 순서, 위치 추정 RNG 등)을 manifest에 열거한다. 모델이 seed를 받지 않으면 `model_seed=null`과 실효 모델 문자열을 남긴다. 같은 환경 seed가 같은 LLM 응답을 보장한다고 쓰지 않는다. 매 시행 대화·기억·캐시 정책을 리셋한다.
- 실행 순서는 세 조건의 6개 순열을 시나리오당 각각 3회 쓰도록 배정한다. 시나리오마다 j 6개씩을 한 wave로 묶고(3 waves), wave 안 48블록의 순서를 섞는다. 순서 RNG 제안은 20261006, 환경 RNG와 분리한다. 블록의 세 시행은 인접하게 실행하되 공급자 장애는 아래 규칙으로 처리한다. 실제 순서표는 최종 등록 때 생성한다.
- 한 번에 시뮬레이션 하나만 실행한다. 정식 실행은 별도 조정·배타 잠금·자원 확인 뒤 진행한다. 이 문서는 그 실행을 시작하지 않는다.

## 5. 지표와 실패의 처리

**주 지표는 PAR-2 하나이며 결과를 보고 바꾸지 않는다.** H=1800초일 때, 성공이면 완료 SIM초 T, 실패이면 2H=3600초다. 성공은 독립 심판이 시간 안에 모든 주문의 정확한 물건·개수·목적 구역·놓기와 종료 상태를 확인한 경우다. 로봇의 완료 발화나 잠정 기하 판정만으로 성공하지 않는다. 심판 기준과 구현은 최종 등록 전 검증·확정한다.

조기 안전 정지·시간 초과·예산 소진·정책 오류·최종 HOST_ERROR도 실패 3600초로 남는다. 성공 시행만의 시간을 주 비교로 쓰지 않는다. 성공 0건으로 PAR이 전부 같아도 배송 비율로 주 지표를 갈아타지 않는다.

| 보조 지표 | 시행별 정의와 보고 규칙 |
|---|---|
| 성공 | 전체 주문 성공 0/1, 조건별 성공/전체 시행 수, 짝 성공률 차이와 불확실성 |
| 배송 | 시간 안에 올바르게 놓인 고유 주문 물건 수 / 주문 물건 수. 중복·과잉 배송은 따로 기록; 같은 물건 두 번 세지 않음 |
| 시간 | 실제 종료 SIM초, 성공만의 완료 시간(참고), wall초, 모델 응답 지연 평균·중앙값·p95와 관측 호출 수 |
| 명령 | 고수준 행동 선택 수와 저수준 발행 명령 수를 분리. `robot_id + command_id`로 중복 기록 제거. 거절·취소·정지 명령도 별도 수치와 전체 수에 남김 |
| 모델 | 논리 호출 수, 실제 HTTP 전송 시도, 공급자 상류 시도(알 수 있으면), 정상/오류/재시도/상한 거절 수. 호출 계기별 집계 |
| 토큰 | 입력·출력·추론·이미지·캐시·공급자 total과 SIM 청구용 추정치를 구분. 공급자 포함 관계에 맞춰 합산해 이미지/캐시/추론을 이중 가산하지 않음 |
| 조정 | 집결·문 대기 robot-seconds, 전체 idle 비율, 동시 작업 시간 비율, 중복 claim, 충돌·교착·재계획 수 |
| 대화 | 발화·전달·수신 수, 길이·언어, 내용 범주(관측 공유/역할/순서/오류 복구), 채널 위반. 행동 변화와의 연결은 연관으로 보고 |

[기존 지표 문서](../../docs/zone_study_metrics.md)의 실패 보존·usage 미상 원칙을 따른다. 다만 그 모듈은 옛 4조건 schema이므로 `peer_nl→peer_ko` 이름 치환만으로 호환·한국어 조건 준수를 주장하지 않는다. 3조건용 평가 매핑과 단위 검사는 최종 등록 전 별도 작업이다.

토큰 미상은 0이 아니라 `null`, `usage_unknown_calls`, 알려진 합의 하한으로 남긴다. 조건 평균의 분모는 미상 시행을 포함한 전체이며 완전한 total 평균은 모두 확인될 때만 낸다. 호출·명령 로그가 잘리면 해당 값도 미상/하한이다. rule의 실제 미사용만 0이다. 실패한 요청도 비용·토큰을 남기고 비정상 `finish_reason`에서 행동·발화를 실행하지 않는다. 공급자/모델 문자열·call_id·전송 원장·응답 usage를 대조한다.

## 6. 주 분석과 보조 분석

시나리오 s의 seed j에서 `D_sj = PAR_peer_nl − PAR_no_comm`을 만든다. 시나리오별 평균 `mean_s`, 표본분산 `v_s`, 쌍 수 `n_s`를 계산하고 주 효과는 `Delta = sum(mean_s)/8`이다. 고정된 8시나리오 평균을 추정하며 시나리오가 모집단에서 무작위로 뽑혔다고 가정하지 않는다.

주 검정은 시나리오 층화 짝 평균의 **Welch–Satterthwaite t 근사**를 쓴다:

```text
A_s = v_s / n_s
SE = sqrt(sum(A_s)) / 8
df = sum(A_s)^2 / sum(A_s^2 / (n_s - 1))
t = Delta / SE
95% CI = Delta ± t_(0.975, df) * SE
양측 p = 2 * P(t_df >= abs(t))
```

양측 p<0.05이고 Delta<0일 때만 H1의 방향을 지지한다. 초 단위 차이와 CI, 기준 평균, 시나리오별 분포·성공/실패 수를 함께 낸다. p≥0.05는 차이가 없다는 증명이나 동등성 판정이 아니다. SE=0이면 t·p는 미산출로 표시하고 자동 유의 판정을 하지 않는다. 8개 층 중 자료가 없는 층이 있으면 전체 8시나리오 주 추정은 미완료다.

- 민감도: 시나리오 안에서 **세 조건이 묶인 블록**을 재표집하는 층화 bootstrap 10,000회, RNG 20261007의 95% percentile CI를 별도 보고할 계획이다. 이는 미래 분석 계획이며 이번에는 재표집·모의 실험을 실행하지 않는다. 정규 근사와 다르면 둘 다 공개한다.
- 성공은 짝의 2×2 표와 정확 McNemar 양측 검정, 시나리오별 및 동일 가중 성공률 차이를 보고한다. 이산성·작은 층별 표본에 따른 CI 한계를 명시한다. 성공률 차이 CI도 위 블록 bootstrap을 보조로 쓰며 전부 0/1인 경우 퇴화한 CI를 확실성의 증거로 해석하지 않는다.
- H1만 확증 검정이므로 그 α는 0.05다. 미리 정한 보조 가족은 세 대비(peer−no, peer−rule, no−rule)×6지표(성공, PAR, 고수준 명령, 저수준 명령, 논리 호출, total 토큰)에서 H1의 PAR 한 칸을 뺀 **17검정**이다. 가족 내 Holm 보정 p와 보정 전 효과·CI를 표시하되 탐색으로만 읽는다. 미상으로 계산 못 하는 칸은 가족에서 줄이지 않고 보정 입력 p=1, 결과에는 미산출로 둔다.
- 연속 보조 지표는 같은 층화 짝 평균 방식을 쓴다. 심한 왜도는 중앙값·분위수도 보인다. 시나리오 상호작용·사건이 실제 적용된 하위집단·대화 내용 분석·성공만의 비용은 탐색이다. 대화 조건만의 발화 내용을 골라 성공의 원인이라고 단정하지 않는다.
- 로그·심판으로 자동 지표를 만들고 모호한 실패 원인은 조건별 성과를 보기 전에 가린 기록으로 2인이 판정하는 안이다. 합의 못 하면 `UNCLASSIFIED`로 남긴다. 조건 이름을 감춰도 메시지 내용 때문에 완전 맹검은 어렵다는 한계를 공개한다.

## 7. 표본 크기와 검정력

**제안: 시나리오당 18블록, 총 N=144블록(조건당 144회, 전체 432회).** 단일 H1, 양측 α=0.05, 목표 검정력 80%다. [계산 근거와 재현 코드](POWER_ANALYSIS.md)에 비중앙 t 계산과 전체 가정을 남겼다.

실용적 차이의 후보는 **평균 PAR 180 SIM초(시행 상한의 10%) 감소**다. 이는 예상 효과나 문헌 실측값이 아니라 연구자가 판단할 최소 관심 차이 제안이다. 시나리오 내 짝 차이 SD=720초라는 **미검증 계획 가정**이면 `d_z=180/720=0.25`다. 8개 층 균형을 맞추면 128블록부터 약 80%이고, 조건 순서 6개도 균형을 맞추기 위해 144블록으로 올린다.

| 짝 효과 d_z | 144블록 검정력 | 8시나리오×6순서 균형에서 80% 이상인 N |
|---:|---:|---:|
| 0.15 | 43.2% | 384 |
| 0.20 | 66.4% | 240 |
| 0.25 | 84.6% | 144 |
| 0.30 | 94.7% | 96 |
| 0.40 | 99.7% | 96 |

이는 독립 블록·층 내 정규 짝 차이·공통 분산 가정의 계획치다. PAR의 벌점 덩어리, 같은 고정 배치, API 시간 변화로 실제 검정력이 다를 수 있다. **성공률·시나리오별 효과·17개 보조 검정의 80% 검정력을 보장하지 않는다.**

별도 파일럿은 분산·준비 상태·비용을 확인하는 데 쓴다. 파일럿 후 본 자료를 하나도 보기 전에 최소 차이·분산·N을 다시 정하고 새 최종 등록본에 근거를 남긴다. 이번에는 N 자동 재추정이나 해시 동결을 하지 않는다. 본 연구 시작 뒤 관측 효과나 p값으로 표본을 늘리지 않는다. 작은 예산만 가능하면 해당 규모의 검정력을 적고 탐색 파일럿으로 남긴다.

계획 자원: 본 연구의 상한은 432×1800초=216 SIM시간, 두 LLM 팔 HTTP 시도 최대 144×2×90=25,920회다. 외부 파일럿 72회는 추가 36 SIM시간·4,320 HTTP 시도다. 초기화·호스트 오류 비용은 별도이며 SIM시간은 wall시간이 아니다. 토큰 총량·단가·wall 소요·디스크량은 같은 실행 경로의 파일럿에서 추정해야 하고 이번 작업에 실제 호출 예산을 부여하지 않는다.

## 8. 제외·HOST_ERROR·재시도

등록된 각 (시나리오, seed, 조건) 슬롯에 고유 trial_id와 attempt_id를 둔다. 원본 attempt는 덮어쓰지 않는다. **결과가 나쁘다는 이유로 시행·seed·시나리오를 빼거나 성공할 때까지 재실행하지 않는다.**

| 상황 | 주 분석 처리 | 별도 기록/조치 |
|---|---|---|
| DEV·교사·파일럿·다른 버전·중복 저장 파일 | 애초 확증 코호트 밖 | 출처와 제외 사유. 중복 파일은 trial_id로 1회만 계산, raw 유지 |
| 정상 실행의 실패, guard 정지, horizon/명령·호출 상한 도달 | 성공 0, PAR=3600 | 원인·도달 단계·실제 시간·비용 보존 |
| 호스트/프로세스/드라이버 오류, 디스크 부족 **ENOSPC**, 읽기·쓰기 실패 | `HOST_ERROR`; 최종 실패를 분모에 유지 | 성공한 조건으로 대체하지 않음. 사고 당시 공간·trace·시도 순서 기록 |
| HTTP 429/timeout/공급자 장애 | `API_ERROR`, 실패·비용 유지 | 고정 재시도 상한 안에서만 재시도; 무제한 전환·다른 모델 대체 금지 |
| 파서/정책 오류, 모델 대신 rule fallback | 정책/프로토콜 실패, PAR=3600 | 실제 물리 완료가 있어도 따로 보고, 정상 LLM 성공으로 승계하지 않음 |
| 필수 로그/심판 증거 누락 | `UNCLASSIFIED`, 성공 확인 불가, 주 분석 PAR=3600 | ENOSPC 등 증거가 있을 때만 HOST_ERROR 원인을 함께 표기 |
| 금지 입력·다른 프로필·조건 채널 위반 | 프로토콜 실패, 분모 유지 | 다음 실행 중단, 수정 시 새 버전·새 코호트 필요 |

**초기화 재시도 제안:** 첫 모델 전송·첫 로봇 명령·연구 SIM시계 시작 중 가장 이른 시점 전에만, 외부 초기화 실패를 동일 슬롯에서 1회 재시도할 수 있다. rule에도 같은 경계를 적용한다. 두 attempt와 비용을 보존하며 두 번째도 실패하면 최종 HOST_ERROR다. 그 경계를 지난 에피소드는 결과와 무관하게 다시 돌려 주 결과를 대체하지 않는다. API 내부 재시도도 전송 원장에 모두 남기고 등록한 상한을 쓴다.

등록 전 여유 공간 10 GiB 검사와 전체 예상 저장량의 확보를 요구한다. 실행 중 ENOSPC면 현재 시행을 HOST_ERROR로 남기고 전체 코호트를 일시 중단한다. 자료를 지워 공간을 만들거나 다른 작업을 종료하지 않는다. 저장·프로필이 회복되어 동일 등록을 유지할 수 있을 때 미시작 슬롯부터 재개한다.

주 분석은 **시도한 등록 슬롯의 실패를 모두 포함**한다. 계획 432, 시작/시도 수, 완료 수, 실패 수, 미시작 수를 조건·시나리오별로 함께 보고한다. 전체 중단으로 미시작인 슬롯은 실제 실패로 꾸미지 않고 미수집으로 남긴다. 144블록 미완료이면 계획 표본을 채운 확증 완료라고 보고하지 않으며 가능한 주 추정의 N과 한계를 명시한다.

민감도에서만 HOST_ERROR/API_ERROR/필수 결과 누락이 있는 **블록 전체(세 조건)**를 제외하고 같은 분석을 반복한다. 제외 블록 수·조건별 발생률을 공개한다. 주 분석을 대체하지 않으며 불완전 블록에서 남은 좋은 조건만 비교하지 않는다.

## 9. 정지 규칙과 탐색/확증 분리

정식 E2E·본 연구는 **stop-ON**이다. `dev_light`의 “멈췄을 것만 기록” 모드를 쓰지 않는다. 충돌 가드, σ 예산, 재관측 시한, 위치 불확실, 낙하·기울기 한도·GO 상호 확인 실패·집게 이탈·실행 오류의 실제 정지 동작과 문턱을 등록한다. 단위와 모든 조건의 적용이 같아야 한다. STOP을 LLM이 무시하거나 rule이 우회하지 못하게 한다.

고정 N에 도달하면 끝낸다. 중간 효과·p값으로 조기 성공/무익성 종료를 하지 않는다. 동결된 자원 상한, ENOSPC, 안전 가드 무력화, 금지 입력 누출, 소스/모델/구성 변경이 생기면 다음 시행을 멈추고 경위·수집량을 기록한다. 동일 원인으로 복구가 두 번 막히면 반복 시도를 끝내고 고전·최근 방법을 조사해 출처와 함께 재설계를 보고한다. 이 규칙은 성공할 때까지 같은 확증 시행을 반복할 권한이 아니다.

DEV에서 stop-OFF로 얻은 성공, 작은 인수 재생, 교사 실행, 저장 응답 재생, 문서·단위 검사 통과는 본 연구 성공과 분리한다. 탐색 자료로 프롬프트·제어기·문턱·시나리오를 고친 후에만 새 seed·새 응답의 확증 코호트를 시작한다. 확증 자료를 본 뒤 수정하면 기존 코호트는 그 버전의 결과로 남기고 후속 코호트를 새로 등록한다. 두 버전을 합쳐 최초 계획의 결과로 쓰지 않는다.

- 새 실험이 완료·회수되면 [TensorBoard 절차](../../docs/tensorboard.md)에 따라 primary `outputs/tensorboard`에 새 스냅샷을 만들고 원본 manifest와 데이터 읽기를 확인한다. 같은 코호트의 세 조건, success·시간·명령·모델 호출·응답 시간·토큰을 보여 준다. 새 자료가 없는 이번 문서 작성에서는 서버·기존 viewer·스냅샷을 변경하지 않는다.

## 12. 결정 필요

1. **주 목표·표본:** PAR-2를 유일한 확증 지표로 할지, 최소 관심 차이 180초·N=144블록을 채택할지. 외부 파일럿 후 SD·예산으로 재계산하고 본 자료 수집 전에 최종 결정한다.
2. **실행 준비:** s1–s8 전체의 단독/2대/3대 화물, 혼합 주문, 사건, s5 낙하와 stop-ON의 관계, s6 관계, 독립 심판, stop-ON을 검증한 공통 실행 경로와 3대 rule 정책. 불가능한 시나리오가 있으면 몰래 빼지 말고 수집 전 연구 범위·검정력을 새로 정한다.
3. **조건 경계:** 세 로봇의 최소 상태 채널, 수신 후 호출 규칙·프롬프트 차이, 3조건 로그/평가 매핑, top OFF·초음파 OFF 기본안.
4. **모델·비용·상한:** 실효 모델 버전/temperature/reasoning, 문맥·발화·명령·재시도 상한, SIM 비용 계수, 총 토큰·금액·wall·디스크 예산. rule에는 가짜 모델 비용을 붙이지 않는다.
