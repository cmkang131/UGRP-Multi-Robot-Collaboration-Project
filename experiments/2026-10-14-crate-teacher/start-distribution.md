# 상자 교사 v6: 지도 인수 시작 분포 (2026-10-14, PR #500)

`start_assigned_los_v1`을 계획 생성기에 추가했다(기본 off). ACT의 근거리
범위는 지도 코드가 화물 근처의 맡은 쪽으로 데려다준 뒤다. 맡은 손잡이가
상자 몸체 뒤에 있는 시작은 교사의 제자리 회전 과제로 삼지 않는다.
**재배치는 지도 코드의 일이며 E2E에서 따로 검증한다.**

이번 조정자 결정 원문: “관문·기록용 시작 자세는 '지도 코드가 넘겨줄 자세의
분포'에서 뽑는다”, “시작 자세에서 제자리 회전 × 기울기 안에 맡은 손잡이가
≥5/15점 보이는 자세만 받는다”, “가시 판정 임계 5점은 바꾸지 않는다”.
정답 계산은 시연 시작 상태 생성에만 쓰며 교사·학생·판단 LLM의 행동 입력에는
전달하지 않는다. 기존 실행 제어·가시 임계·카메라·물리는 수정하지 않았다.

## 배경과 범위

사용자가 제공한 직전 GCP 진단 `422cc0ad`는 전체 3/4다. v5 77920–77922는
잡기·들기·놓기까지 3/3 성공했고, v4 재현 77902만 탐색 시한으로 실패했다.
제공된 원장 재계산은 r1 시선 31/548표본, 15점 중 최대 3점이었다.
원본 연결: `outputs/e2e18-admin/gcp-reports/crate-diag-422cc0ad.json`,
`outputs/gcp1-runs/crate-{diag,repro}-*-422cc0ad/raw`.
이 작업에서 해당 영상이나 548표본 원장을 새로 재생한 것은 아니다.

기존 v5 계획 `gate_plan_v5_77100.json`의 정적 시작 검사는 두 로봇 모두
한 점 이상 보이는 경우 30/40(r1 32/40, r2 38/40), ≥5점은 25/40
(r1 31/40, r2 34/40)이었다. 이번 회귀 시험에서 30/40·25/40을 재확인했고,
77902의 r1 최대 3/15도 3개 기울기 × 360° 전체 검사로 재확인했다.
이 계획은 시작 시선만으로도 관문 38/40을 달성할 수 없어 대체한다.

## 생성 방식과 분포 축소

기존 지도·화물 구역·축/거리 층화·서로 다른 손잡이 배정을 유지하는
결정적 거절 표집이다. 첫 번째 기존 기하 조건 통과 제안은 off와 완전히
같다. 그 자세와 두 로봇의 시선 검사 결과를 `original_starts`에 보존한다.
둘 중 하나라도 ≥5/15점에 도달하지 못하면 같은 에피소드 시드의 RNG에서
다음 **공동 제안(화물과 로봇 자세)**을 다시 뽑는다. 따라서 채택 분포는
기존 공동 분포에 두 로봇 시선 조건을 건 조건부 분포이며, 원래 전체 분포의
교사 성능을 측정한 결과로 해석하지 않는다.

`scripts/audit_crate_start_los.py`는 직전 검사
`/private/tmp/crate_visibility_422cc0ad.py`의 정적 회전 방식을 옮겼다.
`audit_masterpi_v3_static.set_static_pwm`, 기존 `BandVisibility.measure`의
pinhole+fisheye 범위와 첫 교차 ray, 실제 `search_body_scan_v2`의 기울기
(820/2320, 700/2440, 500/2500), 팬 1500, yaw −180…179°를 재사용한다.
표준 XML 빌더에서 모델만 컴파일하고 `mj_kinematics`·`mj_camlight`로 위치를
계산한다. 실제 v3 카메라 바인딩을 적용하고, 다른 로봇·화물·벽도 가림에
포함한다. 채택은 ≥5점 증거를 찾으면 일찍 끝내도 같으며, 거절은 1080개
뷰를 전부 검사한다. 보고한 `max_seen`은 조기 종료 시 전역 최대가 아니다.
렌더·물리 step·mj_forward·세계/제어기 생성·모델 호출은 0이다.

MuJoCo 공식 API는 ray의 첫 교차 계산이 `mj_kinematics` 결과를 사용하고,
`mj_camlight`가 카메라 위치·방향을 계산한다고 명시한다.
[공식 함수 문서](https://mujoco.readthedocs.io/en/3.4.0/APIreference/APIfunctions.html#ray-casting)를
확인했다. 회전 중 실제 발견이나 물리 파지 성공을 보장하는 검사는 아니다.

## 운영 인계

push 및 원격 SHA 일치 뒤 `20261014-crate-<sha8>.json`을 `ready=true`로
작성하고 `422cc0ad` 대기열을 `superseded`로 바꾼다. GCP 운영 작업자가
진단 6개를 먼저 실행한다. **6/6 전체 파지·해제 성공과
`invisible_measurements=0`, `held_world_reads=0`**을 모든 실행에서 확인하고,
첫 30 SIM초 원본·영상 검토 뒤에만 관문 40개를 시작한다. 관문 동시 수는
최대 16(gcp1 n4-highcpu-64의 기존 16개 속도 관문 통과 기록/이번 지시),
같은 후보의 성능과 저장 예산·비용 정지 장치는 운영 작업자가 확인한다.
GCP 기준 속도는 중앙 wall/SIM ≤3.5를 유지한다. 기존 프로필의 실패·정지
규칙과 원본 보존을 유지하며, 학습 데이터 기록은 이번 대기열에 없다.
이 작업은 대기열 인계까지이며 GCP 실행을 직접 제출하거나 감시하지 않는다.
