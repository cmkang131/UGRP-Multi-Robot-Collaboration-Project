# Recovery references (checked 2026-10-14)
- Classic ROS move_base (Willow Garage 2008 lineage): [source](https://github.com/ros-planning/navigation/blob/noetic-devel/move_base/src/move_base.cpp), executeCycle lines743–750/818–825/863–907: progress timeout triggers recovery; advance recovery index instead of retrying identical action forever.
- Macenski et al., IROS2020, [The Marathon2](https://arxiv.org/abs/2003.00368): behavior-tree navigation and open implementation. This paper motivates structure, not evidence for our camera-only robot performance.
- Current Nav2 public [recovery tree](https://github.com/ros-navigation/navigation2/blob/main/nav2_bt_navigator/behavior_trees/navigate_to_pose_w_replanning_and_recovery.xml): context failure then RoundRobin clear/spin/wait/backup. [SimpleProgressChecker](https://github.com/ros-navigation/navigation2/blob/main/nav2_controller/plugins/simple_progress_checker.cpp): position/time progress.
- Port only failure propagation and continuing the existing native recovery lifecycle. Retain existing calibrated pulses, own-RGB grid and safety filters; no ROS laser, GT pose, costmap erasure or new physics. Failed camera posture is rejected after3 distinct idle frames; not counted as a successful observation. Three unchanged navigation choices trigger native backup/replan. Exact distances/times are our explicitly recorded finite-pulse adaptation, not upstream defaults.
- Scope: sources verified; no claim that camera-only odometry meets Nav2 localization assumptions. This round isolates act-code recovery with static order, 0 model calls as previous stage baseline; not a study of LLM decisions or communication.
