# 운반 중 재측위 B안 첫 실험: 표식 없는 최종 환경에서 체크포인트 재측위 정확도 (오프라인, 물리 0회)

**상태: 측정 완료(원본 로컬 보관).** 사전 등록 절("무엇을 확인하나" ~ "파이프라인 확인")은 측정 전에 고정한 것이며(커밋 `3b1877e5`), 그 뒤 판정 기준·필터·분할·보정·소스를 바꾸지 않았다. 결과는 맨 아래 "결과" 절.
**물리 0회.** 시뮬레이터 시간은 앞으로 가지 않는다(정지 프레임 렌더 + 추론만). `agent_lock` 없음, 모델(LLM) 호출 0.
이것은 **E2E(끝에서 끝까지 실행)가 아니다.** 학생의 운반 성공 근거도 아니고, 어떤 실행기·게이트·번들도 바꾸지 않는다.
관련: PR #277(재측위 방안 비교 설계 메모, 추천안 B), PR #276(시야 감사, 필요 정밀도 표), 표식 없는 위치 추정 VIS3(#216).

## 무엇을 확인하나

B안은 "운반 구간 사이에 빔을 내려놓고, 짐 없는 자세로 주위를 둘러본 뒤 위치를 다시 잡는다"이다. PR #277은 이 지점의 재측위가
**표식 0개 + 벽 0.40 m 환경에서 충분히 정확한지**를 아직 모른다고 했다. 이번 실험은 그 물음의 가장 작은 1단계다.

1. 표식 없는 최종 환경 지도를 **정지 렌더**한다.
2. 체크포인트 9곳 × 로봇 2대에서, 지금 코드(`scripts/run_m2_pair.py`)가 쓰는 짐 없는 둘러보기 자세로 손목카메라 프레임을 렌더한다.
3. **기존 VIS3 국소화기**(표식 없는 벽·문 분할 + 파티클 필터, 재학습 없음)에 자기 카메라 프레임·정적 지도·자기 명령 이력만 넣어 위치·방향을 다시 잡는다.
4. 시작 오차를 여러 가지로 준 뒤 재측위 후 오차 분포(위치 p50/p90, 방향 p50/p90, 실패율)를 잰다.
5. 이 표를 PR #277의 가정(재측위 직후 방향 σ 1.3°, 위치 σ 3.8 cm)과 비교해 B의 오차 예산(체크포인트 간격·횟수)을 갱신한다.

## 입력 경계

- 국소화기 입력: 자기 손목 카메라 프레임(JPEG), 정적 지도(`maps/zones/zone_wide_door_geometry_v2.json`), 고정 보정, 자기 발행 명령 이력(`initial_servo_command`, `look`).
  정답 좌표·시뮬레이터 상태·측정 관절은 넣지 않는다. 짝 로봇·빔·세 번째 로봇은 프레임에 **찍히는 만큼만** 보인다.
- 정답(참값) 좌표는 두 곳에만 쓴다: (a) **틀린 시작 믿음을 만들 때**(참값 + 시작 오차를 필터의 초기 평균으로 준다. 실제 로봇의 "틀린 현재 위치 추정"을 흉내 내는 실험 조건이다) (b) **채점**.
- 교사 분할 라벨(참값 렌더의 분할)은 `oracle` 진단(인식 상한선)에만 쓴다. 학생이 아니다.
- 학습 없음. 분할 모델은 기존 `seg-v2`(sha256 `348539030fda962cc5ba64e21c956619bc4db9321a99cd3ae6746611a9939fd9`)를 그대로 쓴다.

## 체크포인트와 자세

- 경로: PR #276 후보점 예측과 같은 기록 경로(빔 중심): (1.0, 0.05) → (1.55, 0.05) → (2.4, 0.05) → (3.2, 0.05) → (3.2, −0.667) → (3.2, −1.383) → (3.2, −2.1) → (3.9, −2.1) → (4.6, −2.1).
  체크포인트 번호 0..8 = `start`, `after_L0`..`after_L7`. **B안의 재측위 지점은 운반 구간 사이 7곳 = 1..7(`after_L0`..`after_L6`)**이다. 0(정렬 시작 위치, 빔이 바닥에 있고 첫 잡기 전)과 8(도착)은 참고용이다.
  `after_L1`(빔 x=2.4)은 문(x=2.2) 바로 옆이다.
- 로봇: r1은 빔 x−0.425 m 방향 0, r2는 빔 x+0.425 m 방향 π, 빔은 바닥에 놓임(방향 0), 세 번째 로봇(r3)은 자기 도크. 짝 로봇은 같은 둘러보기 자세, pan 1500.
- 둘러보기 자세(짐 없음, 그리퍼 열림 서보1=2000): **`p20`**(기본) = `harness.owncam_drive.LOOK_P20`(서보 3/4/5 = 1072/2400/1482), 현재 `run_m2_pair._queue_grasp`가 체크포인트 재측위에 쓰는 자세. **`search`**(보조) = `SEARCH_POSE`(740/2320/1320), PR #276 후보점 예측이 쓴 자세.
- pan 순서: `PREGRASP_PANS_V2` = 1500, 1230, 970, 700, 1770, 2030, 2300, 1500(8프레임; 마지막은 첫 장면의 반복). 프레임은 pan 명령 1.0 s 뒤에 들어온다(필터 설정 `settle_s` 0.2 s보다 길다).
- **팔 처짐 재현:** `set_servo_pulses(forward_only)`만 쓰면 팔이 명령 그대로의 기구학 자세라 물리 처짐이 없다. 그래서 팔 4관절의 **정적 중력 평형**을 뉴턴법으로 푼다(속도 0, 시간 전진 없음).
  결과 카메라 처짐(고도 편향/높이)을 학습 보정표와 비교했다: `p20` −0.02291 rad / −0.00257 m (보정표 −0.02306 / −0.00258), `search` −0.01693 rad / −0.00166 m (보정표 −0.017 / −0.00166). 오차 0.0002 rad 미만이라 보정표를 그대로 쓴다.
- 렌더는 `world.render_jpeg`(하네스가 받는 것과 같은 어안 JPEG). 렌더 후 세계 시간이 그대로임을 코드가 검사한다.

## 시작 오차와 코호트 (측정 전 고정)

필터는 프레임마다 새로 만든다(`run_m2_pair`가 체크포인트에서 국소화기를 새로 만드는 것과 같다). 초기 분포 = 가우시안(평균 = 참값 + 시작 오차, 퍼짐 = 아래 prior).

| 칸 | 시작 오차 | 묘사 | 그룹당 횟수 |
|---|---|---|---:|
| S | dx, dy ~ U(−5, 5) cm, dyaw ~ U(−3°, 3°) | 작업 지시의 ±5 cm, ±3° | 40 |
| Y | dy = ±5 cm 번갈아, dx = dyaw = 0 | 주문서 반올림 오차 y ±0.05 m | 8 |
| L | dx, dy ~ U(−10, 10) cm, dyaw ~ U(−6°, 6°) | 스트레스(S의 두 배) | 20 |

- 그룹 = (렌더 프로필, 둘러보기 자세, 체크포인트, 로봇). 추첨 시드는 그룹·칸·번호의 해시로 고정한다(`relocalize_grid.py`의 `seed_of`, `SEED_BASE` 20260929).
- prior(초기 퍼짐): **wide**(기본) = VIS3 학생의 초기 분포 (0.15 m, 0.15 m, 10°), **tight**(민감도, S·Y만) = 운반 게이트 (0.07 m, 0.07 m, 3°).
- 필터: 확정 설정 그대로(`selected_config_v3.json`: 필터 a1, `robust` 비어 있음, 입자 수·운동 모델·보정 변경 없음). 분할 추론 크기 480×360.
- 관측 출처: `vision`(학생, 분할 모델), `oracle`(교사 라벨, 인식 상한선 진단, 기본 프로필만).

주 집단(판정에 쓰는 것): **렌더 프로필 `default`, 자세 `p20`, 관측 `vision`, prior `wide`, 칸 S∪Y**(그룹당 48회). 나머지(L, tight, `search`, `floor_light_v1`, `oracle`)는 민감도·진단이며 판정을 바꾸지 않는다.

## 사전 등록 기준 (측정 전 고정)

수치는 PR #276 결과 3(필요 정밀도)과 기존 코드 값에서 인용했다. 새로 유도한 기준이 아니다.

| 이름 | 값 | 출처 |
|---|---|---|
| 티어 A 위치·방향 p90 | ≤ **0.05 m**, ≤ **2.0°** | 내려놓기 자리(슬롯) 등록 한도 `release` 0.05 m / 2.0°(PR #276 결과 3, M1 `release`). VIS3 게이트 G2(위치 p90 5 cm)와도 같다 |
| 티어 B 위치·방향 p90 | ≤ **0.07 m**, ≤ **3.0°** | 운반 게이트 `GATE_LOADED` σ_xy 0.07 m, σ_yaw 3°(`harness/zone_own_guards.py`, PR #276 결과 3). 다음 구간을 게이트 수준에서 시작할 수 있지만 슬롯 한도는 못 맞춤 |
| 실패(WRONG) | 마지막 위치 오차 > **0.10 m** 또는 방향 오차 > **4°** | 티어 A 한도의 두 배(0.10 m는 구간 끝 오차 한도, PR #276) |
| 표시(FLAGGED) | 필터가 스스로 "불확실"이라 보고: σ_xy > **0.06 m**(`PREGRASP_FIX_STD_M`) 또는 σ_yaw > **3°** | `run_m2_pair.py`의 기존 수락 규칙 + 운반 게이트 |
| 조용한 실패(SILENT) | WRONG이면서 FLAGGED 아님 | 가장 위험한 실패: 틀렸는데 스스로 모름 |
| 통과 조건(그룹) | 실패율 ≤ **10 %**(PR #277 §7.1 "체크포인트별 90 % 수렴") **그리고** 조용한 실패율 ≤ **5 %** | |

- **그룹 판정:** 위 통과 조건을 만족하면서 위치·방향 p90이 A 한도 이내면 **A**, B 한도 이내면 **B**, 아니면 **X**.
- **체크포인트 판정:** 두 로봇 중 나쁜 쪽(둘 다 재측위해야 하므로).
- **"재측위 가능(B안 1단계 통과)":** 주 집단에서 운반 구간 사이 7곳(1..7)이 **모두 B 이상**(A 또는 B)이고, 그중 문 옆 `after_L1`(체크포인트 2)이 포함된다.
  **"슬롯급 재측위 가능":** 7곳 모두 **A**. 하나라도 X면 "불가(그 지점 지도·보정·자세 문제)"로 보고하고 어느 지점인지 적는다.
- p90은 그룹당 48회 표본의 값이다. 95 % 부트스트랩 구간(시드 0, 1000회)을 함께 적는다. 프레임은 정지 렌더라 같은 프레임을 반복하고, 서로 다른 것은 시작 오차와 필터 난수뿐이다(표본이 독립 실행이 아님).
- 판정 뒤 임계값·집단을 바꾸지 않는다. 필터·분할·보정을 조정하지 않는다(dev 조정 없음). 파이프라인 버그가 코호트 시작 전에 발견되면 고치고 이 문서에 기록한다.

## 오차 예산 갱신 방법 (측정 전 고정)

PR #277 §4.2의 모형을 그대로 쓴다: σ_yaw(t) = √(σ0² + (b t)²), σ_xy(t) = √(σ0_xy² + (k t)²). 게이트 σ_yaw 3°, σ_xy 0.07 m에 닿는 시간이 구간 시간보다 길어야 한다.
b(1.56 / 2.04 / 2.33 / 2.55 mrad/s), k(1.1–1.5 mm/s), 구간 시간(L0 18.5 … L7 21.15 s, 합 170.8 s), 체크포인트 왕복 18 s는 **PR #277에서 인용**한 값이며 이번에 새로 재지 않았다.
σ0는 세 가지로 넣는다: (1) PR #277 가정(방향 1.3°, 위치 축당 3.8 cm), (2) **측정한 값** = 주 집단 운반 구간 사이 7곳 합친 오차의 RMS(방향은 각도 RMS, 위치는 반경 RMS/√2), (3) 가장 나쁜 체크포인트의 RMS.
체크포인트 횟수는 연속 구간을 시간 예산 안에서 묶는 탐욕 분할로 센다. 둘러보기 시간은 코드 상수에서 8.4 s(0.8+0.6, 7×(0.4+0.6))로 적고, pan 프레임 수(1/3/5/8)별 오차도 함께 적는다.

## 파이프라인 확인 (코호트 전 스모크, 판정에 쓰지 않음)

체크포인트 2(`after_L1`) `p20`만 렌더(14프레임)해 파이프라인을 확인했다. 시작 오차 14회(S 6, Y 4, L 4)의 결과는 위치 1–2 cm, 방향 0.4° 미만으로, 이 지점에서 필터가 작동함을 보였다(코호트 결과가 아니다).
같은 프레임에서 교사 라벨로 만든 열 관측은 **지도가 예측한 벽 아래 모서리 행과 0.5 px 안팎으로 일치**했다(참값 자세, 처짐 보정표 적용). 이는 렌더·처짐 재현·필터 기하가 일관됨을 보인다.
반면 학생 분할 관측은 큰 벽이 화면을 채우는 일부 프레임에서 잘못된 모서리(바닥 타일 선)를 냈다(분할-라벨 벽 IoU 0.08–0.19인 프레임 있음). 이런 프레임은 필터의 이상값 처리로 걸러진다.

## 3. PR #277 가정과의 비교 및 오차 예산 갱신

PR #277 가정: 재측위 직후 방향 σ0 = 1.3°, 위치 축당 σ0 = 3.8 cm. 측정(주 집단, 7곳 풀링): **방향 RMS 0.42°, 위치 RMS 축당 1.57 cm**(반경 RMS 2.22 cm / √2). 가장 나쁜 체크포인트(축별 각각의 최댓값): 방향 1.13°(cp1 r2), 위치 축당 2.77 cm(cp4 r2).
→ **측정치가 PR #277 가정보다 모든 지점에서 좋다.** 가정은 안전 쪽으로 보수적이었다.

게이트(σ_yaw 3°, σ_xy 0.07 m)에 닿기까지 시간 t_gate(초). 모형 σ_yaw(t) = √(σ0² + (b t)²). 표류율 b, 구간 시간, 왕복 18 s는 PR #277에서 인용한 값이며 이번에 새로 재지 않았다. **위치 축(k)이 아니라 방향 축이 늘 결정한다(binding = yaw).**

| b (mrad/s), 출처 | PR #277 가정 σ0 (1.3°) | 측정 σ0 풀링 (0.42°) | 측정 σ0 최악 체크포인트 (1.13°) | 구간 하나조차 예산 초과 (측정 풀링 σ0) |
|---|---:|---:|---:|---|
| 1.56 (v6e pm+edge) | 30.2 s | 33.2 s | 31.1 s | 없음 |
| 2.04 (v6g pm+edge) | 23.1 s | **25.4 s** | 23.8 s | 없음 (가정에서는 L1, L2 초과) |
| 2.33 (registered E0 cal2) | 20.3 s | 22.3 s | 20.8 s | L1, L2 |
| 2.55 (registered E0 v6g refit) | 18.5 s | 20.3 s | 19.0 s | L1–L7 전부 |

- **체크포인트 횟수는 b에 관계없이 7곳(구간 8개, 각 구간 하나씩)이다.** 구간 하나가 18.5 s 이상이라 인접한 두 구간의 합은 37 s 이상이고, 이는 t_gate의 최대값(33.2 s)보다 길어 묶을 수 없다. 재측위를 더 정확하게 해도 횟수는 줄지 않는다.
- 비용: 체크포인트 왕복 18 s × 7 = **126 s 추가**(구간 합계 170.8 s의 74 %). 이 값은 PR #277이 인용한 그대로이며 재측위 정확도가 좋아져도 바뀌지 않는다.
- b ≥ 2.33에서는 L1, L2(가장 긴 구간)가 **재측위 없이 한 구간만으로도 게이트를 넘는다**. 이 경우 구간 도중 추가 재측위나 구간 분할이 필요하다. 즉 B안 자체로는 b가 2.3 mrad/s 이상이면 부족하다.
- 결론: B안의 남은 위험은 재측위 정확도가 아니라 **운반 중 방향 표류율 b**다. 측정 σ0 기준으로 b = 2.04 mrad/s까지는 구간 하나가 예산 안이고 b = 2.33부터 L1·L2가 넘는다. 그 이상이면 구간 내부 표류를 줄이는 별도 조치가 필요하다.

같은 계산을 다른 구성으로 하면 풀링 σ0(방향 / 위치 축당)가 `default / search` 0.92° / 3.9 cm, `floor_light_v1 / p20` 0.78° / 2.7 cm, `floor_light_v1 / search` 2.18° / 6.0 cm이다. `floor_light_v1 / search`는 v6g에서 t_gate 17.6 s로 짧아지고, `default / search`와 `floor_light_v1 / search`의 최악 체크포인트에서는 **재측위 직후 이미 게이트 밖(t_gate 0)**이다. 전체 표: `analysis/budget.json`.

## 4. 한계와 아직 모르는 것

- **정지 프레임이다.** 실제 로봇은 이동 후 정지, 팔 자세 변경, 흔들림, 빔을 내려놓는 동작에서 오는 자세 오차를 겪는다. 팔 처짐은 정적 평형으로 재현했고 학습 보정표와 0.0002 rad 이내로 맞췄지만, 실제 물리 스텝에서의 정착 시간·진동은 재지 않았다. **물리 0회**.
- **필터를 프레임마다 새로 시작**했고 시작 평균은 참값 + 시작 오차다. 실제로는 이동 명령 이력으로 얼마나 틀린지가 정해진다. 시작 오차가 실제 표류 분포와 다를 수 있다(L 칸으로 2배까지는 확인).
- 참값 근처에서 시작하므로 **멀리서(1 m 이상) 잘못 시작하는 "납치 문제"는 이번에 시험하지 않았다.** 좋은 결과는 "이미 5–10 cm 안에 있을 때 정밀화"에 대한 것이다.
- 프레임이 정지 렌더의 반복이라 **표본은 독립 실행이 아니다**(다른 것은 시작 오차와 필터 난수). 부트스트랩 구간은 이 점을 반영하지 못해 실제보다 좁다.
- 지도는 문 1개 최종 지도만 다뤘다. 문 2개·복도 최종 지도는 장면에 연결되지 않아 시험하지 못했다. 렌더 프로필은 `default`(모델 학습 조건)이고 `floor_light_v1`은 위 4번처럼 실패.
- 분할 모델(`seg-v2`)의 학습 분포와 이번 렌더가 같은 렌더러·지도라서 이 결과는 **학습 분포 안**이다. 빔이 손목카메라에 새로 보이는 것, 다른 로봇 위치 변화, 조명 변화의 일반화는 시험하지 않았다.
- 실제 물리에서 빔을 내려놓고 다시 집을 때 발생하는 **위치 변화(재파지 오차)**는 이 측정의 범위 밖이다. B안 전체의 성공 여부는 이 측정으로 알 수 없다.
- 개발·스모크 측정(체크포인트 2 한 곳, 14회)은 판정에 쓰지 않았다. 코호트 전에 발견한 파이프라인 문제(M1 필터의 `landmarks` 키, 교사-지도 정합 진단의 센티널 처리)는 소스 고정 전에 고쳤다.
- 학생 분할 모델이 큰 벽이 화면을 채우는 일부 프레임에서 바닥 타일 선을 벽 모서리로 잘못 잡는다(스모크). 필터의 이상값 처리가 걸러 주지만 `search` 자세 cp2 r1에서는 걸러지지 않았다.
