# mapbuild6 — 실제 지도 주행 인계 경로에서의 위치 추정 관문

ownership-ack. 같은 `codex/mapbuild1`, PR #556, gcp5 단독이다. 현재 **진행 중 / NOT_READY**이며 녹화·추정·운반·LLM E2E 성공은 아직 없다. 이전 mapbuild5c 40 SIM초/1.13m 자극은 성능 분모에 넣지 않는다.

판정은 녹화 전에 고정한다. 차체 중심 SE(2), 시작 자세 한 번 정렬, 척도1을 쓴다. 모든 필수 지점에서 요구 정확도를 양쪽 모두 만족하면 LK가 기본이고 RBPF는 off다. LK만 실패하고 RBPF만 통과하면 RBPF다. 둘 다 실패하면 원인 분포와 다음 묶음 제안만 남기며 이번 라운드에서는 상수를 맞추지 않는다. 필수 지점·실제 파지/운반·내려놓기/둘러보기가 빠지면 미측정이며 채택하지 않는다. 3라운드가 상한이고 호스트 wall 상한은 없다.

요구 정확도는 `mapbuild6_requirements.py`가 기존 성공 교사40건(79800–79839, 소스6f057f7e)의 보존 원장과 v7 정적 지도에서 계산한다. native87420–87459 원본은 이 작업의 단독 gcp5에 없고 다른 VM에 접근하지 않았다. 사용자 허용 대체인 기존 교사 원장을 사용한다. 과거 CPU 교사 분포는 요구 조건 근거일 뿐 native 성능·ACT 학생 성공과 합산하지 않는다. 이질적인 시작 XY 구름의 P95 반경을 위치 허용오차로 사용하지 않는다. 거리 P5/P50/P95의 작은 양쪽 여유를 XY 예산으로 하고, 위치오차가 만드는 시선각과 yaw 오차의 합을 성공 시작의 시선 오차 P95와 비교한다. 이 경험적 범위는 학생의 성공 허용범위를 입증하지 않는다.

실제 녹화 후보는 `s1_normal_mixed_v7`의 cyan_2→A 경로다. 실제 성공 원장의 자기 발행 휠/PWM 파지 prefix를 새 native 물리에서 재생한 뒤 기존 `scripts.zone_teacher.plan_path/proportional_drive`로 지도 주행을 잇는다. 제어는 자기 JPEG의 LK와 자기 명령 예측, 정적 지도만 쓴다. 시작은 원장에 고정된 진단 조건이며 온라인 위치 정답을 읽는 초기화가 아니다. 추정기는 시작0 gauge다. 과거 교사의 성공을 native 재생 성공으로 승계하지 않으며, 실제 파지 실패가 확인되면 감독 중단한다. 목적 구역에서는 원장의 lower/open/backoff/자기 RGB 둘러보기를 발행하고 같은 통로로 돌아오도록 한다. 실제 도착/파지/구역/문 통과는 별도 평가에서 확인한다.

`warp_native_contact_v1` owner bytes를 유지한다. noslip0, 벽/바닥 질감·색 분리 `walls_floor_contrast_v5_indigo110_s80`, MJWarp 물리/렌더, 자기RGB10Hz이며 TOP은 렌더조차 하지 않는다. 기존 원장의 파지 휠/PWM을 타 장면/호스트로 옮기는 새 재생 후보이고, 기본값이나 기존 제어기 수정은 아니다. 일반 휠 duty의 명령 예측은 기존 6f057f7e 명목 휠 기하식이며 native 실측 보정이 아니다. 이 경계와 arm/servo 변화에 따른 LK 미측정도 원인표에 남긴다.

소스는 실행 전 커밋·push한다. gcp5 bare 공유 저장소가 shallow여서 `clone --reference`가 거부됐다. 공유 저장소를 unshallow/gc/prune하지 않았으며 이미 fetch한 해당 커밋의 `git archive`만 풀어 이력 복사 없이 사용한다. 소스 사본 전체 SHA 파일로 검증한다. 키/모델 자격증명은 전송하지 않는다. 분석은 gcp5, Mac 회수는 요약·몽타주·실패 프레임뿐이다. idle20과 budget-stop을 유지하고 CPU VM은 시작하지 않는다. 종료 전 실제 임대·프로세스·GPU 부하를 확인한 뒤 gcp5를 정지한다.
