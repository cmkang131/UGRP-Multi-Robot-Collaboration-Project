# 2026-11-19 sim2real DR (로봇 없이)

실물 로봇을 켤 수 없어서, 실물에서 달라질 수 있는 것들을 시뮬에서 흔들어 어디서 깨지는지 본 실험.
ACT는 이 컨테이너에서 못 돌린다(torch 설치 차단). 그래서 ACT 앞 단계인 **접근(approach) + 정렬**과
**색 분할(seg5_v1)** 만 본다. ACT가 배운 허용 오차는 약 ±1 cm / 4° (docs/sim2real/03_pipeline.md).

## 1. 시뮬 펄스 기준표 — `sim_pulse_reference.py`, `sim_pulse_reference.jsonl`
시뮬 바퀴 값(0.31–0.40) × 펄스 길이 × 방향별 이동량 810회. 실물 측정(scripts/real_pulse_bench.py)을
이 표에 맞춰 보정값을 만든다(scripts/fit_real_robot_calibration.py). 0.32 이하는 시뮬에서도 안 움직인다.

## 2. 접근 DR — `approach_dr.py`
평가에 쓴 접근 코드(solo_pipeline/harness/approach_survey_v1.py)를 고정 장면(6f057f7e) 그대로 돌리고 흔든다.
실행: `run_jobs.sh baseline_jobs.txt out.jsonl` (4개 병렬, MUJOCO_GL=osmesa).

기준(act14 red/cyan 12개 장면): 10개 정상 도착, 옆오차 최대 8.4 mm, 각도 최대 2.8°.
흔들기는 그중 6개 장면(91420 91421 91425 91432 91436 91440) × 10개 조건 (`approach_dr_results.jsonl`).
"허용 안" = arrived 이고 |옆오차| ≤ 10 mm, 각도 ≤ 4°.

| 바퀴 이동량 배율 | 0.7 | 6 | 6.9 | |

읽는 법:
- 바퀴는 **덜 가는 쪽(배율 < 1)은 안전**, 더 가는 쪽은 위험. 보정은 실물이 시뮬보다 조금 덜 가도록 잡는다.
- 지연은 0.3 s 명령 지연까지 정밀도는 그대로(시간만 길어짐).
- **카메라 장착 각도가 가장 민감**. 아래로 3° 또는 좌우 3°면 절반 이상 실패. 실물 카메라 각도를 1° 단위로 재서
  시뮬 카메라에 맞춰야 한다(사진 한 장 + 바닥 표식으로 측정 가능).

## 3. 인식 DR — `seg5_dr.py`
기준 실행 2개(91420 cyan, 91421 red)에서 10틱마다 저장한 카메라 화면 78장(`approach_dr.py --save-frames`).
노출·화이트밸런스·채도·감마·노이즈·흐림·JPEG을 바꿔 seg5_v1 결과를 비교 (`seg5_dr_*.json`).

- 노출 0.7–1.5, 화이트밸런스 ±15%, 노이즈, 흐림, JPEG 30: 목표 상자 재현율 ≥ 0.95, 잘못 칠한 픽셀 < 0.2%.
- **깨지는 곳**: 노출 0.5(벽 재현율 0.03–0.09, 다른 상자 0.37–0.55), 채도 0.6(cyan 목표 재현율 0.30).
- 즉 실물 화면이 어둡거나 색이 바래면 seg5 기준값을 실물 사진으로 다시 맞춰야 한다. 실물 사진(PR #725 원본)이 있으면 바로 확인 가능.
