# Jev를 행동 결정기로 쓸 수 있는가 — 오프라인 평가 (사전 등록)

2026-10-11. 시뮬레이션 없음. 질문: 자연어 대화는 LLM(Gemma 4 31B), 행동 **선택**은 Jev가 맡는 분업이 가능한가. Gemma와 의견이 다르다는 이유로 Jev를 기각하지 않는다. Gemma 일치율은 기술 통계일 뿐 성공 기준이 아니다. 기준은 아래 고정한 라벨 집합이다.

## E2E에서 로봇 LLM이 실제로 고르는 행동 (코드 근거)
`harness/e2e_dialogue.py` `check_action`: `continue`, `claim`, `approve_route`(r2만), `route_vote` GO/ACK. 그 밖은 `E2E_DIALOGUE_ACTION_NOT_CONNECTED`. 이동 자체는 코드(`e2e_live_transport`)가 하고 `continue`는 운반을 막는다. 파이프 계층(`pair_llm_decisions.HOOK_ACTIONS`, `e2e_setdown_relook`)에 `carry_decision`(continue/set_down), `post_look_decision`(regrasp/look_again)이 있다. 별도 묶음(carry, postlook)으로 평가한다. 저장된 실제 E2E 요청 54건은 전부 t≤4 s, key=null이며 응답은 전부 `continue`였다. 한 결정 지점만 다룬다. 그래서 라벨 묶음은 합성이다.

## 고정 자료
- `suite.json`: 64개 상태, 결정 지점 10종, 각 상태의 허용 행동 **집합**과 규칙 인용(`rules`). 라벨 근거: hard_contract 51, inferred_from_contract 9(규칙에서 추론, 하드 검사 아님), ambiguous 4. 메시지 민감도 쌍 22(change 6, no_change 14, either 2).
- 분할: `dev` 31 / `holdout` 33. 같은 기준 상태의 변형은 같은 쪽에 둔다. 소금 `s0:`, 그룹 해시로 코드가 고정. 개선 표현은 dev에서만 조정하고 holdout에서 한 번만 시험한다. holdout 개별 실패는 개선안 확정 전에 열지 않는다.
- 구조적 후보 수(`n_structurally_admissible`): 의미 술어만으로 남는 후보 수. 1이면 코드가 사실상 답을 정한 경우. "후보 2개 이상 중 정답" 비율을 따로 보고한다.
- 규칙 기준선은 구조 필드만 보고 피어 텍스트를 무시한다. 하드 라벨은 규칙으로도 풀린다(테스트로 확인). Jev/Gemma가 규칙보다 나을 수 있는 곳은 피어 메시지로 답이 바뀌는 쌍뿐이다.

## 정책·반복
Jev(jev-1.13.0, 선택 API): 표현 2(raw, semantic) × 3회. Gemma(google/gemma-4-31b-it, DeepInfra 고정, temp 0.2 = E2E와 같음): 같은 두 표현 × 3회. 같은 텍스트 상태·같은 선택지. E2E 실제 Gemma 프롬프트(이미지·메시지 생성 포함)와는 다르다. 동일 입력 비교일 뿐이다. 호출 상한 1,500(HTTP 시도 포함, 재시도 2회까지 기록).

## 판정 기준 (결과 보기 전에 고정)
결정 지점 X에서 Jev를 결정기로 쓸 수 있다 = (a) 그 지점 하드 라벨 상태의 허용 행동율 ≥ 90%, (b) 후보 ≥2 구조 상태에서도 ≥ 90%, (c) 반복 안정성(3회 동일) ≥ 90%, (d) 해당 쌍이 있으면 no_change ≥ 80%, change ≥ 80%. 하나라도 모자라면 "아니오" 또는 "표현 의존"으로 적고 원인을 진단한다. 신뢰도는 (정답 vs 오답) AUROC>0.7이고 모호 상태에서 낮을 때만 게이트로 권고한다. 표본이 작아 n/N을 항상 함께 적고 통계적 유의성은 주장하지 않는다.

## 해석과 한계
- **표현이 결과를 좌우한다(09-21과 같은 교훈).** E2E 요청에 가까운 raw 필드만 주면 Jev는 진행 단계(claim·GO·ACK)에서 `continue`로 멈추는 편향이 있다(하드 105/153). 계약 술어를 코드가 계산해 주면 136/153, 선택지별 사용 조건과 피어 준비 상태 문구를 더한 v2는 holdout 90/90이다. Gemma도 같은 방향이다(139→147/153).
- v2는 선택지마다 "허용 조건"을 적은 것이어서 코드가 사실상 답을 정한다. 규칙 기준선이 하드 라벨 51/51을 이미 푼다. 모델이 규칙 위에 보태는 것은 **피어 자연어 읽기**뿐이고, 그 시험 표본은 작다(holdout 9 + dev 9 + probe 24 호출 중 NL 민감 일부). 새 표현(부정, 과거형, 한국어) probe에서 각 모델이 1/13 상태(3/39 호출)를 틀렸다(Jev는 P05 안전 쪽, Gemma는 P10 위험 쪽). 한국어·부정문 일반화는 확인 안 됨.
- 규칙에서 추론한 라벨 9개(피어 "미끄러졌다" 등)는 하드 검사가 아니다(R-GRIPPEER). change 쌍 6개는 전부 이 종류다. 이 라벨 자체는 사용자 확인이 필요하다.
- 결정 지점 `approve`에 B04(claim) 상태가 들어 있다. carry/post_look는 상태 수가 적다(holdout post_look 1상태). 모호 상태는 4개뿐이라 보정 결론은 약하다.
- 이 평가는 텍스트 상태 비교다. E2E에서 GO/ACK의 "내 RGB가 그립을 지지"는 손목 영상 판단이다. Jev는 이미지를 받지 못한다. 영상 요약을 누가 만드는지(Gemma 또는 코드 분류기)는 시험하지 않았다. 폐루프·실제 시뮬레이션·실제 영상 입력은 확인 안 됨.

## 판정 (사전 등록 기준 적용; 표본이 작아 통계적 유의성은 주장하지 않는다)
Jev를 행동 결정기로 쓸 수 있는가: **semantic_v2 형태일 때만, 그리고 영상 입력 문제를 풀어야 한다는 조건으로 예.** raw 필드나 사용 조건 없는 semantic으로는 아니오(하드 라벨 105/153, 136/153; 피어 문장 반응 0/18, 3/18).

결정 지점별(semantic_v2, holdout 호출/상태 수; 기준 a·b·c·d는 위 사전 등록):
- 예: ack 21/21(7상태), approve 12/12(4), carry_stop 15/15(5), claim 12/12(4), explore 9/9(3), go 12/12(4), idle 6/6(2).
- 판정 보류(표본 부족): post_look 3/3(1상태; dev 12/12는 조정에 쓴 자료), propose·no_comm(holdout에 없음; dev만 각 3/3, 6/6).
- 신뢰도 게이트: **아니오.** 사전 기준 AUROC>0.7은 정답/오답에서 충족(0.80, 0.82)하지만 "모호 상태에서 낮을 것"은 불충족(모호 평균 0.80~0.90 > 비모호 0.71~0.83). v2 holdout은 오답 0/90이라 보정 자료 없음. 신뢰도는 오답 탐지용 약한 신호일 뿐 모호함 표시가 아니다.
- 한 줄 평가: v2에서는 코드가 계산한 술어가 답을 거의 정하고 규칙이 하드 라벨 51/51을 이미 푼다. Jev가 보태는 것은 피어 자연어 읽기뿐이며(쌍 6상태 + probe 13상태) Gemma가 같은 수준이다. 측정된 Jev의 장점은 지연(중앙 0.30 vs 0.57 s), 측정된 약점은 이미지 입력 없음이다. Jev가 Gemma와 달라서가 아니라 라벨 기준으로 판단했다.

## 다음 E2E 토글 설계 `decider=jev_v1` (기본 off, 켠 실행은 baseline과 구분)
1. Gemma는 지금처럼 전체 E2E 요청(영상 포함)을 받아 `messages`와 자기 `action`을 낸다. `action`은 그림자(shadow)로 기록만 한다.
2. 코드가 `dialogue` 뷰 + 전달된 `peer_reports` + 자기 명령 이력 + 아래 `own_rgb_supports_grip`으로 semantic_v2 상태를 만든다(`jev_decider_eval.semantic_state`, `V2_CRITERIA`).
3. Jev가 `kind`/`choice`만 고른다. 코드가 `grip_epoch/seg/route_hash/peer_go_ref`를 `dialogue` 뷰에서 채운다. `check_action`은 그대로 막고, 위반은 `continue`로 바꾸며 기록한다. Jev 신뢰도는 기록만 하고 게이트로 쓰지 않는다.
4. 네 통신 조건에 똑같이 적용한다. 호출마다 Gemma shadow action, Jev choice·confidence·확률, 지연을 남긴다.
- **차단 요소(토글 출하 전 필수 결정):** `own_rgb_supports_grip`을 누가 만드는가. Jev는 이미지를 받지 못한다. 후보는 (가) Gemma가 손목 영상에서 구조화 필드로 내는 것, (나) 코드 분류기다. 둘 다 이번 오프라인 평가에서 시험하지 않았다. 이 필드가 틀리면 Jev는 그대로 따른다.

확인 안 됨: 폐루프·실제 시뮬레이션, 실제 영상 입력, 한국어·부정문 일반화(probe 13상태), 규칙에서 추론한 라벨 9개(R-GRIPPEER)의 사용자 확인.
