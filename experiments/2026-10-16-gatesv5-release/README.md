# gatesv5 release: 진행 중

실행 소스 `a41781dd122b1e20b8eec7e43c553e779e6cfc30`, PR #491. gcp2 C MuJoCo CPU, 확정 장면 `walls_floor_contrast_v5_indigo110_s80` + 원본 v1 바닥 + `no_mip_v1`. 경계 검출 OFF, weld OFF, 학습/모델 호출 0. 이전 장면·gcp1·짧은 실행과 관문은 합산하지 않는다.

장면 연결 초기 HOST_ERROR는 `setup-rejection_table.json`과 gcp2 원본에 보존했다. 빔 짝은 32개, release24는 14개 비물리 검사를 통과했다.

최종 상태는 아직 미확정이며 gate 관문 성공을 주장하지 않는다. 운영 명령·계획·원본 경로와 최종 집계는 후속 기록에서 갱신한다. 다른 임대를 보존하며 호스트 전체 실행 상한40을 적용한다.

짧은 재검증 최종: A3/3, B3/3, cap_end/HOST_ERROR0(최종 소스만), 입력 감사6/6=0/0/top0, 원본2534파일 해시 불일치0·최종 오수용0. 이전 장면 DEV는 합산하지 않았다. 초기 두 장면 연결 버전의 HOST_ERROR12는 별도 보존한다. 새 A40/B40은 APPROVED_PINNED이며 빔 짝 관문이 임대를 해제하면16동시로 시작한다. 짧은 실행의2초 안정 기간은 원본 evaluation_settled_s를 사용하고, 최종 구역 적합성은 원본 좌표로 독립 재계산했다. 본 관문은 평가 snapshot도 추가 보존한다.

운영 복구: 기록 카메라 API 오류16건 HOST_ERROR 뒤 수정했다. 이후 용량 입장 거부를 예외로 처리한 감독기 때문에14회가 중단됐다(10회 중단 최종화·4회 최종화 미완 HOST_ERROR). 본래 같은80회 계획에서 검증된20성공은 보존하고60개 중단/미실행 사례만 같은 소스·장면·시드·프로필로 재개했다. 이는 제어 후보나 장면을 합친 결과가 아니다. 용량 부족은 제출 대기, 대기열 pop은 제출 성공 뒤, SIGINT는 Python 자식에 한 번만 전달하도록 고쳤다. 실패한 결과 수집기의 DONE 생성 경합도 고쳐 별도 로그를 보존했다. `operational-recovery.json`과 회귀 검사 파일을 참고한다.
