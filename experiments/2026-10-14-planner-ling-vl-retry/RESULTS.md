# Ling VL 제한 확인: 대체 비율 초과로 중단

실행 소스 `c3e164b09d7c1071836610d0a601b037486187eb` (진단은 `f81bced0`).
이전 137 HTTP 시도와 별개인 새 원장이다. 호출 상한 600회·$0.08,
Ling 전용 재시도 정책과 중단 조건을 커밋한 뒤 실행했다.

429 본문은 `provider_name=Novita`,
`limit_source=upstream_provider_shared_pool`을 명시했다.
따라서 이번 오류는 **Novita 공유 풀의 상류 제한**이다.
Retry-After와 X-RateLimit-* 헤더는 없었다. 정확한 공급자 RPM 한도는 미확인이다.
진단 3회는 모두 200이었으나 본 확인의 네 번째 결정이 429를 세 번 받았다.

| 항목 | 새 실행 결과 |
|---|---|
| HTTP 시도 | 9/600: 진단 3 + 본 확인 6; 200 6건, 429 3건 |
| 본 확인 | 4/400 결정 요청; 이후 396개는 호출하지 않음 |
| 재시도 후 대체 | **1/4 (25%)**, 5% 초과 즉시 중단 |
| 형식 오류 / 재질문 | 0/4 결정 / 0회; 실제 모델 본문 수신은 3개 |
| 재시도 분포 | 본 확인: 0회 3개 결정, 2회 1개 결정; 진단: 모두 0회 |
| 재시도 대기 | 합계 4.614초 (1.340초 + 3.273초) |
| 결정 지연 중앙 / p90 | 1.770 / 7.024초, N=4; 실패·속도 제한 대기 포함 |
| 확인된 usage 비용 | $0.0003207064, 진단 포함 |
| 비용 미확인 | 429 3건; 보수적 예약 포함 합계 $0.0016563568 (청구액 아님) |
| prompt_tokens 중앙 | 3,533; 성공 본문 3개 |
| 캐시 off / on | 9,472/11,900 = 79.60% / 미측정 (0/40 호출) |
| 이미지 수락 | 미측정: 0/5 호출, 수락 확인 0건; 거부 5건을 뜻하지 않음 |

off 캐시는 앞선 진단이 같은 입력을 사용했으므로 따뜻한 캐시일 수 있다.
on 비교를 하지 못했으므로 순서 변경 효과를 주장하지 않는다.
형식·지연 조건 외에 새 대체 조건이 작동했다. 작업 전용 중계는 종료했다.

원본 채점 표에는 미호출을 포함한 원래 분모를 유지했다. 그 표의 대체 표시
397/400에는 미호출 396개가 들어 있으므로 실행 대체 비율로 쓰지 않는다.
실제 요청한 결정의 대체는 1/4다. 이 표본으로 모델 성능을 평가하지 않는다.
합성 튜닝 사례이며 확증·전체 세트·VM 실행은 하지 않았다.

## 동시 16실행 부하

r80의 저장된 16실행 요청 시각을 다시 세면 첫 30 SIM초에 각 실행의
r1/r2 합계 4호출, 즉 실행당 0.1333호출/SIM초다. 로봇 2대가 이미 포함된
값이므로 다시 2를 곱하지 않는다. 16실행이면 2.1333호출/SIM초다.
wall/SIM=3.5를 가정하면 **36.57회/분**, 3.0이면 **42.67회/분**이다.
재시도와 r3는 제외했으므로 실제 HTTP 부하는 더 클 수 있다.

이번 설정은 중계당 동시 1개·30회/분이다. 3.5 가정에서도 수요가 설정을
22% 초과한다. 공급자의 숫자 한도는 공개 응답에 없고 이 설정에서도
공유 풀 429가 발생했으므로 **16실행 수용 가능 여부는 확인되지 않았다**.
이 설정은 공급자 보장 한도가 아니며 여러 중계를 합친 전역 제한도 아니다.
과거 r80 제어기의 요청률을 이용한 추정이며 새 Ling E2E 실측이 아니다.

## 검증과 보존

관련 시험 21개 통과: `test_openrouter_upstream.py`, `test_task_planner_ling.py`.
Retry-After 초/날짜, 지터, 간격 제한, 최대 재시도, 재시작 후 예산,
비밀 삭제, 대체 비율 중단 및 기존 Gemma 동작을 검사했다.
새 번들 v401/v402는 유지하되 VM 제출하지 않았고 PR은 draft다.

짧은 수치와 한계는 `summary.json`, r80 원본 해시는 `r80-load.json`,
실행 원본 경로·해시는 `raw-manifest.json`에 있다.
큰 결정 원장은 zstd 무손실 압축 후 해제 SHA-256을 확인했다.
진단 기록의 sha256은 진단 3회 시점 원장의 해시이며 최종 9회 해시는
raw-manifest에 따로 남겼다. 이전 137회 원본은 변경하거나 합산하지 않았다.
