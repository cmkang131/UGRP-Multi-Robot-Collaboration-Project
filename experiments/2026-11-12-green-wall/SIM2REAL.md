# 시뮬레이션에서 ras1로 옮기는 범위

2026-11-18 사용자 방향: GitHub에 올라간 시뮬레이션을 기준으로 Sim2Real을 한다.
이 기록은 2026-11-12의 벽·바닥 특징점 DEV를 그 작업의 **초기 보정 근거**로
연결한다. 새 실물 실행이나 Solo 임무 전체 이식 성공을 선언하지 않는다.

## 기준과 출처

- [관측·명령 계약](https://github.com/cmkang131/UGRP-Multi-Robot-Collaboration-Project/blob/3d1e654f5dfbd86163216897913c664be6b64fa8/docs/sim2real/02_robot_interface.md).
- [T01–T13 카드와 결과 양식](https://github.com/cmkang131/UGRP-Multi-Robot-Collaboration-Project/blob/3d1e654f5dfbd86163216897913c664be6b64fa8/docs/sim2real/04_tasks.md).

  자기 발행 PWM에서 명목 카메라 위치·시선을 계산하는 구조.
  기구 체인 SHA256 `0cced72fd129556cb1e1ecbeef63155129426e669f77b6d5a70244d3d9b269be`.

11/12 실물 실행은 위 11/13 카드 묶음보다 앞선 별도 DEV다. 과거 기록을 새 카드의
준비 조건·통과 기준을 만족한 실험으로 소급하지 않는다. 시뮬레이션 결과와
실물 결과, 모의 검증과 물리 검증의 분모를 합치지 않는다.

같은 기준 커밋의 최신 [README](https://github.com/cmkang131/UGRP-Multi-Robot-Collaboration-Project/blob/3d1e654f5dfbd86163216897913c664be6b64fa8/README.md)는
11/15 결정에 따라 천장 카메라의 로봇 위치·방향을 실행층에 쓰는 구조다.
11/13 과제 문서의 자기 RGB 전용 설명과 이 후속 변경을 혼동하지 않는다.
이 ras1 DEV는 자기 RGB만으로 동작한 **별도 지역 거리/상대 이동 진단**이다.
이를 최신 실행층의 천장 위치 측정 대체물이나 전체 입력 계약 구현으로 주장하지
않으며, 통합 시 관측 출처와 좌표계·입력 경계를 별도 버전으로 명시해야 한다.

## 가져온 것, 실물 차이, 남은 검증

| 연결 카드 | 시뮬레이션에서 가져온 구조 | ras1에서 관측한 차이와 현재 범위 |
|---|---|---|
| T01 환경·색 | 자기 RGB에서 색과 바닥/벽 접점을 구분 | 초록 벽 후보·회색 점박이 바닥의 DEV HSV/접점 프런트엔드. 정식 마스크 평가·일반화는 미완료 |
| T02 카메라 | 고정 어안 K/D, 같은 pinhole K로 기하 계산 | ugrp1 보정값을 재사용했으나 ras1 독립 보드/holdout 보정은 미완료. 초기 노출 변화는 안정화·ORB 상호 대응으로 진단 |
| T04/T05 팔·시선 | 명령 PWM·링크·장착 체인 | 현재 명령 자세에서 높이23.086cm를 설계 환산 기준으로 사용. 명목 바닥 방향은 영상 추정과 약30도 달라 별도 바닥 법선을 적합·고정. 실측 관절·높이·하중 처짐 보정 아님 |
| T03/T06 구동·계약 | 발행 명령 이력과 자기 RGB로 이동 확인 | 기존 SDK의35/65와 시뮬 휠0.31–0.40은 같은 단위가 아님. 100배 환산·몰래 clipping 없음. 관측 벽 거리 변화로 접근/후퇴 구동을 고름 |
| T07 기록 | RGB·발행/정지 시각·실패·해시 보존 | 동일 기기 시각의 연속40프레임·차체5펄스·6거리 관측. 새14채널/10Hz 어댑터 이벤트 계약 전체를 검증한 것은 아님 |
| T11 지도 없는 이동 | 자기 카메라에 기반한 상대 주변 기억 | 벽 밑 접점과 카메라 기준 거리 변화를 표시. 문 통과·색 구역 도착·자율 경로 성공은 미검증 |
| T13 SysID 되먹이기 | fit/holdout 분리 후 새 시뮬 버전 비교 | 바닥 방향·실제 구동 축 차이는 되먹이기 후보. 기존 동결 본 실험이나 production 물리를 덮어쓰지 않음 |

현재 실행기는 기존 I2C transport를 사용하는 독립 짧은 펄스 진단이다. 최신
Solo/hybrid의 동기14채널·10Hz·중첩/취소/STOP 계약을 구현한 backend라고 부르지
않는다. 표준 어댑터와 실제 단위/채널/정지 계약을 맞추는 T06 검증이 남아 있다.

## 실물에서 확보한 근거

- 고정 실행 소스: `65e42db68891937c1ee4224c7a494e338f9ef0f8`.
- 실행 식별자: `wall-distance-runs/20261112-195538` (로봇의 실행 저장소 기준).
- 팔/머리 서보 명령0회, 초기·최종 명령 자세 동일, 차체5펄스 후 정지.
- 카메라 기준 벽 밑 접점 거리 추정: 17.563→22.776→17.353cm.
  높이는 명령과 설계도 기반이고 외부 실측 정확도는 미검증이다.
- 바퀴 속도·펄스 길이를 측정 이동 거리로 대체하지 않는다. 자기 RGB의 바닥
  homography와 보이는 접점으로 계산하며 공용 TOP·태그·정답 좌표를 쓰지 않는다.
- 관련 코드 시험9개와 해당 짧은 왕복 검증은 완료했지만 카드 전체 인수 성공은 아니다.

다음 비교는 같은 고정 소스·카메라 변환·입력 해상도·명령 의미를 가진 sim/real
쌍으로 구성하고, 실측 보정용 자료와 새 평가 자료를 분리한다. 먼저 T02/03/05/06의
차이를 계측하고 그 결과를 명시적 어댑터·새 보정 버전에 반영한다. 기존 DEV의
색/개수/기울기 문턱을 최신 과제의 채택 상수로 자동 승계하지 않는다.

공개 기록에는 개인 경로·주소를 넣지 않는다. 원본 위치의 비공개 인덱스와 원본
해시는 실행 저장소에 보존하며, 공개 상대경로·해시가 있다는 사실만으로 원본
회수나 원격 백업 완료를 선언하지 않는다.
