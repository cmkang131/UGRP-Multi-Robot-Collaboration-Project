### 6. MAJOR · #294 — p=0.88/N=225는 계산상 맞지만 현재 배치 설계가 정확 이항의 전제를 제공하지 않는다

10 Hz 프레임의 시각을 각각 ±0.1초 옮겨 동시 시각을 제거하면 0.2–0.3초 공백이 생긴다. 인과적인 0.11초 허용 선택과 긴/짧은 쌍 검사가 그 검사를 `MISSING_FRAME`으로 만든다. 기존 테스트와 같은 정렬/동시 시각 처리에서 **영상 점수를 항상 유효하게 만들어도** 다음 비율이었다.

| 명령 길이 | RNG 93001 | 93002 | 93003 |
|---|---:|---:|---:|
| 60 s, 기준 이후 284회 | 223/284 = 78.52% | 224/284 = 78.87% | 231/284 = 81.34% |
| 90 s, 기준 이후 434회 | 349/434 = 80.41% | 341/434 = 78.57% | 350/434 = 80.65% |

기존 8초 합성 이동 영상의 93003도 18/24=75%, 경보 0, `status=EVALUATED`였다. **EVALUATED는 기준 신호를 얻었다는 상태일 뿐 95% 유효 검사를 뜻하지 않는다.** 기존 지터 테스트는 상태/경보 존재만 확인하므로 이 수용 기준을 검증하지 않는다. 이 반례는 물리나 검출 정확도와 무관한 시각 계산만으로 발생한다.

**최소 수정:** 95% 관문을 잡음·지터 모든 조합에 적용하는지 명시하고, 그대로라면 현재 지터 조건은 관측 실패로 기록한다. 다른 카메라 지터 모형을 의도했다면 근거와 함께 봉인 전에 변환/중복/공백 규칙을 새 버전으로 고정한다. evaluator에 ≥95% 검사를 넣고 이 반례를 시험한다. 확증을 보고 95%를 80%로 낮추거나 누락 창을 분모에서 빼지 않는다.

### 9. MINOR · #294 — Monte Carlo 경계값의 표준오차 0을 불확실성 0으로 읽지 않게 해야 한다

**위치:** `V/analysis/cohort_sizing.py:157–160`; `V/analysis/sizing_20260930/COHORT_SIZING.md:8,14–15`.

3,000회 중 3,000회가 ≥48이므로 plug-in MCSE가 0인 것은 산술상 맞다. 하지만 이 모형 안에서도 확률이 정확히 1이라는 증거는 아니다. 초안 본문의 경고는 적절하다. 기계 판독 JSON에는 0.0만 있어 경계값 정밀도가 과장될 수 있다.

## 독립 통계 재계산

프로젝트의 확률/MC 함수를 호출하지 않고 표준 라이브러리의 직접 조합합과 NumPy 최소제곱·난수로 다시 계산했다. SciPy는 기존 환경에 없어 설치하지 않았다. 이항 꼬리는 `sum(comb(n,j)*p**j*(1-p)**(n-j), j=k..n)`이다. Wilson/정확 구간의 정의는 [NIST 원문](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm), 0건 사건의 3/n 근사는 [Hanley–Lippman-Hand 원 논문](https://jhanley.biostat.mcgill.ca/Reprints/If_Nothing_Goes_1983.pdf)을 확인했다. 아래 수치는 직접 계산값이다.

### A: 60개 관측 gate와 모집단 gate

| 독립 동일확률 p 가정 | P(X≥48), n=60 | P(X≥55), n=60 |
|---|---:|---:|
| 0.65 | 0.008602576509 | 0.000001751065 |
| 0.70 | 0.056770682002 | 0.000050019992 |
| 0.75 | 0.231557633688 | 0.000956128743 |
| 0.80 | 0.576440301446 | 0.012106170019 |
| 0.83 | 0.789637100385 | 0.044768596803 |
| 0.85 | 0.893753999022 | 0.096798508727 |
| 0.88 | 0.976071987195 | 0.258970174673 |
| 0.90 | 0.994318994952 | 0.437165870737 |

문서의 반올림과 일치한다. 48/60의 Wilson 양측 95% 구간은 **[0.682182, 0.881715]**다. 54/60의 Wilson 하한은 0.798505, 정확(Clopper–Pearson) 하한은 0.794942라 0.80을 넘지 않는다. 55/60은 각각 **0.819311 / 0.816142**다. 초안은 z=1.96, 이 표는 z=1.959963984540054를 사용해 마지막 자리만 다르다.

**48/60은 제한된 관측 gate로는 정직하다.** 고정 60개에서 관측한 완주 수만 말하고, B와 모든 시드 안전 거부가 별개로 통과해야 하며, 모집단 80%·무접촉·정지 대응·E2E·실물 성공으로 확대하지 않아야 한다. p=0.75에서도 23.16%가 넘는 문턱이므로 모집단 적격성 시험이라고 부르면 안 된다. 현재 문서의 이 경계와 p2f 0/208 명시는 유지할 가치가 있다.

각 N=1…619를 직접 검색해 귀무 p=0.8의 꼬리가 ≤0.025인 최소 k를 찾고 대립 p에서 검정력을 계산했다.

| 설계 p | 최초 N | k | 검정력 | 귀무 꼬리 | 더 작은 모든 N의 최대 검정력 |
|---|---:|---:|---:|---:|---:|
| 0.88 | **225** | **192** | **0.905981140258** | **0.024504935351** | 0.899475489335 (N=219,k=187) |
| 0.85 | 619 | 515 | 0.903669256993 | 0.024438581171 | 0.899818687963 (N=614,k=511) |
| 0.90 | 137 | 119 | 0.910009477951 | 0.024479741322 | 0.896557542708 (N=131,k=114) |

따라서 **N=225 주장은 명시된 i.i.d./p=0.88/양측 정확 95% 하한/90% 검정력 조건에서 맞다.** 이는 통과 개수만의 검정력이다. B·접촉/하드 거부까지 통과할 확률이 90%라는 뜻은 아니다. 단측 95% 하한(α=.05) 설계와도 구분한다. p=0.80에서 이 검정의 통과 확률은 ≤2.5%이므로 N을 늘려 90%를 얻을 수 없다.

### A: 두 시드의 상관과 59.741/60

주 판정은 배치당 **941 한 건**, 943은 12개 보조다. 따라서 120건 독립 이항으로 계산하거나 “두 시드 모두 통과” 확률을 현재 주 판정에 넣으면 안 된다. 반대로 29개 probe의 58건을 n=58로 Wilson 계산하는 것도 안 된다. 29/29의 명목 하한(z=1.96)은 **0.883026406**이고, 잘못된 58/58은 약 0.93788이다.

| 입력 경계 | import는 NumPy/dataclasses/typing/__future__뿐. GT/시뮬레이터/모델/파일 I/O 없음. 자기 일정 병진 구간을 올바르게 만드는 adapter는 아직 별도 검증 대상 |

**검토한 lag·block·reference·k 로직에서 확정된 오프바이원/단위 오류는 없다.** 연구 README의 “2창(0.4 s)”는 검사 주기×횟수 표현이다. 실제 두 검사 끝점 사이 간격은 0.2초이고 각 점수는 겹치는 1초 창을 사용한다. 이를 독립된 0.4초 관측이나 고정 0.4초 검출 지연으로 해석하지 않는다.

연구 코드와 바이트 동일하지 않은 변경(인과적 프레임 선택, 회색 변환, clean에도 잡음 보정, 프레임 단위 잡음, 느린 명령 포함)은 초안에 공개돼 있다. 따라서 탐색의 18/18·0/90·지연 1.6/1.2초는 새 구현의 재현 성능이 아니다. 저장 summary 재집계는 그 구별을 지켰다.

## 동결·누출·다중 비교 판단

- **사후 선택 자체는 숨겨지지 않았다.** D1 ratio 0.4/0.5, k 2/3을 탐색 후 선택했고 과거 9건/두 로봇/반복 시드의 의존성을 공개했다. 같은 자료를 새 확증 n에 넣지 않으며, 보조 `(0.5,3)`으로 주 `(0.4,2)` 실패를 대체하지 않는 규칙도 적절하다.
- 다만 parameter freeze만으로는 충분하지 않다. staging 지원 dev에서 본 **배치/영상/기전 조정 이력**, 포함/제외 판정, case/예비 목록, **평가 코드**, 잡음 변환/시드/시각 동률 처리, 고정 관측 길이까지 첫 확증 프레임 전에 해시로 묶어야 한다. adapter가 실제 자기 발행 명령의 속도/방향 변경을 올바르게 분할하는지도 필요하다. 이 모듈은 CommandInterval의 시작/끝만 받아 실제 비영 병진 여부를 확인할 수 없다.
- 두 문서 모두 **모든 사전 지정 관문을 AND로 통과**해야 하는 단일 주장이라면, 단순히 관문이 많다는 이유로 Bonferroni 보정을 강제할 필요는 없다(교집합–합집합 검정, intersection–union). 겹치는 창/변형을 독립 표본으로 세지 않는 것이 우선이다.
- 반대로 여러 정책·문턱·잡음 범위 중 **하나라도** 잘 나온 것을 최종 성공으로 선택하거나 개별 CI 전부를 동시에 95%라고 주장하면 별도 다중 비교/계층 검정 규칙이 필요하다. #294는 A/B 문턱 및 N 선택을 확증 전 하나로 봉인하고, #293은 주/보조와 잡음 범위의 위계를 봉인해야 한다. 12조합×3 RNG가 n을 36배 늘리지 않는다.
- B의 6개 축/leg 관문과 D1 기전별 비율은 현재 **관측 수용 기준**이다. 단순 gate 통과를 “과신이 없다는 모집단 증명” 또는 “모든 기전의 감도 ≥75% 증명”으로 넓히지 않는다.

## 봉인 전 필요한 결과와 확인하지 않은 것

봉인 전에 **1–8의 규칙/검증 공백**, 현재 OPEN 정의, 모집단 주장 여부를 닫고 문서·평가 코드·manifest를 일치시켜야 한다. #294는 다섯 플래그 등록 구현의 독립 검토와 lag ON 5개 골든 명령 바이트 동일 인수 재생도 별도 필요하다. #293은 고정 30/60 manifest와 독립 staging 지원·평가 코드가 필요하다. 알려진 시작 정체 누락 또는 지터 관측 실패를 받아들인 음성 결과 수집은 가능하지만, 그 경우 전체 성공을 기대/선언하도록 기준을 바꾸면 안 된다.

이 검토에서 **확인하지 않은 것**: 새 확증 60+12 또는 D1 30/60 실행, 제어기 등록/봉인 파일·PR #292 구현 전체, 물리 조작 성립, 원본 영상의 D1 재생, 카메라/조명 전이, 실물·E2E·안전, 전체 CI, 인수 재생, 전역 실행 이력의 완전한 중복 감사. 본 검토의 계산과 합성 반례는 새 물리/학습/평가 코호트가 아니다. 따라서 새 TensorBoard 스냅샷·서버·브라우저를 만들거나 기존 결과를 다시 변환하지 않았다. Google Drive는 프로젝트 예외와 read-only 범위에 따라 사용하지 않았다.

## 재계산 방법 보존 — 프로젝트 통계 함수를 호출하지 않는 핵심 코드

기존 `.venv-sim-worker-mac`의 Python 3.12/NumPy, `PYTHONDONTWRITEBYTECODE=1 OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1`로 저장 자료만 읽었다. 아래를 저장소 루트에서 실행하면 이항 최소 N과 네 MC 행을 독립적으로 재계산한다. 새 파일/물리/모델 호출은 없다.

```python
import json, math
from pathlib import Path
import numpy as np

def tail(n, p, k):
    return math.fsum(math.comb(n, j) * p**j * (1-p)**(n-j)
                     for j in range(k, n+1))

critical = {}
for n in range(1, 620):
    cumulative, k = 0., n+1
    for j in range(n, -1, -1):
        cumulative += math.comb(n, j) * .8**j * .2**(n-j)
        if cumulative > .025:
            break
        k = j
    critical[n] = k
for p in (.88, .85, .90):
    for n, k in critical.items():
        if tail(n, p, k) >= .90:
            print(p, n, k, tail(n, p, k), tail(n, .8, k))
            break

base = Path('experiments/2026-09-30-pair-v6h-carry')
obs = json.loads((base / 'analysis/sizing_20260930/training_inputs.json')
                 .read_text())['observations']
pl = json.loads((base / 'placements_confirmatory_DRAFT.json').read_text())
keys = [(r['label'], r['cell']) for r in obs]
units = sorted(set(keys))
by = {u: [i for i, k in enumerate(keys) if k == u] for u in units}
X = np.array([[1., math.degrees(r['beam_place'][2]),
               1000*(r['beam_place'][1]-.05)] for r in obs])
Y = np.array([r['signed_y_mm_L0_L1'] for r in obs])
features = np.array([[1., p['yaw_deg'], 1000*(p['y']-.05)] for p in pl])
sx = np.array([round(round(p['x']/.1)*.1, 6) for p in pl])
dx = np.array([p['x'] for p in pl]) - sx
cmd = .06 / (2.2/1.4)
gain = 1.4004 * .9483378899463337

def distance(T):
    return .05123 * (T - (.898-.0063)*(1-math.exp(-T/.898)))

def planned(d, lag_on):
    if not lag_on:
        return d / (.06*.772)
    lo, hi = 0., d/(gain*cmd)+8
    for _ in range(80):
        t = (lo+hi)/2
        traveled = gain*cmd*(t-(.8-.05)*(1-math.exp(-t/.8)))
        if traveled < d:
            lo = t
        else:
            hi = t
    return (lo+hi)/2

for lag_on, scale in ((False, 1), (True, 1), (True, 1.5), (True, 2)):
    axial = np.empty((40, 60, 2))
    for j, phase in enumerate(np.linspace(.495, .995, 40)):
        for i, sheet in enumerate(sx):
            d0 = 1.55-sheet
            t0 = .1*(math.ceil(round(planned(d0, lag_on)/.1, 9))-1)
            q = planned(.85, lag_on)/.1
            t1 = .1*(math.floor(q)+(phase+q-math.floor(q) >= 1))
            axial[j, i] = [dx[i]+distance(t0)-.00376-d0,
                           dx[i]+distance(t0)-d0+distance(t1)-.00376-.85]
    rng = np.random.default_rng(20261001)
    counts = []
    for _ in range(3000):
        chosen = [units[k] for k in rng.integers(0, len(units), len(units))]
        ix = np.array([i for u in chosen for i in by[u]])
        coef = np.linalg.lstsq(X[ix], Y[ix], rcond=None)[0]
        residual = Y[ix]-X[ix]@coef
        lateral = scale*(features@coef +
                        residual[rng.integers(0, len(residual), 60)])/1000
        along = axial[rng.integers(0, 40)]
        counts.append(np.all(along**2+lateral**2 <= .1**2, axis=1).sum())
    counts = np.array(counts)
    print(lag_on, scale, counts.mean(), (counts >= 48).mean(),
          (counts >= 55).mean())
```
