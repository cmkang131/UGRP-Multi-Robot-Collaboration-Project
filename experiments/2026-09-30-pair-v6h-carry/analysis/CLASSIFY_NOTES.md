# v6h 배치 분류: 봉인 전 해석·남은 결정

이 분석은 초안 §4–6의 평가 전용 구현(PR #290, base `claude/b-v6h-gain`에 병합)이다. 분류기를 만들 당시에는 사전등록 문서·제어기·봉인 파일을 바꾸지 않았다. 2026-09-30 후속 초안 갱신은 아래 **11개 권장안을 `../PREREG_DRAFT.md` §5.1에 같은 순서로 반영**했으며, 분류기·제어기·봉인 파일은 수정하지 않았다. 아래 권장안은 **검토자가 봉인 전에 확정할 해석**이며 현재 코드가 적용한 안을 공개한다. 일반 setdown 검사(6)와 teacher 준비/실행 기록 경계(7)는 **OPEN QUESTION FOR COORDINATOR**로 남아 있다.

| 모호한 점 | 한 줄 권장 해결안 / 현재 구현 |
|---|---|
| 1. 에피소드가 leg 창에 완전히 들어와야 하는가, 일부 겹치면 되는가? | 기존 `contacts_in`과 같이 닫힌 구간이 조금이라도 겹치면 포함한다(경계 허용오차 1e-9 s). |
| 2. 가드 정지는 `recorded=false`, `end_sim_s=null`이라 기존 leg 창이 없다. | 시작 시각부터 해당 carry leg의 첫 실패 시각까지 사용하고, 그 시각이 없으면 stop 시각→마지막 trace 시각 순으로 대체하며 출처를 기록한다; 시작도 없으면 접촉 귀속을 하지 않는다. |
| 3. “충돌 가드 정지 포함”이 접촉 없는 예방 정지도 BLOCKED인가? | **실패 AND 실제 벽 접촉 겹침**을 모두 요구한다; 가드 코드만 있고 에피소드가 없으면 FAIL이다. |
| 4. 통과 중 내려놓기·재파지 창에서만 접촉한 경우 CLEAN인가? | PASS_CLEAN의 “벽 접촉 0”은 전체 기록을 뜻하도록 정한다; leg 밖 접촉도 PASS_CONTACT_RECOVERED로 분리한다. |
| 5. 실패가 내려놓기·재파지에서 났고 그 창에 접촉이 있는 경우 BLOCKED인가? | 초안의 “실패한 leg 창”을 carry 창으로 한정한다; leg 밖 접촉만 있으면 FAIL, 하드 한계 초과이면 위치와 무관하게 FAIL_HARD_LIMIT이다. |
| 6. 일반 내려놓기 검사도 주 통과에 추가하는가? | §4의 L0·L1 표준 leg 검사만 주 통과에 사용한다; setdown 검사 실패를 별도 관문으로 추가하지 않되, setdown·재파지의 하드 한계는 전체 trace/에피소드로 검사한다. |
| 7. “연쇄 전체”가 L0 시작 전/다른 leg 기록도 포함하는가? | PR #288의 `hard_limit_chain`과 동일하게 **전체 저장 trace의 기울기와 모든 벽 에피소드**를 사용한다; teacher 준비와 실행 창을 분리하려면 봉인 전에 별도 기록 경계를 정해야 한다. |
| 8. 배치 단위 주 시드 판정과 탐색의 모든 시드 통과 판정이 다르다. | 확증 주 시드 기본값은 941로 고정하고 보조 시드는 별도 표시한다; 탐색 대조는 명시적으로 911을 선택하고 케이스·모든 기록 시드·하나라도 통과 통계를 각각 보고한다. |
| 9. 보조 시드의 하드 한계도 코호트 거부인가? | “코호트 전체에서 1건이라도”를 그대로 적용해 보조 시드도 safety veto에 포함한다; 배치 주 분류는 주 시드 결과를 유지하고 `hard_limit_any_seed`를 별도 표시한다. |
| 10. HOST_ERROR, 주 시드 누락, trace/접촉 기록 누락은 어떤 FAIL인가? | HOST_ERROR·주 시드 누락은 미분류로 이름/사유를 보존해 완료 판정을 막고, 일반 케이스의 trace/접촉 기록 누락은 오류로 중단한다; 미분류를 5개 결과 분류로 억지 변환하지 않는다. |
| 11. 작은 개발 코호트에 80% 문턱을 비례 적용하는가, σ 기준도 성공 선언인가? | 48/60은 정확히 60배치에만 적용하고 전체 하드 한계가 0이어야 한다; 이 도구는 관측 기준 A+safety만 판정하며 σ 기준 B·최종 성공 선언은 별도 분석이다. |

6·7의 현재 구현은 위 표의 권장안을 적용하지만, 초안의 OPEN 표시는 이 구현을 승인했다고 뜻하지 않는다. 조정자가 다른 정의를 고르면 문서·분류기·관련 시험을 **봉인 전에** 맞춘다. 3·4의 결과 이름은 접촉의 인과나 전용 복구 제어가 검증됐다는 뜻이 아니다. HOST_ERROR 재실행은 원 기록과 연결하며 원본+재실행을 같은 배치/시드로 한 입력에 중복 합치지 않는다.

현재 정책 초안은 다섯 플래그(`carry_axial_lag` 포함)이고 기본 주 기준은 여전히 ≥48/60이다. ≥55/60과 모집단 주장용 N 권고는 `../PREREG_DRAFT.md` §3.3–3.4 및 [`sizing_20260930/COHORT_SIZING.md`](sizing_20260930/COHORT_SIZING.md)에 별도 표시한다. 분류기에서 문턱을 조용히 바꾸지 않았다.

`hard_limit_chain`은 기존 파일의 출력 dict이고 같은 이름의 호출 함수는 없다. 이 구현은 `chain_analysis.py`를 **경로 기반 importlib**로 불러와 그 dict에 사용되는 `hard_limit_violated`, `contacts_in`, `pcp.leg_checks`, `wilson`을 재사용한다. 하드 문턱(기울기 >15°, 관통 >5 mm)을 복사하거나 변경하지 않았다. 양성 접촉 분류는 합성 단위 테스트로 확인했으며 실제 새 접촉 실험은 수행하지 않았다.

## 사용과 재검증

```sh
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 /Users/changmin/projects/ugrp/.venv-sim-worker-mac/bin/python \
  experiments/2026-09-30-pair-v6h-carry/analysis/classify_placements.py \
  --primary-seed 911 --output /tmp/v6h-classify-NEW \
  cB=/Users/changmin/projects/ugrp/outputs/b-v6h-gain-69c2a99a-cB
```

출력은 코호트별 JSON/TXT이며 기존 출력·raw 폴더에는 쓰지 않는다. JSON에는 배치·시드 분류, 첫 실패 phase/code, leg 창 출처, 전체 하드 한계, 원본 해시를 남긴다. Wilson 구간은 분류된 주 시드 배치의 n으로 계산하고 미분류 이름과 전체 배치 수도 같이 표시한다; 미분류가 있으면 코호트 판정은 `NOT_EVALUABLE`이다. 확률은 n=60에서 `P(X>=48)`의 정확한 이항 꼬리이며 안전/σ 조건을 동시에 만족할 확률은 아니다.

기존 raw 대조 수치·해시·범위는 [VALIDATION.md](VALIDATION.md), 배치별 표는 [validation_20260930/](validation_20260930/)에 있다. 기존 TensorBoard 스냅샷의 원본 코호트를 읽어 재분류한 작업이라 새 실험/스냅샷 변환·브라우저 재개방은 수행하지 않았다. 봉인·등록·새 물리 실행·모델 호출·병합은 수행하지 않았다.
