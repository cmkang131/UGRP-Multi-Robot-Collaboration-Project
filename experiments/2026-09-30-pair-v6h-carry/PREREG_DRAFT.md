# b-v6h 확증 코호트 사전 등록 초안 (2026-09-30, Claude) — **초안: 봉인·실행하지 않았다**

Refs #216. 독립 검토(Opus) 전에는 봉인하지 않고, 봉인 뒤에도 등록 구현(`REGISTRATION_PLAN.md`)이 병합되기 전에는 돌리지 않는다. 이 문서의 수치는 **기존 탐색·probe 코호트(`experiments/2026-09-30-b-v6h-gain`), PR #286의 오프라인 모형 및 이번 짧은 수치 계산**이며 확증 결과가 아니다. 2026-09-30 조정자의 `carry_axial_lag` 포함 결정을 반영했으나, 다섯 플래그 조합의 독립 검토와 등록 구현·인수 재생은 남아 있다. 이 문서가 봉인되면 아래 기준은 바꾸지 않는다.

2026-09-30 독립 검토(Codex 적대적 검토, PR #285 코멘트 P1-1…P2-7)를 이 초안에 반영했다. 기준의 **문턱·관문은 조용히 바꾸지 않았고**, 바꿀 수 있는 것은 아래 "게이트 전 남은 결정"에 안(案)으로 모아 두었다.

## 게이트 전 남은 결정 (봉인 전에 조정자가 정한다. 이 초안은 기본값만 적었다)

- **(a) 통과 기준의 뜻: 48/60 대 55/60** (§3, §4 기준 A).
  - 초안 기본값은 **안 A = 48/60**이다. 이것은 "고정된 60곳에서 관측한 통과율이 80 % 이상"이라는 기준이고, **모집단 통과율 ≥ 80 %의 증명이 아니다**(참 통과율 75 %인 제어기도 23.2 %의 확률로 넘는다. 관측 48/60의 Wilson 95 % 구간은 68.2–88.2 %).
  - **안 B = 55/60**은 이 배치 생성 분포의 모집단 통과율 ≥ 80 %를 주장할 때의 문턱이다(Wilson 하한 81.9 %; 양측 정확 95 % 구간도 같은 최소 통과 수). 다만 참 통과율 0.88에서도 넘을 확률은 25.9 %, 0.85에서는 9.7 %라 n=60은 모집단 주장용으로 검정력이 낮다(§3.4).
  - 문턱을 바꾸거나 두 안 중 하나를 고르는 것은 조정자의 결정이다. 어느 안이든 결과 보고에는 관측 수와 Wilson 구간을 함께 적고, 안 A만 넘었으면 "모집단 80 % 입증 아님"이라고 쓴다.
- **(b) 결정 완료: `carry_axial_lag`를 `b-v6h1`의 다섯 번째 플래그로 포함한다** (§2, §3.3; `REGISTRATION_PLAN.md` §2 결정 4).
  - **2026-09-30 조정자 결정**이며 `carry_fwd_gain` 보정과 함께 사용한다. 독립 검토는 아직 끝나지 않았다. 이는 초안 정책의 결정이며 등록·봉인 완료가 아니다.
  - 완료된 probe는 tS 12곳 + tR 10곳 + tX1/tX1b 추가 7곳으로 **29/29 배치, 58/58 케이스**가 L0→내려놓기→L1 표준 검사를 통과했다. 벽 접촉·하드 한계 위반은 0건이다. 같은 배치의 지연 OFF 대조는 추가 7곳 **3/7**, sB **11/12**, rB **7/10**이었다. 출처: gain README "carry_axial_lag 물리 확인", `results/axial_lag_physical_check.{txt,json}`와 각 코호트 결과.
  - **29개 probe 배치는 확증 60개가 아니다.** 시드 두 개는 독립 표본이 아니므로 58을 Wilson 분모로 쓰지 않는다. 보고된 29/29에 대한 Wilson 95 % 하한은 **0.8830 ≈ 88 %**(z=1.96)지만, 탐색 배치의 대표성·독립성이나 새 배치의 참 확률을 보장하지 않는다. 기존 HOST_ERROR 두 건은 X06 재실행(tX1b)과 구분해 보존한다.
- **(c) 과보수(σ가 너무 큼) 진단을 보고만 할지, 통과 관문으로 올릴지** (§4 진단 C). 초안 기본값은 **보고만**이다(관문이 아님). 관문으로 올리면 문턱 값(예: 축별 평균 z² ≥ 0.1)을 정해야 하는데, 지금 탐색 자료(cB L1 x 0.03)는 이 문턱을 넘지 못하므로 올리는 즉시 현 제어기가 기준을 못 넘는다.

## 1. 무엇을 확증하려는가 (쉬운 말)

든 채로 문을 지나 내려놓은 뒤(L0), 다시 집어(재파지) 문의 다른 쪽 끝까지 가는(L1) 연쇄를, **처음 보는 시작 위치 60곳**에서 로봇 스스로(자기 카메라·자기 명령 이력·정적 지도만으로) 해낼 수 있는지 본다. 제어기 초안은 등록된 b-v6g에 다섯 가지를 더한 것(`b-v6h1`):

1. 든 채 앞으로 갈 때의 위치 추정 이득을 0.9483배로(5.2 % 과대 보정).
2. 충돌 여유에 들어가는 위치 불확실성(σ) 배수를 2 → 1(든 상태).
3. 든 상태의 방향(yaw) 불확실성 관문을 3.0/2.5도 → 5.0/4.0도.
4. 진행 감시(정지 감지)는 "이동을 시작한 뒤에 들어온 위치 측정"으로만 기준을 세운다.
5. 축 방향 이동 시간도 이득 보정된 지연 모형의 역산(`carry_axial_lag=True`)으로 정한다. 옆 방향 지연 모형은 기존 보정을 유지한다.

**통과하면 말할 수 있는 것**: 이 조건(teacher가 만든 연쇄 시작 상태, SIM 시간, weld OFF, 정답 미사용)에서 위 제어기가 **고정된 60곳 중 기준 비율 이상**(안 A: 관측 통과율 ≥ 80 %)을 문 연쇄로 완주했고, **기록된 leg 끝점에서 σ의 과신이 없다**(±2σ 포함과 평균 z²가 과신 기준 안. 도달하지 못한 배치는 "검증되지 않음").

**말할 수 없는 것**:
- E2E 성공, 접근·파지 단계 포함 성공, 실제 로봇, 정지 감지가 작동함(아래 §7).
- **모집단 통과율 ≥ 80 %**(안 A만으로는 입증되지 않음, §3). 안 B를 사전에 선택하고 독립·대표 표본 전제가 맞을 때에만 그 생성 분포의 모집단에 한정해 구간 하한으로 말할 수 있다.
- **σ가 보정됐다**(정확하다)는 것. 포함 100 %와 낮은 평균 z²는 σ가 실제 오차보다 훨씬 커도 나오는 값이라 과신이 없다는 증거일 뿐 보정의 증거가 아니다. 탐색에서 cB L1 x의 평균 z²는 0.0285, 3자유도 NEES 평균은 0.2684로 **매우 보수적**이었다(σ가 실제 오차의 약 6배). 기존 "세 축 σ가 정직해졌다"는 말은 쓰지 않는다.
- 99.5 % 같은 모형 예측을 실제 완주율이나 안전 보증으로 읽는 것(§3.3).

### 3.1 파워와 기준의 뜻

주 판정 안 A = 60곳 중 48곳 이상 통과(관측 통과율 ≥ 80 %). 이항 분포에서 통과 수가 기준 이상일 확률. 안 B(55/60)와 나란히 적는다.

| 참 통과율 | 0.65 | 0.70 | 0.75 | 0.80 | 0.83 | 0.85 | 0.90 |
|---|---|---|---|---|---|---|---|
| 안 A: n=60, k ≥ 48 | 0.009 | 0.057 | 0.232 | 0.576 | 0.790 | 0.894 | 0.994 |
| 안 B: n=60, k ≥ 55 | 0.000 | 0.000 | 0.001 | 0.012 | 0.045 | 0.097 | 0.437 |

- **48/60은 "고정된 60곳의 관측 통과율" 기준이다.** 모집단 통과율 ≥ 80 %의 증명이 아니다. 참 통과율이 **75 %인 제어기도 23.2 %**, **70 %도 5.7 %**의 확률로 이 기준을 넘는다. 관측이 딱 48/60이면 **Wilson 95 % 구간은 68.2–88.2 %**로 80 %를 가로지른다(검토자 재계산과 이 문서의 재계산이 일치).
- **모집단 통과율이 80 % 이상이라고 주장하려면** Wilson 95 % 하한이 80 % 이상이어야 하고, 60곳에서는 **최소 55/60**(하한 81.9 %)이다. 54/60은 하한이 79.9 %라 모자란다.
- 두 안:

| | 안 A (초안 기본값) | 안 B |
|---|---|---|
| 기준 | 통과 ≥ 48/60 | 통과 ≥ 55/60 |
| 말할 수 있는 것 | 고정된 60곳의 관측 통과율 ≥ 80 % | 독립·대표 배치 전제에서 해당 생성 분포의 모집단 통과율 ≥ 80 % (Wilson 하한 ≥ 81.9 %) |
| 참 0.70 / 0.75 / 0.85에서 넘을 확률 | 0.057 / 0.232 / 0.894 | 0.000 / 0.001 / 0.097 |
| 위험 | 모집단 75 % 제어기가 넘을 수 있다(23 %) | 좋은 제어기(참 0.85)도 넘을 확률이 9.7 %뿐이다. ON 모형 평균을 참 p로 단정하면 검정력을 과장한다 |

- **이 문서는 안 A를 기본값으로 적었을 뿐이고, 고르는 것은 조정자의 결정이다("게이트 전 남은 결정" (a)).** 문턱을 조용히 바꾸지 않았다. 안 A로 진행하면 결과 보고 첫 줄에 "고정 60곳의 관측 통과율 기준이며 모집단 80 %를 입증하지 않는다"를 쓴다.
- 참 통과율이 0.70 이하인 제어기를 안 A로 잘못 통과시킬 확률은 ≤ 6 %(n=60)다. 0.85이면 통과 확률 89 %.
- n=60은 관측 기준의 설계다. 모집단 하한 주장을 원하면 같은 80 % 관측 문턱을 단순히 비례 확대하지 말고 §3.4의 정확 이항 문턱·검정력을 사용한다.

### 3.2 지연 OFF 대조의 dx 분석 (현재 ON 정책의 예측과 구분)

지연 OFF 탐색 sA/sB는 배치의 (빔 x − 반올림 시트 x) = dx에 의해 L1 끝 오차가 `64 mm + 1.09·dx`로 결정되고(상관 0.95–0.97), 100 mm 관문은 dx ≳ +33 mm에서 넘는다. **이 절의 49/60·≈77 %·+33 mm 경계는 OFF 대조의 진단이며, 지연 ON인 b-v6h1의 기대 완주율/실패 경계가 아니다.** ON의 앞뒤 오차는 대체로 dx 수준으로 줄지만 옆 오차는 남는다(§3.3).

- **dx ≤ +33 mm인 배치의 비율은 x 범위에 따라 다르다.** 시트 격자가 0.1 m라 dx의 범위는 ±50 mm지만, 생성기의 x 범위(0.92–1.07 m)는 격자 폭의 정수 배가 아니다. x < 0.95이면 시트가 0.9라 dx는 항상 +20…+50 mm이고(문턱 쪽으로 치우침), 1.05–1.07이면 −50…−30 mm다. 그래서 연속 균등 x에서 dx ≤ +33 mm인 비율은 116/150 = **77.3 %**이지, 균등 ±50 mm를 가정한 (33+50)/100 = 83 %가 아니다. 격자 반올림(밀리미터)과 제외 규칙까지 그대로 옮긴 모의 추첨(60곳 × 300번)의 평균은 0.761(표준편차 약 5.5 %p)로 같은 수준이다.
- **확정 파일(시드 20260941)의 60곳**에서는 dx ≤ +33 mm가 **49/60 = 81.7 %**다. 모집단 값(≈ 77 %)보다 높은 쪽으로 뽑힌 표본이며 모의 추첨의 흩어짐 안이다. dx ≤ +20 mm는 42곳, dx ≥ +45 mm는 2곳이다.
- 이 OFF 경계를 ON 정책의 표본 설계에 적용하지 않는다. 현재 정책의 수치 판단은 다음 절의 실제 60개 배치 모형·민감도를 사용한다.

| 지연 OFF 대조(P0) | 50.921 (84.868 %) | 0.975333 | 0.001333 |
| **현재 초안: gain+지연 ON(P1b)** | **59.741 (99.568 %)** | **1.000000** | **0.999667** |
| ON, 옆 방향 오차 ×1.5 | 55.487 (92.478 %) | 0.989333 | 0.699667 |
| ON, 옆 방향 오차 ×2 | 47.205 (78.675 %) | 0.488000 | 0.018000 |
| 보수적 가정: 모든 배치의 참 p=0.88 | 52.800 | 0.976072 | 0.258970 |
| 더 보수적 가정: 모든 배치의 참 p=0.80 | 48.000 | 0.576440 | 0.012106 |

- **모형 네 행**은 PR #286의 배치 단위 적합 부트스트랩·짝지은 L0/L1 잔차·공유 틱 위상을 그대로 사용한 Monte Carlo **3,000회**다. 조건마다 RNG 시드 20261001로 다시 시작해 배율 비교를 짝지었으며, 배율은 **평균+잔차 전체**에 곱했다. 통과 수에서 ≥48와 **≥55** 빈도를 직접 계산했다(원래 스크립트의 ≥54 출력과 구분). 1.000000은 3,000회에서 기준 실패가 관측되지 않았다는 뜻이며 확률 1의 보장이 아니다. 같은 평균을 독립 이항에 대입한 값도 아니다.
- **p=0.88/0.80 두 행**은 독립·동일확률 이항의 정확 꼬리 합이다. 29/29의 Wilson 하한 **0.883026406**을 보수적으로 0.88로 둔 민감도이며, probe가 각 확증 배치의 참 p를 알아냈다는 뜻이 아니다. 모형 배율 민감도와는 별개 가정이고 두 위험을 독립이라 가정해 곱하지 않았다.
- 모형은 **두 leg의 끝점 100 mm 검사만 예측**한다. 접촉·충돌/σ 게이트·내려놓기·하드 한계·기준 B를 모형화하지 않아, 이 확률은 A+B+안전의 전체 성공 확률이 아니다. ON probe 29/29는 새 시간 계산의 기존 배치 물리 근거이고 **60곳의 확증이나 등록 구현의 완주 근거는 아니다**.
- **옆 방향 전이가 가장 약하다.** 원래 잔차 평균 cB −7.2 / rB +26.2 / sB −14.6 mm, 배치 제외 예측 오차 28.7 mm 대 학습 잔차 26.4 mm. ON 물리 확인에서도 L1 잔차 sd 29.3 mm, 평균 tS −13.5 / tR +23.9 / tX1 −22.0 mm로 코호트 차이가 남았다(gain README 물리 확인 절). ×2에서는 기대 통과 수가 48보다 작다.
- 손실 값은 기존 기록의 용어를 유지한다: 시작 손실 46.0 mm(속도×시정수), 순손실 45.7 mm; 계획 상수 0.772는 10초 명령 비율 0.7777의 근사다. dx 반올림과 옆 방향 오차는 ON 뒤에도 남는다.

### 3.4 모집단 주장을 원할 때의 권장 N (봉인 전 별도 결정)

**초안 기본값은 여전히 n=60, ≥48/60 관측 기준**이다. 모집단 주장에 필요한 표본 수는 명시적인 설계 가정으로 계산한다: 독립·동일분포 배치, 귀무가설 p≤0.80, **양측 정확 이항 95 % 구간의 하한 >0.80**(Clopper–Pearson; 상단 꼬리 α=0.025), 목표 검정력 **90 %**. 각 N의 최소 통과 수 k는 `Σ(j=k…N) C(N,j)·0.8^j·0.2^(N-j) ≤0.025`로 정하고, 참 p에서 같은 정확 꼬리가 ≥0.90인 첫 N을 전수 검색했다. 정규 근사는 쓰지 않았다.

| 참 p 설계 가정 | 최소 N | 통과 문턱 k | 정확 검정력 | p=0.80 꼬리 | 모든 더 작은 N의 최대 검정력 |
|---|---:|---:|---:|---:|---:|
| **0.88 (권장 보수적 가정)** | **225** | **192/225** | **0.905981** | 0.024505 | 0.899475 |
| 0.85 (더 약한 전이 가정) | 619 | 515/619 | 0.903669 | 0.024439 | 0.899819 |
| 0.90 (비교용) | 137 | 119/137 | 0.910009 | 0.024480 | 0.896558 |

따라서 조정자가 모집단 주장을 원하면 **N=225, ≥192/225**를 권장한다(참 p=0.88에서 90 % 검정력을 원한다는 조건). p=0.85까지 대비하려면 **N=619**가 필요하다. 참 p=0.80이면 이 검정의 통과 확률은 어떤 N에서도 ≤0.025라 표본 수만 늘려 90 %를 얻을 수 없다. 현재 60곳은 p=0.88에서도 ≥55 통과 확률이 0.258970이다. 54/60은 정확 꼬리가 0.025보다 크고 55/60은 0.012106으로 충분해 Wilson 문턱과도 일치한다.

**OPEN QUESTION FOR COORDINATOR:** 모집단 주장을 추가할지, 그때의 참 p 설계 가정·90 % 검정력·양측 정확 95 % 하한 규칙을 채택할지. 확대 표본은 아직 생성·실행하지 않았다. 현재 60곳의 모형 평균 99.568 %를 새 225곳/619곳의 모집단 참값으로 사용하지 않는다. 배치·사전분포의 독립성/대표성을 정하지 않으면 N을 늘려도 그 모집단 주장은 성립하지 않는다.

## 4. 주 판정과 σ 검사 기준

**단위 = 배치. 한 배치는 주 시드(941)의 연쇄 결과 하나다.**

- **주 통과(PASS_CLEAN 또는 PASS_CONTACT_RECOVERED)**: L0와 L1 둘 다 표준 leg 검사(들어 올림·기울기·집게·leg 길이·끝점 100 mm)를 통과하고 하드 한계를 넘지 않는다. 접촉이 있으면 PASS_CONTACT_RECOVERED(통과로 세되 분리 보고).
- **주 기준 A(성공률)**: 통과 배치 ≥ **48/60**(안 A, 초안 기본값). 이것은 **고정 60곳의 관측 통과율 기준**이지 모집단 통과율 ≥ 80 %의 입증이 아니다(§3.1). 함께 배치 단위 Wilson 95 % 구간을 보고한다(관측이 48/60이면 68.2–88.2 %). 안 B는 통과 ≥ **55/60**(Wilson 하한 81.9 %)으로, 모집단 ≥ 80 %를 주장할 수 있다. 어느 안으로 봉인할지는 조정자의 결정이다("게이트 전 남은 결정" (a)).
- **주 기준 B(σ 과신 없음, 축별)** — leg 끝(L0, L1 각각)의 PF 추정 오차(추정 − 정답)와 자기 공분산으로, **x, y, yaw 각각**:
  - ±2σ 포함 비율 ≥ 90 %(표본 = 통과·비통과 무관하게 leg 끝이 기록된 로봇 표본).
  - 평균 z² ≤ 1.3 (정직하면 ≈ 1, 과신이면 > 1).
  - **배치 단위 보고(구간의 n = 도달한 배치 수)**: 한 배치는 그 축에서 그 배치의 **모든 로봇·시드 표본**이 ±2σ 안에 있을 때만 "포함된 배치"로 센다. Wilson 구간의 n은 그 leg 끝에 **도달한 배치 수**(`n_observed_placements`)이며 전체 60이 아니다. 도달하지 못한 배치는 분모에서 빼고 **"검증되지 않음"**으로 개수와 이름을 함께 적는다(포함 100 %라고만 쓰지 않는다). 예: 탐색 cD L1은 1배치(로봇 2개)만 도달했는데 전체 12배치를 n으로 써서 76–100 %로 나왔던 것을 1/1 [21–100 %]로 바로잡았다(`experiments/2026-09-30-b-v6h-gain/README.md` "검토 반영").
  - 3자유도 NEES는 연속성을 위해 보고하지만 기준이 아니다(보수적인 y·yaw가 x의 과신을 가려서).
  - **기준 B는 과신만 막는 한쪽 검사다.** 포함 100 %와 낮은 평균 z²는 σ가 보정됐다는 증거가 아니다(σ가 아주 크면 저절로 나온다). 그래서 이 기준을 통과하면 "기록된 끝점에서 σ의 과신이 없다"고만 쓰고, "σ가 정직하다/보정됐다"고 쓰지 않는다.
- **진단 C(과보수, 보고만: 관문이 아니다)**: 축별·leg별 평균 z²와 "σ가 실제 오차 RMS의 몇 배인가"(≈ 1/√평균 z²), NEES3 평균을 표로 낸다. 평균 z² < 0.1이면 "매우 보수적", 0.1–0.5 "보수적"으로 표시한다. 탐색 예: cB L1 x 평균 z² 0.0285(σ ≈ 오차의 5.9배), NEES3 평균 0.2684. 이 진단은 **성공 선언에 들어가지 않는다**(관문으로 올릴지는 "게이트 전 남은 결정" (c)). 다만 보고서에는 "과신은 없으나 매우 보수적"이라고 그대로 적는다.
- **성공 선언 = A와 B 둘 다**. A만 통과하고 B가 깨지면 "통과했으나 σ가 과신이다"로 보고하고 성공으로 세지 않는다. 성공 선언의 뜻은 §1의 "통과하면 말할 수 있는 것"으로 제한한다.
- **하드 한계**: 기울기 > 15도 또는 벽 관통 > 0.005 m.
  - **하드 한계는 일반 leg 검사보다 먼저 본다.** 한 leg에 하드 한계 위반과 일반 실패(끝점 오차 등)가 겹치면 FAIL이 아니라 FAIL_HARD_LIMIT이다(PR #288, `chain_analysis.py`의 `leg_class`가 수정되어 병합됨).
  - **검사 범위는 연쇄 전체**다: L0, L1 두 leg의 창만이 아니라 내려놓기·재파지 구간을 포함한 전체 기록(전체 trace의 기울기와 모든 접촉 에피소드의 관통). PR #288이 이 범위의 위반 수를 `hard_limit_chain`/`hard_limit_chain_cases`로 따로 센다. 탐색 9개 코호트 모두 0건(`results/*.txt`의 "hard limit … anywhere in the run" 줄).
  - **위반이 1건이라도 있으면 그 배치는 FAIL_HARD_LIMIT이고, 코호트 전체(보조 시드 포함)에서 1건이라도 있으면 성공을 선언하지 않는다**(A를 넘어도). PR #290 배치 분류기는 leg 창 밖(내려놓기·재파지)의 위반도 반영한다. 봉인 전 정의 확정 및 관련 시험을 확인한다(§5).

## 5. 결과 분류 (각 배치)

| 분류 | 정의 |
|---|---|
| PASS_CLEAN | L0·L1 모두 표준 leg 검사 통과 + 전체 저장 기록의 벽 접촉 0 + 하드 한계 이내 |
| PASS_CONTACT_RECOVERED | 표준 검사 통과 + 전체 저장 기록 어디든 벽 접촉 에피소드 있음 + 하드 한계 이내 |

| FAIL | 그 밖의 실패(끝점 오차, 게이트 정지, 시간 초과 등). 첫 실패 코드(phase/code)를 기록 |
| FAIL_HARD_LIMIT | **먼저 검사한다.** 연쇄 전체(L0·L1 창 + 내려놓기·재파지 구간)에서 하드 한계 위반. BLOCKED/FAIL보다 우선(PR #288) |

PR #288 `chain_analysis.py`의 leg 검사·하드 문턱·접촉 겹침·Wilson 함수를 재사용하며 BLOCKED_BY_CONTACT와 배치 단위 전체 기록 하드 한계 판정을 구현했다. 양성 접촉은 합성 단위 시험으로 확인했고 새 접촉 물리 실행은 하지 않았다. 이 분석기는 **기준 A+안전 거부만** 평가하며 기준 B나 전체 성공 선언을 대신하지 않는다. 접촉·관통·GT는 평가 전용이고 제어기로 전달하지 않는다.

### 5.1 봉인 전에 고정할 정의 (definitions fixed before sealing)

`analysis/CLASSIFY_NOTES.md`의 **11개 모호점 순서**와 같다. 아래는 현재 구현에 맞춘 권장안이며 이번 갱신은 봉인 승인이 아니다. 특히 6·7은 **OPEN QUESTION FOR COORDINATOR**로 남긴다. 독립 검토와 조정자 확정 뒤 문서·분류기·봉인 입력이 같아야 한다.

1. **접촉 창 겹침:** 닫힌 leg 구간과 접촉 에피소드가 조금이라도 겹치면 포함한다(경계 허용오차 1e-9 s). 에피소드 전체가 창 안에 있을 필요는 없다.
2. **중단된 leg 창:** `recorded=false`, 끝 시각 null이면 시작→해당 carry leg의 첫 실패 시각을 쓴다. 없으면 stop 시각→마지막 trace 시각 순으로 대체하고 `window_source`를 남긴다. 시작도 없으면 접촉을 그 leg에 귀속하지 않는다.
3. **접촉 없는 예방 가드 정지:** BLOCKED에는 **실패 AND 실패 carry 창의 실제 벽 접촉 겹침**이 필요하다. COLLISION_GUARD 코드만 있으면 FAIL이다. 접촉과 실패의 동시 기록이지 인과가 입증됐다는 뜻은 아니다.
4. **통과 중 내려놓기·재파지 접촉:** PASS_CLEAN의 접촉 0은 전체 저장 기록을 뜻한다. leg 밖 접촉도 있으면 PASS_CONTACT_RECOVERED이고, 이름의 "복구"가 전용 접촉 복구 제어를 입증하지는 않는다.
5. **leg 밖 실패·접촉:** BLOCKED의 창은 실패한 carry leg로 한정한다. 내려놓기·재파지 창에만 접촉한 실패는 FAIL이다. 어느 창이든 하드 한계 위반은 FAIL_HARD_LIMIT가 먼저다.
6. **내려놓기 일반 검사:** 권장안은 현재 §4대로 L0·L1 표준 검사만 주 통과로 세고 별도 setdown 검사 관문은 추가하지 않는 것이다(전체 기록 하드 한계는 포함). **OPEN QUESTION FOR COORDINATOR:** 연쇄의 "내려놓기 성공" 주장에 일반 setdown 통과까지 요구할지. 추가한다면 성공 정의·분류기·시험을 봉인 전에 함께 바꾸며 현재 구현이 이를 검사한다고 쓰지 않는다.
7. **전체 기록의 시작/끝 경계:** 현재 구현과 PR #288처럼 저장 trace 전부의 기울기·모든 벽 에피소드를 검사한다(L0 전/추가 leg도 포함). **OPEN QUESTION FOR COORDINATOR:** teacher 준비 창까지 거부 기준에 포함할지, 실행 창을 분리할지. 권장안은 증거 누락을 막는 현재 전체 기록 기준이며 경계를 줄이면 별도 기록·검사가 먼저 필요하다.
8. **주 시드와 탐색 strict 분리:** 확증 주 시드는 941, 앞 12곳의 보조 943은 별도 보고하고 통과 분자에 합치지 않는다. 탐색 대조는 911을 명시해 주 시드 통계·케이스 통계·모든 시드 통과(strict)·하나라도 통과를 구분한다.
9. **보조 시드의 안전 거부:** 주 시드 배치 분류는 그대로 두고 `hard_limit_any_seed`를 별도 표시한다. 보조 시드에서도 위반 1건이면 코호트 전체 성공을 선언하지 않는다.
10. **HOST_ERROR·누락:** HOST_ERROR와 주 시드 누락은 미분류로 이름·사유를 보존하며 완료/성공 판정을 막는다. 일반 케이스의 trace·접촉 기록 누락은 오류로 분석을 중단한다. 5개 분류 중 FAIL로 억지 변환하거나 분모에서 빼지 않는다. 같은 배치·시드 1회 재실행 시 원 기록과 연결하고 중복 케이스를 한 판정 입력에 합치지 않는다.
11. **60개 분모와 σ 검사:** ≥48/60은 정확히 60개 주 시드 배치가 모두 분류됐을 때만 적용한다(작은 개발 코호트에 비례 적용하지 않음). 전체 시드 하드 한계 0 및 기준 B를 별도로 확인해야 최종 성공 선언을 한다. 분류기의 A+안전 통과만으로 A+B 성공이라 쓰지 않는다.

## 6. 보고할 부수 분석 (기준 아님)

- 배치별 dx(빔 − 반올림 시트 x)와 L1 앞뒤·끝점 오차의 관계를 보고한다. ON 정책의 사전 모형 예측은 §3.3의 배치별 통과확률(`cohort_sizing.json`)이다. 기존 "dx≤+20 mm는 ≥95 %, dx≥+45 mm는 대부분 실패"는 **OFF 적합(`64+1.09·dx`)의 과거 진단**으로 남기며 ON의 예측으로 쓰지 않는다. 현재 60곳의 dx≤+20 mm 42곳, dx≥+45 mm 2곳은 층별 보고용이며 판정 분모를 바꾸지 않는다.

## 7. 정지 감지는 없다 (fail-open) — 명시

탐색 208건 전부에서 진행 감시 기준선이 세워진 횟수는 **0**이었다(무시한 시도 1176건 전부 `move_t0=None`, 구간 시작 직후 한 번씩만 시험). 이동 명령이 나간 뒤에는 든 쌍에 신선한 위치 측정(나이 ≤ 0.3 s, σ_xy ≤ 하한)이 다시 들어오지 않는다. 그러므로:

- **든 쌍(문 구역만이 아니라 든 구간 전체)에는 정지 감지가 사실상 없다.** 이 코호트에서 로봇이 물리적으로 갇혀 있어도 진행 감시가 멈추지 않는다.
- 통과는 "정지 감시가 안전을 보장해서"가 아니라 "가로막히지 않고 도착해서"다. 정지 감지가 필요한 실제 상황(끼임, 바퀴 미끄러짐)은 이 코호트로 검증되지 않았다.
- 코호트는 무장 횟수를 기록해 보고한다(`progress_relax_p2f.armed`). 확증에서 무장이 1건이라도 나오면 그 케이스의 정지 규칙 동작을 별도로 검토한다. 이 fail-open은 성공 기준의 일부로 승인된 것이 아니라 **수용된 알려진 한계**이며(조정자·사용자 수용, 독립 검토 지적 1), 정지 감지를 복원하는 후속 작업은 이 사전 등록 밖이다.

**위험:** loaded 상태에서 믿을 만한 정지 감지(no reliable stall detection)는 아직 없다(p2f **0/208**). 손목 영상의 밝기 차이를 쓰는 D1 검출기는 **PR #291의 별도 탐색 연구 제안**이며 `b-v6h1`의 다섯 플래그나 확증 판정에 포함하지 않는다. b-v6h1 통과를 **안전한 끼임/정지 대응(safe stall handling)**으로 보고하지 않는다. D1의 사후 선택·렌더 조명 의존성·새 막힘 조건 검증은 별도 사전 등록의 문제다.

## 8. 운영·보존·TensorBoard

- 실행: `agent_lock`을 잡고(코호트마다 driver PID) SIM 시간, `--render-profile floor_light_v1`, `--workers 4 --omp-threads 1`, 모델 호출 0, weld OFF. 시작·종료 부하 평균 기록. 소스 SHA 고정, `source_changed=False` 확인. 여유 디스크 ≥ 10 GiB(케이스당 약 28 MB로 60+12건 ≈ 2.0 GB 예상). ENOSPC는 HOST_ERROR로 분류하고 성공/실패에 넣지 않는다.
- raw는 기본 체크아웃 `outputs/`에 절대 경로로, `cases.jsonl` sha256을 실험 README에 기록. `experiments/`에는 분석 결과(JSON/TXT)만.
- 케이스 결과는 실패 포함 전부 보고. 중단·호스트 오류 케이스는 별도 표에 사유와 함께 적고 분모에서 조용히 빼지 않는다(재실행은 같은 배치·시드로 1회, 원 실행 기록 보존).
- TensorBoard: 코호트 종료 뒤 `analysis/build_tb_views.py`(탐색 실험 것)로 파생 뷰를 만들고 `scripts/export_offline_audit.py`로 새 스냅샷(`outputs/tensorboard/<날짜>-b-v6h-confirm`)에 변환, 이벤트를 다시 읽어 통과 수를 분석과 대조, 브라우저에서 고정 카드와 HParams 열을 확인한 뒤 `outputs/tensorboard-view.json`에 자기 키만 추가(쓰기 직전 다시 읽음). 고정 카드: `offline/pass`, `offline/pass_rate`, `result/sim_s`, `result/commands`, `result/model_calls`. 비교 기준으로 탐색 스냅샷 `0930-b-v6h-gain`의 집계를 함께 보이되 코호트는 구분해 표시한다.
