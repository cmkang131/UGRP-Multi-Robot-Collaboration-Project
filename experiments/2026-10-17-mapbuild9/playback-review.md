# mapbuild9 직접 검토

새 렌더·물리는0이다. mapbuild8이 gcp5 ffmpeg으로 만든 기존 자기 카메라
몽타주를 Mac 파일 읽기로 직접 확인했다. 화면 앱/브라우저 실행0.

- R1 자기r1: 0–27.5SIM초2Hz의3장 띠(0/100/200)를 전부 봤다.
  처음 pan에서 벽발이 보이고, 약8–15초는 바닥만 보이다가 16초 이후 벽이
  다시 들어온다. 준비 회전/머리 pan만 있고 집기·운반은 보이지 않는다.
- R3 자기r1: 0–38.5SIM초2Hz의4장 띠(0/100/200/300) 전부, 마지막
  28.8–38.8SIM초10Hz의6장 띠(288/308/328/348/368/388)101프레임 전부.
  6.5초부터 벽/동료/화물/문이 차례로 지나가고, 약17–24초는 긴 벽면,
  25–28초는 모서리가 옆으로 이동한다. 28.8–32.9초에는 같은 방향의
  연속 회전, 33.1초부터 머리 pan으로 벽 높이·화물 위치가 이동한다.
  거짓 수렴35.2초에는 카메라 pan으로 청록 화물이 화면에 들어오는 중이다.
  이 RGB만으로 전역 위치 정답이나 물리 파지 성공을 판단하지 않았다.
- 듬성한6장과 달리10Hz에서 회전→pan 전환과35초 부근 관측 변경을 확인했다.
  이 범위에 빠른 좌우 왕복·두 로봇이 같은 물건 끝을 잡는 동작은 없다.
- 원본 영상은 기존 gcp5 `review-r1/review-3x.mp4`, `review-r3/review-3x.mp4`.
  R3 ffprobe:389프레임/12.966667초/109151B. 기존3배속 합성 영상이며 Mac
  기존 파일 SHA와 remote SHA를 별도 검증한다. 새로 동영상 앱으로 재생하지 않았다.
- 성공1개 비교: 이 자료에는 native 성공 운반 영상이 없어 **미충족**.
  기존 교사 성공 기록이나 열린 집게418뷰를 성공 운반 영상으로 바꾸어 쓰지 않는다.
