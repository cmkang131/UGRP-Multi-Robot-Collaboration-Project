## 1. 먼저 사용할 수 있는 값과 신뢰도

공식 수치(`official spec`)와 도면에서 잰 값(`official drawing scaled`)은 다르다. 아래 소수점은 계산 재현용이며 0.1 mm 실물 정밀도를 뜻하지 않는다. 도면은 수평·수직 기준에 약 1% 차이가 있고, 선 두께/축 중심 판독 오차가 있다. 대략 ±2 mm는 **판독 범위**일 뿐 제조 공차나 통계적 신뢰구간이 아니다. 서보/카메라 생산 revision와 조립 편차는 포함하지 않는다.

신뢰도: **높음** = 공식 인쇄값 또는 고정 SHA 소스의 직접 확인, **중간** = 축척/형상 대조를 통한 명목 후보, **낮음** = 버전·기준점·조립 상태가 모호함, **미확인** = `not found`, JSON `null`. 높음도 해당 로봇 개체에 대한 보증이 아니다.

좌표: 앞뒤 차축 중심의 중점과 좌우 바퀴 중심의 중점을 평면 원점으로 삼는다. x 전방+, y 좌측+, z는 바닥부터 위+. SDK의 x=횡방향/y=전방 팔 좌표는 이 좌표와 다르다. 공구축 `along`은 ID3 손목 축에서 집게 끝 방향, `up`은 공구축에서 카메라가 달린 쪽이다.

`Sonar.getDistance()`는 I2C 버스1을 열고 `[0]`으로 읽을 레지스터를 지정한 다음 2바이트를 little-endian unsigned로 해석한다. 하한 검사는 없으므로 raw=0/1/19도 그대로 돌아온다. raw가5000보다 크면5000으로 제한하며, try 구간의 예외는 초기값99999를 유지한다. `Distance` 속성 접근도 같은 함수를 부른다. `mm`/`cm` 열거값이 있어도 `getDistance()`에는 단위 선택 인자가 없고 변환하지 않는다. `avoidance.py`가10으로 나누어 cm로 표시한다. ([S1/S5])

소스에 읽기마다 새 측정을 시작한다는 명령/완료 대기/샘플 timestamp가 없다. 레지스터0 쓰기를 ping trigger라고 단정할 수 없다. 공식 예제 `sleep(0.1)`은 호스트 폴링 대기일 뿐이다. [U1] 본문은8개의40 kHz 펄스를 설명하지만 표는40 Hz라 내부적으로 상충한다. **40 Hz=25 ms 갱신**이라는 해석도, HC-SR04 관행의60 ms를 MasterPi 사양으로 쓰는 것도 근거가 없다.

**#248 권고:** 반각은 JSON에서 `null`로 둔다. 후보 비교가 필요하면 반각7.5°(전체각15° 가정)와15°(반각15° 가정)를 별도 가정으로 명시한다. 무반사/오류를 전방이 비었다는 판정으로 바꾸지 않는다. 설치 SDK의 파일 해시·오류 반환 계약이 확인되기 전까지 99999만으로 모든 버전을 설명하지 않는다. 잡음 σ, 누락률, 간섭률, 입사각 감도는 공개값이 없어 기존 가정을 검증된 사양으로 승격하지 않는다.

     [0, 1285.5144320144632, 116.0909553740869],
     [0, 0, 1]]

이는 **공개 샘플 보정값**이다. 카메라 일련번호·렌즈 revision·보정 날짜·RMS·holdout 오차가 없고 NPZ에 해상도 필드도 없다. 모델이 일반5계수이므로 현재 `CAMERA_FISHEYE_D`4계수에 복사하지 않는다. `public_reference_intrinsics`에 별도 저장하고, 템플릿의 실제 카메라 `intrinsics` 값은 `null`로 남겼다. 170°로 pinhole 초점거리를 역산하거나 이 K로 제조 FOV를 검증했다고 하지 않는다.

현재 [I4]는 **ugrp1 icspring fisheye** 프로필이며 fx/fy 약619.519/622.165, cx/cy287.689/218.697이다. 렌즈 위치67/13.6 mm와 하향각은 기존 촬영 적합/구조적 후보이고, held-out hand-eye로 검증된 순정 배치가 아니다. 공개 순정 카메라의53/28 mm·170°로 이 프로필을 덮어쓰지 않는다. 집게가 보이도록 카메라 배치를 바꾸는 작업도 하지 않았다.

## 3. 자료가 충돌할 때의 우선순위

1. 공식 SDK 실행 상수는 그 SDK의 행동 계약을 설명한다. 치수도·실물 치수와 같다고 간주하지 않는다. 복사된 주석과 실행값이 다르면 실행값을 기록한다.
2. 특정 MasterPi의 도면 라벨(휠30 mm)을 별매 부품 일반표(31 mm)보다 모델 명목값에 우선한다. 다른 revision 가능성을 닫지 않는다.
3. 초음파15°·40 Hz, 카메라170°·120°, 서보모델/외형처럼 의미·세대가 모호한 숫자를 평균하지 않는다. 정의 불명은 `null`, 다른 값은 `alternatives`에 남긴다.
4. 공개 MJCF [R3]는 같은 도면/SDK를 사용한다. FK 0 mm라는 작성자의 주장은 SDK와 모델 일치이지 로봇 실측이 아니다. 두 독립 초음파 ray를 실제 하드웨어 채널로 채택하지 않는다. 공개 STEP은 발견하지 못했다. [R3]의 “주문번호로 제조사 요청 가능”은 그 작성자의 주장으로만 기록했고 제조사에 연락하지 않았다.
5. [R4] ROS2 프로젝트와 [R5/R6] 논문·포스터를 확인했지만 필요한 축 위치/빔 패턴의 독립 실측표는 찾지 못했다. [R5]의 motion-capture 제어는 우리 로봇 입력/성공 판정의 근거로 가져오지 않았다.

## 4. 인터넷으로 끝내지 못한 것과 후속 선택

**지금 사용자에게 수작업 측정을 요구하지 않는다.** 아래는 이후 개체별 sim2real을 검증하려 할 때 실제 증거가 필요한 항목이다. 우선 제조사의 revision별 치수 CAD/도면·관절 BOM·초음파 펌웨어 명세로 대체할 수 있는 항목과, 실제 장착/센서 데이터가 필요한 항목을 나눈다.

| 남은 항목 | 공개 조사 한계 | 이후 필요한 증거 |
|---|---|---|
| 상완65 대58, 닫힌 끝100 대94, bare 차대 전장 | 공식 상수와 비치수 축척 불일치 | 정확한 revision CAD/축간 치수표; 없으면 해당 로봇 축간 거리/집게 상태 확인 |
| 실제 sonar/camera 장착 변환, yaw/shoulder 편차 | 도면은 명목 배치만 설명 | 장착 도면+개체 일치 증거 또는 태그 없는 자/체커보드/영상 보정 |
| 초음파15° 정의 | 표에 half/full와 강도 기준 없음 | 제조사 빔 감도 곡선 또는 거리·표면별 검출각 시험 |
| 갱신·최소거리/무반사 반환·간섭 | SDK만으로 펌웨어 상태를 알 수 없음 | firmware 계약/버전 확인 또는 실제 I2C 판독 시계열 |
| 개별 camera intrinsics/extrinsics | 공개 NPZ는 다른 모델/개체일 수 있음 | 실제 카메라 모델 확인과 체커보드 fit/holdout, 손목 자세별 검증 |
| 서보 모델별 연속 토크/반복성, 휠 미끄럼·유효 지름, 질량/COM | 상품표와 실제 하중/바닥 조건 다름 | 개체별 부품 식별과 실물 시험; 시뮬레이션 통과로 대체 불가 |

인터넷 명목값을 선택해도 PHYSICAL 준비 승인, 실제 통과/도착/파지 성공, 하중 성능 증명이 되지 않는다. 이 기록은 정적 참고 자료이며 로봇 제어·단계 전환·성공 통보에 실시간 정답을 주지 않는다. 최종 환경은 태그0개 전제를 유지한다.

## 5. JSON 사용 규칙·검증 범위

`schema=ugrp.masterpi_public_specs.v1`이고 `ugrp.real_measurements.v1`로 가장하지 않는다. `measurement_source`, `hardware_unit`, `measured_by`, `measured_at`은 `null`, `deployment_allowed=false`다. 템플릿의 정적 항목/초음파spec/카메라intrinsics 경로를 유지했지만 값이 `{value, unit, source, source_type, confidence, derivation}` 객체이므로 런타임 설정 파일로 직접 로딩하지 않는다. `static_geometry.upper_arm_mm.value`는 도면 판독이며 권고 SDK값65는 `alternatives`/`recommendation`에 명시했다. 자동 평균/교체는 금지한다.

검증 명령·결과와 Git 제약은 [WORK_LOG.md](WORK_LOG.md)에 기록한다. 물리 실행 없는 기존 `tests/test_real_geometry.py`만 실행하며, 별도로 JSON 파싱·템플릿 키 포함·출처 ID/URL·축척 계산·이미지 해시를 검사한다. 신규 실험/학습/평가 지표가 없어 TensorBoard 스냅샷이나 viewer를 만들지 않았다. Google Drive는 조회·다운로드·업로드하지 않았다.
