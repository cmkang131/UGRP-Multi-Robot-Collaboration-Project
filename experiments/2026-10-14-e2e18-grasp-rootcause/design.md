# 교사와 학생의 경계

사용자 결정: “llm이 판단할 때에는 위치를 모르게, 코드는 위치를 알게 해서 교사 그걸 만들고 ACT를 만들어”, “정답을 안다는 말은, 모든 위치를 다 아는 느낌으로다가”.

판단 LLM(Gemma v405 기본)은 자기 RGB·정적 지도·자기 명령 이력·통신 조건에 맞는 받은 메시지만 본다. 끝 배정, 접근, 집기, 대기, 다시 잡기, 운반·내려놓기를 스킬로 지시한다. 위치 정답·교사 상태·접촉 성공 판정은 전달하지 않는다. 이번 첫 교사 검증은 고정 스킬 지시를 쓰며 실제 LLM 호출·통신 효과 검증으로 보고하지 않는다.

시연 전용 실행기는 모든 로봇·봉·짐·장애물의 위치와 관절·접촉을 알고, 기존 표준 Scene·v7 물리·v3 명령 IK·교사 경로 계산을 재사용한다. 교사는 명령만 발행한다. 초기 상태 설정 후 위치를 덮어쓰거나 물체를 붙이지 않는다. 정답 기반 역할 배정과 LLM/대체 규칙 배정은 데이터에 별도 표시한다.

학생 입력은 현재/이전 자기 RGB, 자기 발행 명령 이력, 팬의 발행 목표와 경과 시간, 상위 계층이 지시한 스킬·끝 역할이다. 팬의 실제 측정 관절은 입력하지 않는다. 스킬 지시는 작업 명세이며 정답 위치를 포함하지 않는다. 학생 입력 파일, 교사 행동/종료 표적, 평가 정답 파일을 나눈다. 학습 loader와 배포 adapter는 입력 허용 목록을 검사한다.

## 재사용과 달라지는 점

- `harness/reference_act.py`의 고정 LeRobot `ACTPolicy`와 체크포인트 검증을 재사용한다. 원 구현의 측정 관절은 자기 발행 명령 벡터로 대체하고, top RGB는 제거한다. 현재·과거 자기 RGB는 별도 시점 입력이다. 기존 고정 모델은 수정하지 않고 새 adapter로 구분한다.
- `scripts/cargo_formation_teacher.py`, `scripts/zone_teacher.py`의 정답 교사·경로·팔 명령 방식을 재사용하되 v2 팔 중심 가정은 v3 IK와 실제 Scene 규약으로 교체한다. 기존 지각 가드·기억 어댑터는 교사/학생 실행 경로에 덧붙이지 않는다. 이전 번들은 재현을 위해 유지한다.
- 9/24 모델은 학습 9개·개발 4개에서 종료 누락이 있었고 첫 ACT 물리 비교는 0/2였다. 후속 종료 가중 손실·조기 종료 문제도 읽고 반영한다. 새 표적은 스킬별 완료 시점과 실패/중단을 분리한다. timeout은 성공 종료 표적이 아니다. 배포와 같은 zero-latent 첫 행동의 조기 종료·종료 누락을 모델 선택에 사용한다.
- 같은 에피소드의 두 로봇·복구·영상 이력·행동 청크는 같은 split에 둔다. 미래 청크가 스킬 경계·에피소드 끝을 넘지 않게 마스킹한다. 평가 시작 상태로 정규화나 종료 임계값을 고르지 않는다.

## 고정할 첫 검증

1. 감사로 파지 허용 오차와 실제 오차를 비교한다. 과거 결과는 새로운 교사 성공에 합산하지 않는다.
2. 단일 로봇 접근→정렬→한쪽 파지부터 무작위 시작 상태 20개 이상. 봉은 길고 무거워 단일 로봇의 한쪽 파지와 전체 봉 상승은 별도 기준이다. 성공 목표는 ≥95%; 표본 n/N과 신뢰구간을 함께 기록한다. 무작위 분포·seed·시한·성공 조건은 실행 전에 JSON으로 고정한다.
3. 두 로봇 양 끝 공동 파지, 다음으로 짧은 운반과 내려놓기를 검증한다. 각 단계별 성공률·첫 시도·시간·위치/방향 오차와 실패 원인을 기록한다. teacher gate가 실패하면 대량 수집을 시작하지 않는다.
4. 교사 통과 후 첫 데이터 규모를 정한다(500은 예시이며 아직 제출하지 않음). DART는 학습/개발 오차로 주입 잡음을 정하고, 잡음이 들어간 행동으로 도착한 상태의 깨끗한 교사 표적을 저장한다. 고정 임의 잡음만 쓰면 DART-inspired로 표시한다. 불가능/위험 상태와 복구 실패도 원장에 남긴다.
5. CPU의 작은 실제 forward/backward/저장·재로딩으로 배관을 검증한다. GPU 사용 결정은 조정자를 기다린다. 학습 손실, 고정 데이터 재생, 학생의 새 시작 상태 성공은 서로 다른 결과다.
6. DAgger는 학생이 실행해 방문한 상태에서 교사 라벨을 추가한다. 이 수집 실행은 teacher-assisted로 표시하고 학생 독립 평가 분모에서 제외한다. 그 뒤 새 holdout으로 보정 없는 학생을 다시 평가한다.

## 실행·보존

VM3 한 대·16동시·첫 30 SIM초 속도 게이트(중앙 wall/SIM≤3.5), 저장 예산 검사 후 시작한다. 현재는 VM 사용 허가 대기다. 원본은 VM 영속 디스크→ARM 전체 해시 검증, Mac은 필요한 가벼운 기록만 회수한다. 본 작업 종료 시 자기 실행·자식을 정리하고 보관 및 VM3 deallocated를 확인한다. 다른 작업은 멈추지 않는다.

완료·선택한 모델과 결과 재현에 필요한 비교 모델은 `configs/model_artifacts.json` 및 버전별 GitHub Release에 보존하고 재다운로드·전체 해시·모델 로딩을 확인한다. 아직 새 모델은 없다. 단위 검사 통과로 물리 성공을 대신하지 않는다.

예상 공수(실측 전 계획): 입력/데이터/ACT 연결 1–2일, 교사 물리 검증과 수정 1–3일, 수집·학습·학생/DAgger 평가 1–3일. 교사의 물리 한계와 GPU 결정에 따라 달라진다.
