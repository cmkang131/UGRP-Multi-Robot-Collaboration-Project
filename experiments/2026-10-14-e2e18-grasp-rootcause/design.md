# 교사와 학생의 경계

사용자 결정: “llm이 판단할 때에는 위치를 모르게, 코드는 위치를 알게 해서 교사 그걸 만들고 ACT를 만들어”, “정답을 안다는 말은, 모든 위치를 다 아는 느낌으로다가”.

판단 LLM(Gemma v405 기본)은 자기 RGB·정적 지도·자기 명령 이력·통신 조건에 맞는 받은 메시지만 본다. 끝 배정, 접근, 집기, 대기, 다시 잡기, 운반·내려놓기를 스킬로 지시한다. 위치 정답·교사 상태·접촉 성공 판정은 전달하지 않는다. 이번 첫 교사 검증은 고정 스킬 지시를 쓰며 실제 LLM 호출·통신 효과 검증으로 보고하지 않는다.

시연 전용 실행기는 모든 로봇·봉·짐·장애물의 위치와 관절·접촉을 알고, 기존 표준 Scene·v7 물리·v3 명령 IK·교사 경로 계산을 재사용한다. 교사는 명령만 발행한다. 초기 상태 설정 후 위치를 덮어쓰거나 물체를 붙이지 않는다. 정답 기반 역할 배정과 LLM/대체 규칙 배정은 데이터에 별도 표시한다.

학생 입력은 현재/이전 자기 RGB, 자기 발행 명령 이력, 팬의 발행 목표와 경과 시간, 상위 계층이 지시한 스킬·끝 역할이다. 팬의 실제 측정 관절은 입력하지 않는다. 스킬 지시는 작업 명세이며 정답 위치를 포함하지 않는다. 학생 입력 파일, 교사 행동/종료 표적, 평가 정답 파일을 나눈다. 학습 loader와 배포 adapter는 입력 허용 목록을 검사한다.

## 재사용과 달라지는 점

- `harness/reference_act.py`의 고정 LeRobot `ACTPolicy`와 체크포인트 검증을 재사용한다. 원 구현의 측정 관절은 자기 발행 명령 벡터로 대체하고, top RGB는 제거한다. 현재·과거 자기 RGB는 별도 시점 입력이다. 기존 고정 모델은 수정하지 않고 새 adapter로 구분한다.
- `scripts/cargo_formation_teacher.py`, `scripts/zone_teacher.py`의 정답 교사·경로·팔 명령 방식을 재사용하되 v2 팔 중심 가정은 v3 IK와 실제 Scene 규약으로 교체한다. 기존 지각 가드·기억 어댑터는 교사/학생 실행 경로에 덧붙이지 않는다. 이전 번들은 재현을 위해 유지한다.
- 9/24 모델은 학습 9개·개발 4개에서 종료 누락이 있었고 첫 ACT 물리 비교는 0/2였다. 후속 종료 가중 손실·조기 종료 문제도 읽고 반영한다. 새 표적은 스킬별 완료 시점과 실패/중단을 분리한다. timeout은 성공 종료 표적이 아니다. 배포와 같은 zero-latent 첫 행동의 조기 종료·종료 누락을 모델 선택에 사용한다.
- 같은 에피소드의 두 로봇·복구·영상 이력·행동 청크는 같은 split에 둔다. 미래 청크가 스킬 경계·에피소드 끝을 넘지 않게 마스킹한다. 평가 시작 상태로 정규화나 종료 임계값을 고르지 않는다.

## 고정할 첫 검증

1. 감사로 파지 허용 오차와 실제 오차를 비교한다. 과거 결과는 새로운 교사 성공에 합산하지 않는다.
2. 단일 로봇 접근→정렬→한쪽 파지부터 무작위 시작 상태 40개 이상. 봉은 길고 무거워 단일 로봇의 한쪽 파지와 전체 봉 상승은 별도 기준이다. 성공 목표는 ≥95%; 표본 n/N과 신뢰구간을 함께 기록한다. 무작위 분포·seed·시한·성공 조건은 실행 전에 JSON으로 고정한다.
3. 두 로봇 양 끝 공동 파지, 다음으로 짧은 운반과 내려놓기를 검증한다. 각 단계별 성공률·첫 시도·시간·위치/방향 오차와 실패 원인을 기록한다. teacher gate가 실패하면 대량 수집을 시작하지 않는다.
4. 교사 통과 후 첫 데이터 규모를 정한다(500은 예시이며 아직 제출하지 않음). DART는 학습/개발 오차로 주입 잡음을 정하고, 잡음이 들어간 행동으로 도착한 상태의 깨끗한 교사 표적을 저장한다. 고정 임의 잡음만 쓰면 DART-inspired로 표시한다. 불가능/위험 상태와 복구 실패도 원장에 남긴다.
5. CPU의 작은 실제 forward/backward/저장·재로딩으로 배관을 검증한다. Kaggle 비공개 데이터/GPU 학습은 사용자 승인됐으며 유한 실행 예산을 지킨다. 학습 손실, 고정 데이터 재생, 학생의 새 시작 상태 성공은 서로 다른 결과다.
6. DAgger는 학생이 실행해 방문한 상태에서 교사 라벨을 추가한다. 이 수집 실행은 teacher-assisted로 표시하고 학생 독립 평가 분모에서 제외한다. 그 뒤 새 holdout으로 보정 없는 학생을 다시 평가한다.

## 실행·보존

VM3 한 대·16동시·첫 30 SIM초 속도 게이트(중앙 wall/SIM≤3.5), 저장 예산 검사 후 시작한다. VM3 사용은 11:38 허가됐으며 실행마다 소유 작업과 유휴 상태를 확인한다. 원본은 VM 영속 디스크→ARM 전체 해시 검증, Mac은 필요한 가벼운 기록만 회수한다. 본 작업 종료 시 자기 실행·자식을 정리하고 보관 및 VM3 deallocated를 확인한다. 다른 작업은 멈추지 않는다.

완료·선택한 모델과 결과 재현에 필요한 비교 모델은 `configs/model_artifacts.json` 및 버전별 GitHub Release에 보존하고 재다운로드·전체 해시·모델 로딩을 확인한다. 아직 새 모델은 없다. 단위 검사 통과로 물리 성공을 대신하지 않는다.

예상 공수(실측 전 계획): 입력/데이터/ACT 연결 1–2일, 교사 물리 검증과 수정 1–3일, 수집·학습·학생/DAgger 평가 1–3일. 교사의 물리 한계와 GPU 결정에 따라 달라진다.

## 확정 구성으로 변경 (2026-10-14 후속 사용자 결정)

위의 운반 ACT 확대 계획은 이번 후속 결정으로 대체한다. **주행·운반 경로는 현행 지도 코드, 근거리 접근·정렬·집기는 ACT, 무엇/어디/끝/대기/재파지는 Gemma v405**다. 공개 스킬은 `grasp_end`, `regrasp`, `release`, `wait`이고 `stop`은 즉시 중단한다. 끝은 `teal|blue`로 지정한다. ACT는 스킬 4개+끝 2개의 one-hot과 자기 명령 이력만 조건으로 받으며 자유 문장이나 지도상 정답 위치는 받지 않는다.

스킬 시작은 지도 주행 도착 + 1초 이내 자기 RGB 추정에서 끝까지 거리 ≤0.8m로 정한다. 0.5–2.0m/화면 밖 시작은 전체 배치 다양성에 포함하되 이 인계 전 구간은 지도·탐색 코드다. 시연 교사의 정답 주행과 학생 지도 주행을 구분하여 기록하고 인계 자체 n/N도 보고한다. ACT 청크는 8행동×0.1초=0.8 SIM초. wait/stop/안전 정지는 대기 청크를 폐기한다. 끝 재배정 때도 이전 청크를 폐기한다.

ACT done≥0.65만으로 완료라고 하지 않는다. 별도 자기 영상 검사에서 연속 3회 완료 확인이 있어야 판단 LLM에 완료 추정을 돌려준다. 검사가 미학습/미검증이거나 가려지면 모름이다. 시한 90초(최대120초)는 실패로 구분하고 성공 종료 라벨을 만들지 않는다. 별도 영상 검사 구현·정확도 검증은 아직 남아 있다.

데이터 축: 봉의 집기 구역 내 x/y와 0–360° 방향, 내 로봇의 중심 거리 0.5–2m·축 방위 0–360°·봉을 향한 방향에서 ±60°·팬 전 범위, 끝 50:50, 짝 없음/반대 끝/다가옴/내 끝 부근, 정적 지도 여러 개(하나는 held-out). 겹침·벽 내부처럼 시작 자체가 불가능한 표본은 거부 수와 사유를 남긴다. 벽 부근과 가림은 제거하지 않는다. 카메라/FOV/외관/물리/접촉/floor_light_v1은 고정하며, 끝 도색만 기존 사용자 허용 청록/파랑 토글을 쓴다. 검정 장면 결과와 합산하지 않는다.

규모: 교사 ≥95% 통과 뒤 첫 50개에서 SIM초·wall/SIM·16동시 생성속도·용량을 잰다. 동일한 개발 시작 상태 묶음으로 중첩 100/200/400 학습 곡선을 비교한다. 개발 묶음은 크기 선택에 쓰므로 최종 확증 holdout과 분리한다. 2회 연속 두 배 확대에서 성공 증가가 5%p 미만이면 더 큰 균일 수집을 멈추는 기준을 우선 고정하되 n/N과 불확실성도 제시한다. 최종 새 시작 상태와 held-out 지도 결과는 모델 선택 후 한 번 평가한다. DAgger는 실패 상태를 추가하며 독립 평가와 분리한다.

Kaggle 사용과 **비공개 데이터 업로드는 사용자 승인됨**. 2026-10-14 CLI 잔여 GPU 30.00h 확인(갱신 10/17 00:00). Mac에서 학습 해상도로 줄인 입력/라벨만 업로드하고 서버 private를 확인한다. 인터넷 OFF, 유한 9시간 이내 세션, 체크포인트 재개를 준비한다. Azure GPU 계열 28/28 할당량0이며 증가 요청·생성·크기 변경은 하지 않는다.

## 최종 멀티태스크 범위 (위 beam-only 조건 번호표 대체)

ACT 하나를 사용한다. `grasp|wait|regrasp|release` + 화물 종류9개(`cyan, green, red, yellow, can, tile, long_beam, heavy_crate, tri_frame`) + 자리8개(`teal, blue, west, east, any, v0, v1, v2`) one-hot이다. 유효한 물건–자리 조합만 허용한다. 3대 모두 같은 가중치를 쓴다. 주행/운반은 지도 코드, 호출 순서·물건/로봇/목적지 선택은 Gemma가 맡고 여러 물건마다 ACT 스킬을 다시 부른다. 다른 학생 모델을 병행하지 않는다.

교사와 수집은 long_beam 2대 → 1대 화물 집기·놓기 → heavy_crate 2대 → tri_frame 3대 순서다. 각각 ≥95%, 최소40회 교사 검증을 거쳐야 수집한다. 첫 plan은 실제 s1/s3/s6의 다른 화물이 있는 장면이다. 이미 옮긴 물건·일하는 로봇·다양한 목적 구역 release 상태는 다음 수집 단계이며 아직 구현/실행하지 않았다. 종류별 명령 자리 따르기·집기/놓기·종료 정확도를 따로 보고하고 최종 짧은 반복2–3물건에서는 호출별 n/N을 추가한다.

파일 대응: `configs/zone_study_scenarios_v3`는 구 v2 물리/지도, `configs/zone_study_scenarios_v4`는 같은 s1–s8 주문·배치를 현재 v3 하드웨어로 옮긴 대응본이다. 현재 카메라·외관·물리를 유지하려고 v4를 사용한다. 이 설정은 예전 v3 연구 코호트와 합산하지 않는다.

실제 확인 범위: ACT CPU forward/backward와 체크포인트 재로딩 통과. 물리 교사/데이터/학습 곡선/독립 학생 성능은 아직 미측정. 최신 VLA 비교 수치와 ACT 논문의 작업별 성공률은 조정자가 전달한 선택 근거이며 이번 작업에서 독립 재확인하지 않아 성능 근거로 재인용하지 않는다.

## 11:38 후속 결정: 지도와 전체 궤적

학습 배경은 연구 지도의 반복이 아니라 절차 생성 지도다. 벽/문 위치와 폭, 집기/목적 영역, 방해 화물을 바꾸고 렌더·카메라·외관·물리는 고정한다. 각 지도 파일/sha256, 지도당 시연 수, 지도 수별 개발 성공률을 기록한다. s1–s8 연구 지도는 평가에 두며 하나는 모델/데이터 선택에 전혀 쓰지 않는다. 현재 교사 게이트40개는 학습 데이터가 아니다.

교사 전체 실행에서 자기 RGB·자기 발행 명령·깨끗한 교사 행동과 구간 라벨(주행/접근/집기/운반/놓기)을 남긴다. 현재 ACT 학습 필터는 근거리 집기/놓기다. 지도 코드 운반의 실패가 실제 확인되면 같은 원본의 운반 구간으로 확장할 수 있다. 첫 교사의 기존 구현은 접근/집기까지만 있으므로 전체 운반/놓기 완료로 주장하지 않는다. 이전 9/26 교사5/8은 별도 이력이며 이번 성공률에 합치지 않는다.

## 12:20 수정: 검증된 연속 교사 재사용

`zone_teacher.proportional_drive`는 기존 `_drive_to`의 대각선 비례 속도 계산을 그대로 추출했다. 기존 실행기의 출력은 같다. 새 교사는 이 계산, 기존 A*, ArmSequence와 현재 v3 pad IK를 사용한다. 고정 단축 펄스, 4 mm 차체 정렬, 불필요한 0.5 m 후퇴는 퇴역한다. 3 cm 도착+IK 도달 가능 확인 후 팔이 잔여 오차를 흡수한다. yaw는 0.06 rad로 두고 실제 파지로 검증한다.

예전 교사는 차체 힘 기반 구동이었지만 현행 v7은 native wheel PWM과 정지 마찰 relay다. 같은 작은 수를 그대로 보내면 출발하지 않는다. 연속 명령 변환(legacy forward/left×3, yaw×0.65)은 초기 후보이며 검증된 실물 보정이 아니다. 공통 ACT 포트는 자기 발행 명령 부호만으로 출발 0.35, 주행 시 마찰항 1/12을 보상한다. 교사/학생 모두 같은 포트를 사용하며 실제 wheel 명령도 별도 원장에 남긴다. 물리·접촉·카메라 배치/FOV는 변경하지 않는다.

입력 schema v3: 연속 forward/left/yaw(혼합 wheel 범위 ±1), 150 ms 갱신 lease, 서보 PWM 5개, done. 10 Hz·8행동 유지. 측정 모드는 학생 RGB/학생 JSON을 만들지 않고 top 검토 영상 320×240 1 Hz와 명령/평가를 남긴다. 40회 중 38회 이상 통과한 뒤 별도 학습 기록(자기 RGB 640×480 10 Hz, 학생 실행 동일 규약)을 켠다. 검토 영상과 중단 배치는 학습 입력으로 승인하지 않는다.

근거리 전체 <0.3 m 오차는 조정자 재집계 중앙 10.7 mm/p95 254 mm다. fine 단계의 좁은 부분집합 값으로 대체하지 않는다. ACT 실패 시 수작업 파지 fallback은 금지한다. LLM 연속 연결 실패 3회 또는 30 SIM초는 HOST_ERROR 정지하며 실제 LLM 통합은 아직 미구현이다.
