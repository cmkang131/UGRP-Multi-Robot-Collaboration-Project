# Coordinator handoff — 실행하지 않은 후속 계획

Refs #216, #221, #293, #298 READINESS S09. **이번 작업의 실제 SIM 비용 0초, 물리·렌더·학습·모델 호출 0**.
P08은 봉인·기본값 활성화·병합을 하지 않는다. 아래는 코디네이터의 별도 물리 작업과 독립 검토에 넘길 항목이다.

1. **인터페이스 승인부터:** #293 `d86cc82`는 offline `detect()`이며 live binding이 승인되지 않았다.
   명령 분할·자기 frame 생산자·check provenance·잘못된 시각/짧은 명령의 분모 ledger를 확정한다.
   P08 fake prototype을 실제 controller에 import하는 것으로 이 결정을 대신하지 않는다.
2. **최종 바닥/로봇 조합:** P01/P02의 최종 map/walls_v3, 표식 0, 밝은 바닥 재질/조명,
   MasterPi v3 geometry·관절/접촉/카메라/FOV와 실제 로봇 배치를 manifest에서 명명하고 해시로 연결한다.
   현재 조합의 승인/해시가 미확정이므로 P08은 임의의 최종 조합을 만들거나 종전 dark-floor 결과를 승계하지 않는다.
   개발 바닥 및 #293의 세 조명 조건과 최종 환경 조건을 구분하고 교차 배분을 먼저 확정한다.
3. **새 30정체/60정상:** divider 접촉·beam-end·한쪽 막힘·횡 미끄럼/마찰·시작부터 막힘 각6=30.
   정상은 3leg×5속도(0.005/0.010/0.020/0.038/0.050 m/s)×4=60. 독립 배치/물리 seed,
   고정 관측 길이·명령·영향 로봇·같은 기전 예비 순서를 첫 확증 프레임 전에 확정한다.
   30/60 정확 분모, 관측 실패/조작 불성립/INCOMPLETE, 두 로봇 집계를 그대로 유지한다.
   시작 정체6건과 시각 지터의 알려진 실패 가능성 때문에 수집 목적과 가설은 #293 담당자·독립 검토자가 결정해야 한다.
4. **raw 0.1초 + 1초:** 두 자기 손목 RGB를 0.1초 간격으로 연속 보존하고 frame ID/촬영 시각/원본 해시를 남긴다.
   각 1초 차이의 긴 쌍과 0.1초 차이의 잡음 쌍을 정확한 ID로 연결한다. 1초 영상만 저장해 짧은 쌍을 잃지 않는다.
   발행 명령 구간·취소/hold 발행/적용 시각은 자기 로그, GT displacement/contact/실제 관절은 평가 전용 경로다.
   검출 뒤 GT를 join하고, evaluator의 목표 사건 선택·조작 성립 판정은 D1 출력과 독립적으로 한다.
5. **접촉 양성 대조 범위:** #283은 `r2__wheel_rr/r2__wheel_rl` ↔ `zone_wall_divider_1/2` 8/8이다.
   beam-end stall도 높은 문틀 접촉도 아니다. 기존 tracker는 벽↔r1/r2/beam 범위이며 robot↔robot·beam↔peer의
   완전한 접촉 심판이 아니다. beam-end/한쪽 장애물/마찰 조작의 실제 성립·tracker 지원을 별도로 확인한다.
6. **무장되지 않은 구간 수:** #285 p2f는 기존 208건 중 무장 0, 즉 미무장208건(기존 보고; P08 재측정 아님).
   새 cohort도 command 전체 수, 한 번도 무장하지 않은 구간 수, 기준 전/기준 부족/저속/짧음/ROI/결측/시각 오류별
   check 수와 시간, 감지 가능한 구간 내 미무장 비율을 보고한다. 0 alarm을 정상 판정으로 대체하지 않는다.
   D1을 넣어도 p2f나 기존 guard를 더 완화하지 않는다.
7. **별도 실제 중단3흐름:** 정상 이동·중간 정체·시작 정체 각1개, 같은 최종 후보에서
   자기 예정 명령 취소→실제 hold→같은 pair abort→자기 사건→다음 LLM 결정 자격 시각을 기록한다.
   정상 대조는 오경보/불필요한 중단이 없는지 본다. 시작 정체가 unknown이면 detector 중단 성공으로 세지 않는다.
   synthetic alarm 주입으로 경로만 시험한 경우도 별도 표기한다. 취소 이후 stale base/arm 명령 없음,
   실제 정지/추가 밀림·짐 유지/낙하·짝 polling/정지 지연을 평가 전용으로 확인한다.
   이 3개는 D1 감도/오경보의 30/60 분모를 대체하지 않는다.
8. **예산·보존:** 제안 상한 90×120=10,800 SIM초(3h), 별도 중단3×120=360 SIM초(0.1h).
   #293의 본/선택 진단 8,280초+예비 포함3h 초안과 어떤 셀/진단을 포함하는지 조정하여 이중 합산하지 않는다.
   staging/예비가 넘으면 실행 전에 예산을 새로 정한다. 이번 0초를 이 미래 예산의 사용분으로 세지 않는다.
   디스크 여유·raw 예상 크기·ENOSPC=HOST_ERROR 규칙을 사전 점검한다. raw는 기본 checkout의 새로운
   `outputs/` 절대 경로에 보존, 작은 manifest/해시/실패 기록만 Git에 둔다. Drive 없음, 원본 삭제/덮어쓰기 없음.
9. **복구는 별도:** 감지와 명령 중단은 뒤로 물러남·재파지·재계획·임무 재개 성공이 아니다.
   자동 후진/재파지 금지 상태를 유지하고 실제 경로·하중을 검증한 별도 정책/PR에서 다룬다.
   D1 기본 경보/정지 활성화도 새 물리 검증과 독립 검토 뒤 별도 PR로 처리한다.
10. **결과 전달:** 후속 실제 30/60과 중단3 결과는 실패·미완료 포함 새 TensorBoard snapshot으로 등록하고
    원본/기존 snapshot 보존·데이터 로딩·새 영상 등록·표시 수치와 조건을 검증한다. 이번 산술/fake 검사는
    새 물리 결과가 아니므로 TensorBoard snapshot·서버는 만들지 않는다.

P05는 실제 scheduler/다회 결정 연결, P06은 별도 평가·증거, coordinator는 manifest·실행 승인·물리 staging/중단 검증을 조정한다.
