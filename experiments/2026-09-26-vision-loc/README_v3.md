## 질문과 범위

- 2차 test는 train과 독립이 아니었다. test s917이 train s903을 다시 달렸다(PR #227 검토 P1, `results/overlap_round2_vs_train.json`). 3차는 train·dev와 **궤적이 다른** 새 test로 다시 잰다.

## 독립 평가 설계 (`design_episodes_v3.py` → `episodes_v3.json`, 렌더 전 등록 `d934926f`)

2차에서 seed만 달랐던 원인은 결정론적 교사와 물리였다. 같은 출발 줄·배치 칸·상자 칸이면 같은 궤적이 나온다. 3차는 궤적 자체를 바꿨다.

1. **시나리오:** 새 seed(dev 941–950, test 951–970 범위). (출발 줄, 상자 칸) 쌍과 (상자 칸, 배치 칸) 쌍이 2차 전체(train·dev·test)와 먼저 설계한 3차 회차에 없어야 한다. 상자 칸은 시나리오 설정(`sim.zone_arena.episode`)에서만 읽었다. 조건에 맞지 않은 seed 944·952·953·957·958·960·963은 기록하고 건너뛰었다.
2. **출발 자세:** 자기 로봇 출발 위치에 dx −4–6 cm, dy ±8 cm, dyaw ±6°를 더했다(설정 전용, 로봇에게 알리지 않음). 학생의 초기 분포는 그대로 도크 ±15 cm·±10°다.
3. **경로:** 교사가 받는 정답 자세에 회차별 고정 편향(1.2–3.0 cm, 최대 1°)을 더했다. 교사는 참값 + 편향에 있다고 믿으므로 실제 경로가 계획 경로에서 그만큼 비켜난다. 시연 잡음 주입(DART, Laskey 등 2017)과 같은 발상이다. `eval_only/`에는 참 자세가 남는다.
4. **독립성 감사(`overlap_check.py`):** 같은 JPEG 바이트, 같은 명령 팔 자세에서 1 mm·0.1° 안의 재주행 프레임, 같은 길이 회차의 정렬 궤적을 찾는다. 하나라도 있으면 그 회차를 해당 분할에서 뺀다(렌더 전 등록한 규칙).
   - dev 6회: 모두 독립(`results/overlap_v3_dev.json`, 기준 = 2차 17회).
   - test 8회: 6회 독립, **s954(재주행 1프레임)·s962(3프레임) 제외**(`results/overlap_v3_test.json`, 기준 = 2차 17회 + 3차 dev 6회). 두 회차 모두 train s903(= 2차 test s917) 경로와 교차하는 지점(문 밖)에서 1 mm·0.1° 안에 들었다. 규칙대로 뺐다.
   - 같은 명령 자세에서 2 cm·2° 안인 프레임 비율("가까움", 참고용)은 test 21–57%다. 모든 배송이 같은 문을 지나므로 가까운 구간은 남는다. 재주행(1 mm)과 구분해 보고한다.

## 검토 범위와 한계

- 교사가 몬 렌더의 개루프 재생이다. 폐루프(추정으로 주행)는 검증하지 않았다.
- test 6회, 문 근처·운반 1,424 프레임이다. 회차당 표본이 작고 모두 같은 door_1을 지난다. 궤적은 train과 1 mm 안에서 겹치지 않지만, 2 cm 안에서 가까운 구간은 test 프레임의 21–57%다.
- dev 선택 규칙을 세 번 고쳤다. 모두 dev 관찰 뒤, 해당 변형 실행 전에 커밋했다. test는 선택과 사전 등록 뒤에 처음 열었다(분할·추정·채점 모두 `0b1cffa0` 이후).
- 순차 규칙은 요소 간 상호작용(a2 + 정지 모드)을 고르지 못했다. 보조 a3b는 이번 test에서 문 근처 p90 6.1 cm·횡 p99 6.3 cm로 학생과 비슷했고, 길 잃은 프레임은 229(s961 212)로 더 많았다. 끼인 회차가 없는 test에서 정지 모드의 이득은 확인되지 않았다.
- 게이트 p90 5 cm는 문 폭에서 유도한 값이 아니다(Codex 분석). 이번 실패는 진행 방향 편향에서 왔다. 게이트를 다시 유도하려면 새 test 전에 물리 문 여유로 문서화해야 한다. 이번에는 바꾸지 않았다.
- 시뮬레이터 렌더(고정 조명·재질)만 썼다. 실물 이전은 검증하지 않았다.
