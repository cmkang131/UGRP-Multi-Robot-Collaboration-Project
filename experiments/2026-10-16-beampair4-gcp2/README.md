# beampair4 — gcp2 재현과 마지막 R3

PR #522 (`claude/beam-pair-teacher`)의 2026-10-16 후속 기록이다. gcp1은 접근하지 않았다.
첫 프로젝트의 원본·디스크·VM에 요청하지 않고 Mac 회수 요약·몽타주만 읽었다.
기존 R1/R2는 [전날 기록](../2026-10-15-beampair4/README.md)에 보존하며,
이번 gcp2 결과와 합산하지 않는다. 최대 3라운드 중 이번 R3가 마지막이다.

기준 제어 소스 `e645b34beb4fa693ab4ddedfe77045ae26b46388`, 의존성
`26f84d0f0ada1c33473c83cca2d3415ce51bd247`을 gcp2에서 새로 실행했다.
기준 소스의 gcp1 전용 호스트 판독 부분만 `scripts/rehost_beampair3.py`가
메모리에서 바꾸고 차이·원본/적용 코드 SHA256을 실행별 `host-portability.json`에 남긴다.
두 checkout은 clean이며 제어·장면·카메라·입력·수용 상수·성공 판정은 그대로다.
출력의 실제 project/instance는 `ugrp-sim-b-1014` / `ugrp-sim-gcp2`다.
이 이식은 바이트가 완전히 같은 실행 파일이라고 주장하지 않는다.

소스 사본은 공용 `git-shared.git`에 필요한 객체를 넣은 뒤 모두
`git clone --no-local --reference /home/ugrp/ugrp-sim/git-shared.git`으로 만들었다.
사본끼리 alternates를 연결하지 않았고 공용 저장소 gc/prune/삭제는 하지 않았다.
같은 기존 `cargo_v7 / grasp_act_teal_blue_v1 / floor_light_v1` 장면이며
새 벽 질감 v2/v3는 쓰지 않았다. 학습·LLM 호출은 0이다.

## 수정과 R3 경계

R3 제어 소스는 `1242f1d9`의 기존 기본off `beampair_approach_v2` 그대로이며,
호스트/운영 이식 뒤 실행 SHA는 `d72efd13957ce450c5cccc3fd93a555a37dd4705`다.
원래 목표·방향 개선을 유지하면서 같은 현재 경로 위 signed arc의 새 최고 진행만 인정한다.
기존1cm/3SIM초를 유지한다. 목표 감시 초기화를 먼저 하는 기존 R2 TypeError 수정도 포함한다.
후보가 실제로 거부한 오래된 벽만 기존 ActiveReobserve 대상으로 지정한다.
기억 만료로 장애물을 지우거나 통과시키지 않는다.

[Nav2 Pure Pursuit 공식 설명](https://api.nav2.org/nav2-humble/html/md_nav2_regulated_pure_pursuit_controller_README.html)의
최근접 경로점/남은 경로 처리와
[Obstacle Layer 공식 문서](https://docs.nav2.org/jazzy/configuration_and_development/configuration_guide/core_servers/costmap_2d/costmap_plugins/obstacle/)의
관측 persistence·mark/clear 구분을 이번에도 열어 확인했다.
전체 알고리즘 구현·충돌회피 보장을 도입했다는 뜻은 아니다.

보이는 것만·held_object_hidden_v1·weld OFF·카메라·성공 판정·60SIM초 상한은 유지한다.
search24_checks_v1/search25_checks_v1 계산량 예산은 on이다.
기록전용 마지막10SIM초10Hz 자기RGB 링은 on이고 제어/학습 입력으로 쓰지 않는다.
8318620→8318626을 직렬로 먼저, 성공8318600/04/11/31을 그 뒤 실행한다.
한 실패가 확인되면 미시작/같은 결함 실행은 채우지 않는다.
6/6일 때만 gate40 큐를 만들며, 그 경우에도 `HOLD_SCENE`, 미승인·미제출,
8318620/26 먼저·16동시·학습off로 둔다. 장면 확정과 승인은 조정자 몫이다.
