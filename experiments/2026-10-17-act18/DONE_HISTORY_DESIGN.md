# done 신호 학습 후보 design note (실행·코드 없음)

2026-10-18. 근거: B1(미래 horizon h≈99에서 p 0.999/현재 h=0은 ~1e-4), B3a(h=0 라벨만 → done p max 0.0009, done_bce 0.95·grad norm 752로 불안정), B2(from scratch 20k done 미학습). 평가 계약 변경은 사용자 결정 전 금지.

## 문제 정의

- 현재 done 표적은 에피소드당 grasp/release 각 1행(총 400행/72,572)이고, **특정 스텝이 "완료 시점"임을 한 장의 현재 RGB+4틱 명령 이력만으로는 식별하기 어렵다**(hold 마지막 행은 직전 hold 행들과 거의 동일한 관측).
- B1: 미래 horizon 예측은 학습되지만 실행(h=0) 확률은 학습되지 않음. B3a: h=0 라벨만 남기면 최적화 자체가 불안정(BCE 0.95, grad 752)해진다.
- 결론: **done은 별도 시퀀스/기억 입력 또는 라벨 재정의가 필요**하다. 단일 프레임 현재 확률을 문턱으로 쓰는 계약은 유지 불가.

## 후보 1 — done 전용 시퀀스 분류기(2단계, 권장)

1. ACT 정책은 그대로(행동 head만). 완료 head는 별도 소형 분류기로 분리:
   - 입력: 최근 RGB N프레임(예: 0/0.3/0.6/1.0s 전)의 저해상도 특징 + 최근 명령 이력 M틱(예: 8–16) + skill 토큰. 모두 자기 관측/명령.
   - 구조: GRU/LSTM 1층 또는 temporal conv, 약 1–2M 파라미터.
   - 학습: 기록된 에피소드에서 슬라이딩 윈도우 라벨(done은 grasp/release 구간 마지막 local 행). positive-balanced batch + pos_weight, VAL은 TRAIN 시연과 다른 에피소드.
   - 1차 검증(무료): held-out 40검증 에피소드에서 **offline AUC·정밀도/재현율, 발화 시각 오차(lift/hold 대비 ±N틱)**. 이 단계에서 안 되면 물리 실행 불필요.
2. 통합(후보 act18-donehead): 실행 시 분류기 발화 → done으로 스킬 전환. 기존 ACT 행동은 불변 → B2/B3와 isolated 비교 가능.
- 비용: 개발 0.5–1일, offline 검증 1–2h CPU, 물리 TRAIN4 1회(≈15분)+VAL8(통과 시).
- 위험: 경계 오탐(조기 종료)·미탐(끝까지 정지); 발화 문턱과 지속 N틱을 사전등록. 평가 계약(공식 done 정의)은 바꾸지 않고 이 후보 내부 신호로만 사용.

## 후보 2 — state에 긴 명령 이력 + RGB 이력 추가(단일 모델)

- ACT observation.state에 명령 이력 4→16틱(1.6s) 확장, 그리고 image_mode를 `history_montage_v1`(RGB 4장: 0/0.2/0.5/1.0s)로 전환. 둘 다 사용자 허용 입력(자기 RGB 이력·자기 명령 이력) 범위.
- 체크포인트 warm start: state projection 입력 차원이 바뀌므로 backbone/action decoder는 R8/B2에서 초기화하고 state projection·done head만 새로 학습(부분 초기화, prereg에 명시). 이미지가 montage로 바뀌면 첫 conv 입력 채널 변경 → full 재학습 필요(비용↑).
- 비용: 개발 1일, 20–100k bf16 학습. 위험: 입력 계약 변경으로 기존 비교 불가, 학습 비용 큼.

## 후보 3 — 라벨 재정의(평가 계약 변경 필요, 사용자 결정)

- done=마지막 K틱 window(예: 5틱=0.5s)로 양성 확대, 또는 종료까지 남은 시간 회귀(t_done) 후 임계+지속 조건 발화. 
- 장점: 학습 신호 완화. 단점: 공식 성공 정의(issued_done) 변경 → 사용자 승인 필요, 기존 결과와 합산 금지. B3a 결과(h=0만으로는 불안정)를 감안하면 window 라벨은 여전히 단일 프레임 식별 문제를 남김.

## 후보 4 — 규칙 기반 종료(평가 계약 후보, 실행 금지 메모)

- 자기 명령 이력만으로(그리퍼 close 명령 후 lift/자세 명령 유지 N틱) done 발화. 학습 0. 
- 장점: 즉시 사용 가능, 표준 ACT(종료 없음)와의 격차 축소. 단점: 손으로 짠 종료 규칙이 행동/평가에 개입 → 정책 판단 원칙과 충돌, 발화 조건·N 사전등록·입력 감사 필요, 공식 채점 정의 변경은 사용자 결정.
- 오프라인 근거: B1 로그의 "청크 내 터미널 예측" 규칙은 문턱 .65에서 t=9.2/20.1/21.5/41.7s에 발화해 교사 close(12.9–17.7s)·hold(23.6–31.3s)와 3.5–19s 어긋났다(신뢰 불가).

## 권고

1. **후보 1(2단계 done 분류기)** 을 먼저 offline 검증(무료) — done이 학습 가능한지 자체를 싸게 판정.
2. offline에서 AUC/발화 정밀도가 충분하면 후보 act18-donehead로 물리 TRAIN4.
3. 그래도 물리 task가 안 되면 남은 축은 행동 형식/데이터 규모(`ACTION_FORMAT_DESIGN.md`, Phase C)이며, 평가 계약 변경은 사용자 결정 후에만.
