# act18 기억 입력 후보 설계 (2026-10-18, 설계만·코드 없음)

상태: **설계 노트만**. 코드·토글·학습 실행은 하지 않았다. R8/R100 TRAIN4 0/4와
`results/faildiag-r3.json` 진단(조기 base 정지·목표 하단 이탈·post-close 미수행)을
근거로 다음 라운드 후보를 정리한다. 이 문서는 사용자/Lead 승인 전 제안이며
어떤 결과도 주장하지 않는다.

## 현재 입력(고정)

v7 ACT 학생 입력은 자기 RGB 1장(`current_full_v1`) + 자기 발행 명령 이력 +
고정 스킬/물건 토큰이다. 정적 지도·top 카메라·정답 좌표·접촉·측정 관절은 입력에
없다(`held_world_reads=0`). act17 계열의 `history_montage_v1`(RGB 4장 montage)은
구현·감사 경로가 이미 있으나 act18 학습은 현재 프레임 1장만 썼다.

## 후보 M1 — RGB 프레임 이력(가장 저렴, 기존 구현 재사용)

- 입력: 현재 프레임 + 과거 3장(0.5/1.0/2.0s 전 등 고정 stride) montage. 모두 자기 RGB.
- 근거: 교사 데모에는 학생이 멈추는 post-close 구간(lift→hold)의 시각 예시가 실제로
  있고(교사는 close 이후 5–8s 더 수행), 현재 프레임 1장으로는 "정지 직후의 자기
  손/상자 상대 변화"를 볼 수 없다. `faildiag`: 학생은 base 정지 뒤 손가락힘 3.7–5.2N로
  close까지 수행하지만 verify_lift/hold/done을 못 낸다.
- 구현 비용: `history_montage_v1` 데이터 경로가 이미 존재(새 녹화 0). 단 100k 학습을
  새로 돌려야 하고 R8와 합산 금지. R8 checkpoint에서 초기화 불가(첫 conv 입력 채널
  변화) — 새 학습 또는 backbone 동결 + 입력 projection만 학습하는 옵션을 별도 검토.
- 위험: 프레임 4장 montage는 해상도/시야가 줄어 현재 접근 정밀도가 나빠질 수 있음.
- 관문: 새 후보 자체 TRAIN4 4/4 → VAL8 8/8 → FINAL40. R8/R100과 합산 금지.

## 후보 M2 — 마지막 목표 상대위치 기억(자기 RGB 검출 기반)

- 입력: 마지막으로 자기 RGB에서 본 목표(색/종류 토큰과 일치하는 상자)의 **자기 기준
  거리·방향 추정**, 마지막 관측 이후 경과 시간, 불확실성(거리 오차 추정) 3–5 스칼라.
  기억은 이동 명령 적분(자기 명령 기반 odometry)으로 이동량만큼 반대로 갱신한다.
- 금지 유지: 정답 좌표·시뮬레이터 상태·접촉·측정 관절은 기억에 넣지 않는다. 검출은
  자기 RGB 색 분할(기존 기존 act17 색 검출기)만 쓰고, 미검출이면 `not_seen`으로
  명시한다(빈 사유 금지 규칙). 불확실성은 "미측정"으로 남긴다.
- 근거: 학생이 목표를 화면 하단으로 놓친 뒤에도 close를 수행했고, 목표와 0.20m
  전방에서 정지했다(Lead 시각 분석). "마지막으로 봤던 목표가 어디였는지"가 없으면
  정지 후 재접근/정렬을 스스로 복구할 수 없다.
- 구현 비용: observation.state 벡터 확장(기존 MLP 입력 차원 변경) → R8 checkpoint
  전체 초기화 불가, projection warm-start 또는 새 학습. 색 검출기 신뢰도·분산 검증 필요.
- 위험: 검출 오차·odometry drift가 오히려 잘못된 이동을 만들 수 있음. 감사는 입력
  화이트리스트 확장 + `invisible_measurements=0`/`held_world_reads=0` + 검출 실패/오차
  분포 기록으로 한다.

## 후보 M3 — M1+M2 결합

- 프레임 이력 + 기억 스칼라를 함께. 비용 최대. M1/M2를 각자 자체 관문으로 먼저 재고,
  둘 다 개선이 확인된 경우에만 결합 라운드로 올린다(합산 금지).

## 검증 계획(모두 새 라운드, 기존과 합산 금지)

1. 새 입력 토글은 default off. v7 데이터·TRAIN200 그대로 사용(새 녹화 0).
2. 입력 감사: 실제 요청에 실린 필드 화이트리스트·`invisible_measurements=0`·
   `held_world_reads=0`·`top=0` 확인.
3. TRAIN4(4/4) → VAL8(8/8) → FINAL40, 각 단계 raw 재계수. 실패 시 원인표(정지/진동/
   접근/늦은 lift)와 영상 프레임 ≥6장.
4. R8/R100/tune과 합산 금지. 100k bf16 학습은 이번 라운드에서도 별도 검증 항목.
