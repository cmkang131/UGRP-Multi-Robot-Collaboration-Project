# 평가계약(물리 성공 정의) 후보 — 사용자 결정용 메모 (실행 금지)

2026-10-18. 현재 계약: 성공 = **물리 평가(Score: lift/hold/release)** AND **학생이 발행한 done(issued_done)**. 이 메모는 계약 변경을 실행하지 않으며, 사용자 결정용 후보와 근거만 정리한다.

## 근거 (원본)

- B4 hybrid done(`act18-doneh`): TRAIN4 **0/4**이지만 4/4 `issued_done=True·cap_end=False`, grasp done 31.3–31.7s·release done 34.8–35.3s. **물리 lift는 0/4(reason=lift_not_stable)**.
  - 즉 done 모듈은 물리 성공 없이도 "완료"를 발화했다. 성공 정의에서 물리 조건을 빼면 **실패를 성공으로 보고**하게 된다.
- B1–B3: done 미발화로 cap_end 90s까지 실행. done을 policy가 학습하지 못함(현재 스텝 확률 ~1e-3).
- closed-loop 진단(B4 raw): 교사 grasp 10–15s에 base 이동 0.26·gripper closed 0.63→1.0으로 전환하는데 모델은 base 0.75 계속·gripper 0.24에 머묾; 교사 release 0–2s 이동 1.0인데 모델 0.05. **행동/물리 축 실패**가 남아 있다.

## 후보 (권고 아님, 결정 필요)

### 후보 0 — 계약 유지 (권장 기본값)
- 성공 = 물리 AND issued_done 유지. done 모듈은 hybrid 보조로만 표기, 패키징/배포 금지, 결과 pooling 금지.
- 장점: B4가 보여준 "물리 없이 done"을 성공으로 오인하지 않음. 단점: 학생 독립 실행 성공에는 행동/물리 개선이 필수.

### 후보 1 — 종료 신호와 성공 정의의 분리 (학습 조건만 변경, 채점 불변)
- 채점 success = 물리(현재 그대로). 실행 시 종료(episode end)는 ①학생 done ②규칙 종료(gripper close + lift 명령 + hold N틱) ③교사 스타일 최대 시간 중 하나로 가능하되, **성공 판정에는 영향 없음**.
- 장점: done 학습 실패(B1–B3)와 무관하게 행동 학습을 평가할 수 있음. 규칙 종료는 "정책 판단"이 아니므로 성공 판정과 분리.
- 필요 조건: 종료 방식별로 raw·SHA를 분리 기록, 규칙 종료는 사전등록(N=3/5틱 등), 물리 성공률만 비교. 평가계약(성공 정의) 변경 아님 — **실행 조건 변경**이므로 사용자 승인 필요.

### 후보 2 — 부분 성공/단계별 채점 (계약 변경)
- 접근· grasp-close·lift·hold·release 각 단계의 물리 성공을 별도 지표로 보고, 총 성공은 지금처럼 전부 만족.
- 장점: 어디서 실패하는지 성공/실패 이분법보다 잘 보임. 단점: 성공 정의 자체를 바꾸면 기존 비교와 합산 불가 → **사용자 결정 필요**.

### 후보 3 — 완료 라벨 재정의 (계약 변경)
- done을 "마지막 K틱 window" 또는 "남은 시간 회귀"로 학습해 policy가 done을 배울 수 있게 함(B3a 실패 원인 완화). 실행·채점 정의 변경 → 사용자 결정 필요.
- 위험: window 라벨은 여전히 단일 프레임 식별 문제 잔존; 채점에는 교사/평가 GT의 "실제 완료"가 필요.

### 후보 4 — 물리 성공 정의 자체 변경 (비권장)
- 예: lift 없이 release 완료만으로 성공, 또는 명령 기반 완료를 성공으로 인정. B4 근거상 **실패를 성공으로 오인**하므로 권장하지 않음.

## 현재 권고

1. **후보 0 유지**가 기본. B4 결과를 성공으로 보고하지 않는다.
2. 행동/물리 축 개선(Phase C co-training, closed-loop 진단 후속)을 먼저 진행하고, 종료 방식 분리(후보 1)는 사용자 승인 후 사전등록해 비교한다.
3. 후보 2·3은 사용자 결정 전까지 설계·메모만 유지한다(현재 실행 금지).

## 검증 범위

- B4는 hybrid(ACT 행동 + 자기 명령이력 done 모듈), 패키징·배포 금지. TRAIN4 4-world 단일 실행이며 closed-loop GPU 비결정성으로 동일 체크포인트도 실행마다 궤적이 갈릴 수 있음(같은 B2 체크포인트의 별도 실행이 t≈2.2s에서 분기) — 단일 4-world 결과의 성공/실패를 과대 해석하지 않는다.
