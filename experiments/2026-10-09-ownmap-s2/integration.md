# 탐색 → 집기 → B 운반의 남은 연결

아래는 구현 전 작업량 추정이며 실행 약속이나 성공 예측이 아니다. 이번 어댑터는
`step/drive/_control`을 차단하는 오프라인 위치추정 전용이다. 경로·픽업 슬롯·벽 높이를
가정하는 기존 운반 제어기에 바로 연결하면 안 된다.

| 남은 연결 | 현재 재사용할 수 있는 코드 / 필요한 변경 | 추정 인시 |
|---|---|---:|
| 탐색 종료 지도 인계 | `self_map_closed_loop.RememberedGoal.lose`의 causal snapshot 계약을 재사용. own frame ID·종료 시각·grid/landmarks/B provenance·해시를 함께 봉인하고 수신 측에서 확인 | 2–4 |
| 위치추정 인계 | `ownmap_s2`의 입력 경계를 runtime 계약으로 분리. 시작 prior 없음/자기 추정 인계 선택을 명시하고 좌표·공분산·시각·불확실성 의미를 유지. GT 변환 금지 | 2–4 |
| 슬롯 없는 상자 탐색·집기 | `zone_solo_cyan_contract_v106.validate`의 `P1-2` 요구와 `Runtime`의 slot 범위 필터/접근점을 자기 RGB 물체 추적·접근 확인으로 대체. 기존 grasp 동작 자체는 별도 검증 | 4–8 |
| 자기 경로와 B 접근 | `self_map_closed_loop`의 own grid costmap 및 `active_navfn_start` 경로를 재사용 후보로 검토. `passage_route`의 정답 문 ID/정적 waypoint를 없애고 화물 footprint·unknown 처리를 연결. 부분 관측 B는 도착 후 재관측 | 4–8 |
| 단계 전환·하중 관측 | 탐색/상자 발견/파지/이동/내려놓기를 허용 영상·자기 발행 명령 기반 증거로 연결. `declared_goal`·발행 명령을 실제 운반 성공으로 승격하지 않음 | 2–4 |
| 표준 실행·기록 | `configs/simulation_workflows.json`과 기존 어댑터에 연결하고 새 bundle에 지도·환경·카메라·명령/관측 주기를 봉인. 새 번호는 그 작업 때 전체 branch 예약 확인 후 배정 | 2–4 |
| **연결 코드 소계** | 위치추정이 요구 정확도를 만족한다는 전제의 추정 | **16–32** |

그 전제는 이번 비교만으로 확보되지 않는다. 동일 장면 입력의 확인·사전 등록·평가 준비에
추가 4–8인시, 아래 진단에서 드러난 위치추정/지도 문제의 첫 수정·오프라인 검증 주기에
8–16인시를 별도 예상한다. 후속 수정은 먼저 표준 방법·공개 구현을 조사하고 새 후보로 검증해야
하며, 이 시간 안의 해결을 보장하지 않는다. 이번 작업에서는 새 튜닝을 하지 않았다.

동일 물리 장면에서 탐색→집기→운반 전체를 실행·회수·판정하는 인수 작업은 연결 코드와
별개다. 준비·판정 6–12인시 + 실제 실행 시간이 들 것으로 추정하며, 별도 범위·예산·공용 실행
순서/잠금을 확정해야 한다. 이번 과제에는 물리 실행·agent_lock 취득을 포함하지 않았다.

참조 경계: S2는 고정 부모 `e532f52e`; 자기 지도 어댑터 참고는
`4851b313a6280f7f089b8320c18c479ccf421fc1`, 이 연결 목록의 추가 코드 조회는
`80ec4fc06e129c7b84d99b878dbc0e905a4aa6e4`를 `git show`로 읽기만 했다.
다른 branch의 후속 변경을 이번 고정 재생 소스에 가져오지 않았다.
현재 어댑터의 형상 호환용 높이 0 placeholder와 빈 슬롯은 물리 계획용 지도 완성의 증거가 아니다.
