# TASK-CHEN2D-5: how news told to one robot reaches the plan-maker: authors' rules, automatic forwarding, the robot's choice (2026-11-24, version 2 of this brief, after the review debate `../20261123-plan3/debate/R3-ASTRA.md`)

Context: tasks 1 to 4 are done (`REPORT-CHEN2D.md`). Same hard limits (this folder only, no network, fake model for tests, no real-model batches; the main session runs them).

Why: under the edge-computing premise a change of orders is known only to the robot that was told. The authors' rules (written for "everyone knows the state") give that robot no channel (CMAS) or often no turn (DMAS: with 32 robots only 4 spoke; HMAS-2: only agents with an action review). The user's decision: do not force everyone to speak; a robot that receives news CHOOSES whether to pass it on, as in our earlier experiments. The reviewer's point, accepted: to say anything about the choice we also need a control in which the news is forwarded automatically, and the forwarded content must be the same text, otherwise we measure how well the robot summarises.

## H1. `--speech authors | auto | choice | free` (default authors = version 4 behaviour, byte for byte)
Common to `auto`, `choice`, `free` (nothing else in the authors' loops changes):
- When: right after the event has been applied, before the next planning iteration. Only robots that actually received the notice take part (all agents with `--tell all`; L with `leader`; M with `member`; for e2 the member known at the trigger).
- Recipients: CMAS and HMAS-2: the central planner (robot L). DMAS: all other robots. HMAS-1: the central planner and all other robots. A told robot that is itself the only recipient (L under `--tell leader` in CMAS / HMAS-2) sends nothing and gets no call (`relay_skipped_self`).
- Delivery and memory: a delivered message is shown to its recipients from then on in every prompt of theirs that contains the current state (planner prompts, dialogue turns, review turns, re-prompts), as a block right before the current state: `Messages received from robots:\n[Agent[r, c], after step K]: TEXT` (oldest first). It stays for the whole episode and is outside the authors' history window. Non-recipients never see it. Nothing shows that a robot passed.
- `auto`: no LLM call. TEXT is the notice the robot received, word for word.
- `choice`: one LLM call per told robot. Prompt, in this order: the authors' local description of the robot's own square and doable actions (the same text block their local prompts use for the agent's own state; no dialogue, no plan), the notice it received, then ONE of the two pre-registered sentences below. Reply `SEND`: TEXT is the notice word for word (same as `auto`). Reply `PASS`: nothing is sent. Parsing: strip whitespace and trailing punctuation, case-insensitive; if the reply contains exactly one of the two words as a whole word, take it; otherwise record `relay_format_error` and send nothing.
  - Wording 1: `You may forward this notice to RECIPIENT. Reply SEND or PASS.`
  - Wording 2: `You may keep this notice or forward it to RECIPIENT. Reply PASS or SEND.`
  - Which wording a map uses is fixed in the event file (seeded, half of the maps of a set each) and is the same for every framework and condition on that map. RECIPIENT = `the central planner` / `all other robots` / `the central planner and all other robots` as above.
- `free`: one LLM call per told robot, same prompt but the last sentence is `You may send one short message to RECIPIENT, or reply PASS to send nothing. Reply with the message text alone, or PASS.` TEXT is the robot's own words (cut at 400 characters, record if cut). PASS parsing as above (the reply equals PASS).
- Calls, tokens and cost of these calls count in the episode like any other call (their own columns too).
