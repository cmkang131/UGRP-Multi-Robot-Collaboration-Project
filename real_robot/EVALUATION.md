# 실물 평가: 무엇을 어떻게 재나

목표는 **시뮬과 같은 지표를 실물에서도 같은 정의로** 뽑는 것이다. 기본은 **천장 카메라 없이** 노트북 사건 기록과
사람 기록만 쓴다. 사람 손이 가는 곳은 끝난 뒤 바닥을 보고 상자 위치를 적는 것뿐이다.

| 무엇 | 어디서 | 시뮬에서는 |
|---|---|---|
| 사건 시각 (시작, 정렬 끝, 내려놓기, 끝남) | 노트북 실행기 기록 `events.jsonl` (실행기 전까지는 `scripts/real_event_mark.py` 로 손으로) | 시뮬 시각 |
| 상자가 어느 표식 앞에 있나 | 사람이 끝난 뒤 적음 `operator.json` | 시뮬 정답 좌표 |
| 집기 성공 | 사람이 적음 (들었나, 3초 버텼나) | 시뮬 접촉 |
| 휴대폰 영상 | 보조. 개입·이상 장면 확인용. 시작 키를 누른 순간의 영상 초를 `phone_sync_s` 에 적으면 시간이 맞춰진다 | 없음 |
| (선택) 로봇 위치·방향 | 천장 카메라 + 로봇 윗면 카드 (`real_robot/overhead_real.py`) | 같은 카드를 시뮬 천장 카메라로 읽음 |

천장 카메라 없이 잃는 것: 로봇별 이동 거리·로봇 사이 최소 거리, 1대 집기의 정렬 끝 위치 오차(mm, °),
내려놓은 자리의 세 번째 확인. R0·완료 시간·순서 위반은 그대로 나온다.

**주의 (3대 협동)**: 2차 본 실험의 실행층은 `--overhead` 로 돈다. 이동·문 통과·양보·든 채 이동이 천장 카메라로 잰
자기 위치와 다른 로봇 위치를 쓴다(docs/execution_layer.md). LLM 에는 방 이름만 간다. 천장 카메라 없이 3대를 돌리면
실행층이 본 실험과 달라지고, 시뮬에서 바퀴 기록만 쓴 방향은 상자를 돈 뒤 50–150° 틀렸다. 1대 집기(접근 + ACT)는
자기 카메라만 쓰므로 천장 카메라가 필요 없다.

## 지표 (`scripts/real_trial_metrics.py <폴더>`)

docs/architecture.md 7절과 같은 정의다.

- **R0 배달 비율**: 맞는 표식에 놓인 주문 ÷ 주문 수. 순서 규칙을 어긴 주문은 채워지지 않은 것으로 센다.
- **완료 시간**: 시작부터 마지막 로봇이 끝날 때까지. 다 못 끝내면 상한(`cap_s`).
- **순서 위반 수**: 뒤 주문이 앞 주문보다 먼저 놓인 경우.
- **함께 보는 값**: 로봇별 이동 거리, 천장 카메라에 보인 비율, 로봇 사이 최소 거리, 사람 개입 목록.
- **1대 집기**: 성공 n/N, 그리고 정렬이 끝난 순간 로봇 위치를 기준 위치와 비교한 앞뒤·옆 오차(mm)와 각도(°).
  시뮬 DR(experiments/2026-11-19-sim2real-dr)과 같은 숫자라서, ACT 가 실패했을 때 접근 탓인지 ACT 탓인지 가른다.
- **교차 확인**: 내려놓을 때 로봇 위치 + 팔 길이로 천장 카메라가 추정한 표식, 실행기가 말한 표식, 사람이 본 표식이
  셋 다 맞는지. 어긋나면 `checks` 에 남기고 고치지 않는다.

천장 카메라 정밀도 (합성 화면, 렌즈 왜곡 + 장착 2° 기울어짐 시험): 위치 2 mm 이내, 방향 1.6°(95%), 최대 2.1°.
카드가 화면에서 20 px 정도라 방향 한 번 읽기는 흔들리므로, 정렬 오차는 멈춘 1초 동안의 중앙값으로 낸다.

## 천장 카메라 설치 (선택, 한 번)

1. 천장 카메라(USB)를 경기장 가운데 위에 아래를 보게 단다. 시뮬은 2.5 m, 1280×960.
2. 로봇 윗면 카드 출력: `python3 scripts/make_real_markers_a4.py markers.pdf` (시뮬과 같은 번호·크기).
3. 바닥 카드·시작 카드 출력: `python3 scripts/make_floor_cards.py cards/` (5×5 사전이라 로봇 카드와 안 겹침).
4. 체커보드 사진 15장쯤 → `python3 scripts/real_overhead.py intrinsics ...`
5. 바닥 카드 4장 이상을 경기장 모서리 쪽에 붙이고 줄자로 중심 좌표를 재서 `configs/real_robot/floor_cards.json`
   (양식 `floor_cards_template.json`) → 사진 한 장 → `python3 scripts/real_overhead.py pose ...`.
   재투영 오차가 1 px 넘으면 좌표나 카드 번호를 다시 본다.
6. 표식 앞 놓는 구역(`signs`)과 팔 길이(`release_reach_m`, 내려놓을 때 로봇 중심에서 상자 중심까지 줄자로)를 잰다.

## 매 시행

1. 폴더 하나: `runs/<trial>/`. `trial.json` 을 양식(`trial_template_pick1.json` / `trial_template_coop.json`)에서 채운다.
2. (천장 카메라를 쓰면) 천장 기록 시작: `python3 scripts/real_overhead.py record --calibration ... --out runs/<trial>/overhead.jsonl --video runs/<trial>/overhead.mp4`
3. 휴대폰 녹화 시작. 천장 카메라가 있으면 시작 카드를 천장 아래에서 휴대폰에도 보이게 2초 든다. 없으면 시작 키를 누를 때 노트북 화면이 영상에 보이게 한다.
4. 실행. 실행기가 아직 없으면 `python3 scripts/real_event_mark.py runs/<trial>/events.jsonl --robot r1 --item red_1` 에서
   `s`(시작), `h`(정렬 끝), `r 12`(12번 표식에 내려놓음), `f`(끝).
5. 끝나면 바닥을 보고 `operator.json` 을 채운다(양식 `operator_template.json`): 상자마다 어느 표식 앞인지(없으면 null),
   집기 시도별 결과, 사람이 손댄 순간(휴대폰 영상 초)과 이유.
6. `python3 scripts/real_trial_metrics.py runs/<trial>/` → `metrics.json`.

## 아직 정해지지 않은 것

- 상자가 "표식 앞에 놓였다"의 실물 구역 크기는 2차 실험 채점기의 규칙에 맞춰야 한다. 그 코드가 main 에 올라오면
  `signs` 사각형을 같은 값으로 정하고, 같은 입력으로 두 채점기가 같은 값을 내는지 시험을 하나 더 둔다.
- 천장 카메라 실제 높이와 해상도. 시뮬(2.5 m, 1280×960)과 다르면 카드가 더 작게 찍혀 방향 오차가 커진다.
