# 작업 계획

2026-11-14 정하고 2026-11-15 두 번 고쳤다(오후: 천장 카메라 위치 측정, 저녁: 독립 방향 점검을 받아 과제·규모·일정). 실험 수치와 날마다의 진행은 팀 Linear(UGRP 팀)에 적는다.

## 1. 왜 다시 정했나

연구 질문은 그대로다: 각 로봇이 자기가 본 것만 아는 상황에서, LLM 이 짠 작업 계획이 팀 구조에 따라 어떻게 달라지는가. 바뀐 것은 그 질문에 답하는 길이다.

| 문제 | 내용 | 고친 것 |
|---|---|---|
| 계획 실험이 팀 구조를 가르지 못했다 | 움직이는 로봇이 한 대뿐이었다 | MuJoCo 에서 두 대가 실제로 움직이고, 협동이 필요한 장면을 만든다 |
| 계획 실험의 시간이 실제 동작과 달랐다 | 집기 8초로 두었는데 시뮬레이션 실측은 약 1분이다 | 계획 전용 환경은 접었다 |
| 계획과 동작이 따로 놀았다 | LLM 의 선택을 동작으로 넘기는 연결이 없었다 | 선택대로 움직이는 실행층을 붙였다 |
| 위치를 잘못 알았다 | 바퀴 기록으로 잰 방향이 어긋나고 다른 로봇을 거의 못 찾았다 | 위치는 천장 카메라로 잰다 |
| 이대로 돌리면 대부분 비긴다 (2026-11-15 저녁 점검) | 장면 일부는 구조와 상관없이 같은 선택이 나오게 만들어져 있었다. 2대에서 팀장 구조와 동등 구조는 지시문 한 줄 차이다. 같은 장면의 반복 3회는 표본 3개가 아니다. 계획기의 구현 결함이 LLM 의 한계로 보고될 수 있었다 | 장면을 유형별로 다시 짜고, 계획기 결함을 모든 구조에 같게 고치고, 장면을 단위로 센다 |

선행 연구와 다른 점은 LLM 의 계획을 실제로 움직이는 로봇으로 끝까지 실행하고, 계획의 질과 동작의 성패를 나눠 잰다는 데서 나온다.

## 2. 이번 제출의 범위

| 항목 | 한다 | 하지 않는다 |
|---|---|---|
| 환경 | MuJoCo 에서 로봇이 실제로 움직인다(2대 중심, 3대는 작게). 같은 장치를 실물에도 둔다 | 계획 전용 환경의 결과(성적에는 쓰지 않는다) |
| 위치 측정 | 천장 카메라 1대가 로봇 윗면의 번호 카드를 읽어 모든 로봇의 위치·방향을 잰다. 시뮬레이션도 그린 화면에서 같은 방법으로 읽는다. 동작 코드(이동, 문 통과, 충돌 방지)만 쓴다 | 바퀴 기록만으로 위치 추정, 천장 카메라 값을 LLM 에 주는 것 |
| 누가 무엇을 아나 | LLM 은 자기가 본 상자, 자기 주문, 받은 메시지, 자기 진행에서 아는 방 이름(시작은 상자 방, 자기가 문을 지난 뒤는 목적지 방)만 안다. 주문은 팀 전체의 것이고 개수는 팀 합계라는 것, 주문에 없는 상자를 옮기면 감점이고 할 일이 없으면 끝내도 된다는 것은 모든 구조에 같은 과제 규칙으로 준다 | 다른 로봇의 위치를 주는 것 |
| 팀 구조 | 통신 없음(T0), 모두 동등(T1), 팀장 있음(T2). 3대에서는 팀원이 팀장에게만 보내야 T2 로 센다 | 혼합(T3)은 부록 |
| LLM 이 정하는 것 | 어느 상자, 어느 목적지, 문을 누가 먼저 지날지, 무엇을 알릴지. 상자는 번호가 아니라 색·방·"내가 든 것/남은 것"으로 부르게 한다. 코드는 몸 움직임의 교착만 모든 구조에 같은 고정 규칙으로 푼다 | 로봇끼리 길을 예약하거나 협상하는 코드 |
| 과제 | 구조 차이가 의미 있는 유형만 둔다(4절). 한 로봇은 한 번에 상자 하나만 나른다 | 순서 제약 유형, C3 유형 |
| 기준선 | 정답 계획으로 실행한 것(상한), 통신 없음(하한), 모든 정보를 한 LLM 에 준 실행 | |
| 실물 | 대표 장면 1~2개로 같은 장치가 실물에서 도는지 확인. 안 되면 한계에 적는다 | 실물 본실험 |

## 3. 순서

| 때 | 일 | 끝났다고 보는 기준 |
|---|---|---|
| ~11/17 | 계획기·실행기 결함을 모든 구조에 같게 고친다: 상자 지칭, 대화에는 메시지 본문만, 받은 사실은 출처를 붙여 기억 표에, 과제 규칙 두 줄, 문 지나기 전에 새 메시지가 오면 목적지를 다시 묻기, 주문·선택지 순서 균형. 그다음 C01·L01·D01 을 구조마다 2회 | 확인 실행 뒤에는 더 고치지 않는다 |
| 11/17~19 | 장면을 다시 짠다: L 12, C 12, K 10, X 3, D 3, 무작위 20. 설계 장면은 실행을 시간 모형으로 바꾼 재생 층으로 거른다 | 장면마다 정답 계획과 통신 없음의 차이가 계산돼 있다. 재생 층은 거르는 데만 쓰고 성적에는 넣지 않는다. 무작위 20 은 거르지 않는다 |
| 11/20 | 프롬프트와 실행층을 동결한다(해시 기록). 온도, 반복 횟수, 주 검정, 제외 규칙을 한 쪽에 미리 적는다 | 동결 뒤 실행 실패는 고치지 않고 그대로 센다 |
| 11/21~27 | 기준선과 본 비교 A, 무작위 | 중간에 프롬프트를 고치지 않는다 |
| 11/28~12/4 | 팀장 교대, 전체 정보 LLM, 두 번째 모델. 3대는 아래 관문을 넘을 때만 | |
| 12/5~10 | 절제, 순서 편향 확인, 재실행, 실물 시연 1~2장면 | 실험은 12/11 전에 끝낸다 |

3대의 관문: 고정 계획(정답 계획)으로 3대를 돌려 10번 중 9번 이상 성공해야 한다. 11/27 까지 못 넘으면 3대는 버린다. 순위는 2대 본 비교, 3대 소규모, 두 번째 모델, 실물 시연 순이다.

## 4. 과제 유형

| 유형 | 장면 | 무엇을 보나 |
|---|---|---|
| L (주문 집중) | 12 | 한 로봇이 주문 대부분을 안다. 한 로봇 한 상자 규칙에서는 통신 없이 다 덮을 수 없다 |
| C (같은 색 경쟁) | 12 | 같은 색 상자가 있어 목적지를 맞춰야 한다. 주문 보유자와 정답이 첫째 주문인지를 반반으로 맞춘다 |
| K (능력 제한) | 10 | 로봇마다 집을 수 있는 색이 다르다. 정답이 하나뿐이고 자기 주문만으로는 풀 수 없다 |
| X (대조) | 3 | 통신이 해를 끼치지 않는지 본다. 구조 차이가 나지 않는 것이 정상이다 |
| D (대조 후보) | 3 | 주문 없는 로봇이 가만히 있는지 본다. 규칙을 고친 뒤에도 세 구조가 같으면 뺀다 |
| 무작위 | 20 | 규칙대로 뽑은 장면. 설계 장면과 합쳐 검정하지 않는다 |

한 로봇은 한 번에 상자 하나만 나른다(여러 번 나르게 하면 통신 없음이 혼자 끝내 차이가 시간으로만 남는다). 주문 없는 로봇이 추측으로 옮긴 것은 "근거 있음/추측"으로 사후에 나눠 따로 센다.

## 5. 실행 횟수

| 묶음 | 내용 | 회 |
|---|---|---:|
| 정답 계획 기준선 | 본 비교 장면 전부 × 1 (실행 실패율의 분모) | 60 |
| 본 비교 A | 설계 40장면 × 세 구조 × 2 | 240 |
| 무작위 | 20장면 × 세 구조 × 1 | 60 |
| 팀장 교대 | 정보가 한쪽에 몰린 20장면 × T2(팀장을 r2 로) × 2 | 40 |
| 3대 | 12장면 × 세 구조 × 2 (관문을 넘을 때만) | 72 |
| 두 번째 모델 | A 에서 유형별로 뽑은 20장면 × 세 구조 × 1 | 60 |
| 절제 | 10장면 × T1 × (재결정 끔 / 사전 교환 / 듣기 0초) × 2 | 60 |
| 순서 편향 확인 | C 4장면에서 주문·선택지 순서만 뒤집어 × 2 | 8 |
| 전체 정보 LLM | A 에서 20장면 × 1 | 20 |
| 실물 시연 | 1~2장면 | |

합은 약 620회(위 일곱 줄만 약 590회)다. 작업 VM 1대가 5개를 병렬로 돌리면 한 회 30~50분이라 4~5일 연속이고, 재실행할 여유가 남는다. 같은 유형의 장면은 좌표만 다른 변형이라 독립 표본이 아니므로 장면을 단위로 센다. 반복은 온도를 정해 두고 2회씩 하며, 이 온도는 동결 전에 정한다.

## 6. 재는 것

- 주 지표는 계획 덮기다: 로봇들의 마지막 선택이 주문을 모두 덮는가. 물리 성공(맞는 표식 앞에 놓음)은 보조로 두고, 계획이 맞았는데 동작이 실패한 실행은 따로 센다.
- 주 비교는 T0 대 T1, T0 대 T2다. 장면 단위로 짝지어 부호 검정을 하고 Holm 으로 보정한다.
- 2대에서 T1 대 T2 는 팀장 지시문 한 줄 차이라서 기술 통계로만 적고, 우열을 주장하지 않는다. 2대의 T2 는 계층 구조가 아니라 지시문의 효과다. 계층 구조라고 말하는 것은 팀장 교대와 3대에서만 한다.
- 논문의 중심은 정답 계획에 못 미친 부분의 원인 분해다: 안 보냄, 늦게 도착, 받고도 무시, 추측. 유의성보다 이 표를 앞에 둔다.
- 결과는 몇 번 중 몇 번으로 적고, 제외한 것과 실패를 함께 적는다.
- 개발 중에 본 장면(X01, L01, C01, D01, X02)은 표시해 두고 주 분석에서 뺀다.

## 7. 지키는 것

- 상자는 자기 카메라로만 찾는다. 정답 좌표, 정적 지도, 접촉력은 로봇에게 주지 않는다(채점에만 쓴다). 벽의 표식은 목적지 표시이고 위치를 맞추는 데 쓰지 않는다.
- 천장 카메라의 측정값은 동작 코드만 쓰고 LLM 에는 주지 않는다. LLM 이 아는 방 이름은 로봇 자기 진행에서만 나온다. 바꾸기 전과 후의 실행은 합산하지 않는다.
- 원칙: LLM 판단에 들어가지 않고 동작 코드에만 쓰이는 정보는 준다. 경기장 모양(벽, 문)은 동작 코드에 준다. 목적지 표식 위치는 주지 않는다(자기 카메라로 찾는다). 실물에서도 얻을 수 있는 것(고정 배치, 천장 카메라 판독)만 준다.
- 실행 규칙(양보, 앞 로봇 정지, 문 앞 다시 보기, 목적지 전 듣기)은 모든 구조에 같다.
- 하지 않는 것: "메시지를 자기 주문보다 우선하라" 같은 신뢰 규칙, 강제 사전 교환 라운드를 본 조건에 넣는 것(별도 절제로만), 결과를 보고 듣기 시간이나 지연을 바꾸는 것, 실패한 장면에 맞춘 프롬프트 예시. 결함 수정과 결과 맞추기를 가른다.
- 팀 구조는 선행 연구의 절차를 따른다(CoELA, Organized Teams, HMAS-2). 이기게 하려고 구조를 손보지 않는다.
- 동결 뒤에는 실행층을 고치지 않는다. 예외는 구조에 따라 다르게 걸리는 실패뿐이다.
- 새 실행 묶음은 한 번 먼저 돌려 보고 넓힌다. 코드가 바뀌면 그 전 코드의 결과와 섞지 않고, 실행마다 어느 코드로 돌았는지 적는다.
- 직접 확인하지 못한 것은 "확인 안 됨"이라고 적는다.

## 8. 버린 것

- 순서 제약 유형과 C3 유형.
- 20장면 × 3회로 180번 돌리는 계획. 같은 유형 장면의 반복은 독립 표본이 아니다.
- 2대에서 T1 이 T2 보다 낫다거나 못하다는 주장.
- 실물 본실험.
- 계획 전용 환경의 결과를 성적으로 쓰는 것.
- 코드 공개 준비와 분석 도구 다듬기는 비교 결과가 나온 뒤로 미룬다.

## 9. 아직 정하지 않은 것

- 두 번째 모델을 어느 것으로 할지(가격을 확인한 뒤 정한다).
- 실물 천장 카메라의 설치(천장 높이와 화각을 모른다. 팔이 윗면 카드를 가리는지도 봐야 한다).
- 실물 시연을 할지, 한다면 누가 맡을지.
