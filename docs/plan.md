# 작업 계획

2026-11-14 정함. 방향을 다시 검토한 결과다. 날짜를 정해 두지 않고 아래 순서대로 되는 대로 빨리 진행한다. 실험 수치와 날마다의 진행은 팀 Linear(UGRP 팀)에 적는다.

## 1. 왜 다시 정했나

연구 질문은 그대로다: 각 로봇이 자기가 본 것만 아는 상황에서, LLM 이 짠 작업 계획이 팀 구조에 따라 어떻게 달라지는가. 바뀌는 것은 그 질문에 답하는 길이다. 지금까지의 진행에 세 가지 문제가 있었다.

| 문제 | 내용 |
|---|---|
| 계획 실험이 팀 구조를 가르지 못한다 | 과제 두 개 모두 움직이는 로봇이 한 대뿐이고 나머지는 알려 주기만 한다. 누가 무엇을 맡을지가 갈리지 않아 팀장과 동등 구조에 차이가 날 수 없다. 통신 없음이 지는 것은 제한 시간을 그렇게 잡았기 때문이다 |
| 계획 실험의 시간이 실제 동작과 다르다 | 계획 전용 환경은 집기 8초, 놓기 6초로 두었는데, 시뮬레이션 실측은 집기까지 약 1분, 옮기기 약 1분 40초다 |
| 계획과 동작이 따로 논다 | LLM 의 선택을 실제 동작으로 넘기는 연결과 여러 로봇이 동시에 움직이는 실행이 없다. 로봇 한 대의 이동을 다듬는 데 시간을 더 쓰는 것은 이 위험을 줄이지 못한다 |

선행 연구와 다른 점은 두 가지에서 나온다: 같은 환경에서 부분 관측과 전체 공개를 나란히 비교하는 것, 그리고 자기 카메라만 쓰는 실제 동작으로 확인하는 것. 계획은 이 둘을 먼저 만든다.

## 2. 이번 제출의 범위

| 항목 | 한다 | 이번에는 하지 않는다 |
|---|---|---|
| 팀 구조 | 통신 없음, 모두 동등, 팀장 있음, 혼합 | 미리 정해 주는 구조 여섯 가지(계층, 역할 분담, 공유 게시판, 입찰, 구역 담당, 스스로 짜기) |
| 관측 조건 | 부분 관측, 전체 공개(대조군) | |
| 과제 | 세 가지: 정보 의존, 문 하나를 여럿이 지나는 좁은 통로, 누가 무엇을 맡을지 정해야 하는 분담 | 나머지 과제 유형 |
| 로봇 수 | 계획 전용 환경 3대(여유가 되면 8대), 시뮬레이션 2–3대 | 16대 이상 |
| LLM | 기본 모델 하나. 더 강한 모델 하나를 일부 조건에 추가(비용 승인 뒤) | |
| 로봇 한 대의 동작 | 지금 수준에서 고정한다. 장면에는 상자만 둔다 | 한 대 이동의 추가 개선 |
| 실물 | 한 대의 집기 시연까지를 목표로 낮춘다 | 3대 협업 시연 |

하지 않는 항목은 [연구 설계](research_design.md)에 남겨 두고, 이번 제출 뒤의 일로 둔다.

## 3. 순서

앞 단계가 끝나는 대로 다음으로 넘어간다. 1–2 와 3 은 나란히 진행한다.

| 순서 | 일 | 끝났다고 보는 기준 |
|---|---|---|
| 1 | 전체 공개 대조군: 지금 과제에서 네 구조를 전체 공개로 돌린다 | 부분 관측과 전체 공개의 표가 같은 장면으로 나란히 나온다 |
| 2 | 계획 전용 환경의 과제를 다시 만든다 | 로봇 2대 이상이 실제로 움직인다. 분담과 문 순서가 결과를 가른다. 행동 시간은 시뮬레이션 실측값이다. 장면은 서로 독립이다. 완료 시간, 헛걸음, 메시지 수를 잰다 |
| 3 | 시뮬레이션에서 로봇 2대가 동시에 움직인다 | 문 하나를 함께 쓰며 각자 상자를 옮겨 놓는다. 서로 부딪히지 않는다. 계획은 고정 순서로 준다 |
| 4 | LLM 계획기의 선택을 시뮬레이션 동작으로 넘긴다 | 과제 한 가지에서 계획기가 고른 행동(집기, 옮기기, 탐색, 메시지)이 실제 동작으로 끝까지 실행된다 |
| 5 | 본 실험 | 계획 전용 환경: 과제 3 × 구조 4 × 관측 2 × 장면 10. 시뮬레이션: 계획 전용 환경에서 차이가 난 조건을 20–30회 |
| 6 | 정리 | 결과, 한계, 영상 |

## 4. 지키는 것

- 로봇이 쓰는 것은 자기 카메라 화면, 자기가 내보낸 명령 기록, 받은 메시지뿐이다. 지도, 벽 표식, 천장 카메라, 상자의 실제 위치는 쓰지 않는다. 전체 공개 조건은 계획 전용 환경의 대조군에만 있다.
- 팀 구조는 선행 연구의 절차를 따른다(CoELA, Organized Teams, HMAS-2). 이기게 하려고 구조를 손보지 않는다.
- 결과는 몇 번 중 몇 번으로 적고, 실패와 제외한 것을 함께 적는다. 직접 확인하지 못한 것은 "확인 안 됨"이라고 적는다.
- 계획이 맞았는데 동작이 실패한 실행은 계획 평가에서 따로 센다.
- 새 실행 묶음은 한 번 먼저 돌려 보고 넓힌다.
