# 작업 계획

2026-11-14 정하고 2026-11-15 두 번 고친 뒤, 2026-11-16 동결 직전에 메시지 규칙, 내려놓기 행동, 지표, 실험 묶음을 확정했다. 실험 수치와 날마다의 진행은 팀 Linear(UGRP 팀)에 적는다. 이 문서는 완성된 설계만 적는다.

## 1. 왜 다시 정했나

연구 질문은 그대로다: 각 로봇이 자기가 본 것만 아는 상황에서, LLM 이 짠 작업 계획이 팀 구조에 따라 어떻게 달라지는가. 바뀐 것은 그 질문에 답하는 길이다.

| 문제 | 내용 | 고친 것 |
|---|---|---|
| 계획 실험이 팀 구조를 가르지 못했다 | 움직이는 로봇이 한 대뿐이었다 | MuJoCo 에서 두 대가 실제로 움직이고, 협동이 필요한 장면을 만든다 |
| 계획 실험의 시간이 실제 동작과 달랐다 | 집기 8초로 두었는데 시뮬레이션 실측은 약 1분이다 | 계획 전용 환경은 접었다 |
| 계획과 동작이 따로 놀았다 | LLM 의 선택을 동작으로 넘기는 연결이 없었다 | 선택대로 움직이는 실행층을 붙였다 |
| 위치를 잘못 알았다 | 바퀴 기록으로 잰 방향이 어긋나고 다른 로봇을 거의 못 찾았다 | 위치는 천장 카메라로 잰다 |
| 이대로 돌리면 대부분 비긴다 (2026-11-15 저녁 점검) | 장면 일부는 구조와 상관없이 같은 선택이 나오게 만들어져 있었다. 2대에서 팀장 구조와 동등 구조는 지시문 한 줄 차이다. 같은 장면의 반복 3회는 표본 3개가 아니다. 계획기의 구현 결함이 LLM 의 한계로 보고될 수 있었다 | 장면을 유형별로 다시 짜고, 계획기 결함을 모든 구조에 같게 고치고, 장면을 단위로 센다 |
| 메시지가 늦게 도착한 실패의 원인을 가를 수 없었다 (2026-11-15 밤) | 옛 규칙은 메시지 보내기가 한 차례를 썼다. 그래서 늦게 도착한 실패가 규칙 탓인지 LLM 판단 탓인지 알 수 없었다 | 메시지를 행동에 덧붙이게 하고, 로봇당 상한을 두고, 많이 말하면 점수를 낮춘다(아래 5·6절) |
| 아무것도 안 하는 선택이 없었다 | 주문에 없는 상자를 집은 로봇이 할 수 있는 것이 옮기는 것뿐이었다 | 든 상자를 내려놓고 끝내는 행동을 모든 구조에 넣었다 |

선행 연구와 다른 점은 LLM 의 계획을 실제로 움직이는 로봇으로 끝까지 실행하고, 계획의 질과 동작의 성패를 나눠 잰다는 데서 나온다.

## 2. 이번 제출의 범위

| 항목 | 한다 | 하지 않는다 |
|---|---|---|
| 환경 | MuJoCo 에서 로봇이 실제로 움직인다(2대 중심). 같은 장치를 실물에도 둔다 | 계획 전용 환경의 결과(성적에는 쓰지 않는다) |
| 위치 측정 | 천장 카메라 1대가 로봇 윗면의 번호 카드를 읽어 모든 로봇의 위치·방향을 잰다. 시뮬레이션도 그린 화면에서 같은 방법으로 읽는다. 동작 코드(이동, 문 통과, 충돌 방지)만 쓴다 | 바퀴 기록만으로 위치 추정, 천장 카메라 값을 LLM 에 주는 것 |
| 누가 무엇을 아나 | LLM 은 자기가 본 상자, 자기 주문, 받은 메시지, 자기 진행에서 아는 방 이름(시작은 상자 방, 자기가 문을 지난 뒤는 목적지 방)만 안다. 주문은 팀 전체의 것이고 개수는 팀 합계라는 것, 주문에 없는 상자를 옮기면 감점이고 할 일이 없으면 끝내도 된다는 것은 모든 구조에 같은 과제 규칙으로 준다 | 다른 로봇의 위치를 주는 것 |
| 팀 구조 | 통신 없음(T0), 모두 동등(T1), 팀장 있음(T2). 3대에서는 팀원이 팀장에게만 보내야 T2 로 센다 | 혼합(T3)은 부록 |
| 메시지 규칙 | 메시지는 행동에 덧붙여 보낸다(차례를 쓰지 않는다). 새 메시지를 받으면 이동 중에도 답장할 기회가 한 번 온다. 로봇당 8개까지. 상한과 "많이 말하면 감점"을 LLM 에 알린다. 자세한 규칙은 [전체 구조 3절](architecture.md#3-llm-계획기) | 메시지를 자기 주문보다 우선하라는 규칙, 강제 사전 교환(별도 절제로만) |
| LLM 이 정하는 것 | 어느 상자, 어느 목적지, 문을 누가 먼저 지날지, 무엇을 알릴지, 든 상자를 내려놓고 끝낼지. 상자는 번호가 아니라 색·방·"내가 든 것/남은 것"으로 부르게 한다. 코드는 몸 움직임의 교착만 모든 구조에 같은 고정 규칙으로 푼다 | 로봇끼리 길을 예약하거나 협상하는 코드 |
| 과제 | 구조 차이가 의미 있는 유형만 둔다(4절). 이번 실험에서 각 로봇은 상자를 **한 번만** 나른다. 상자를 내려놓으면 그 로봇의 실행은 끝난다 | 순서 제약 유형, C3 유형, 돌아가기·두 번 나르기·메시지로 상자 넘겨주기(2단계, 8절) |
| 기준선 | 정답 계획으로 실행한 것(상한), 통신 없음 T0(하한), 모든 로봇이 팀 전체 주문을 자기 주문으로 받는 T1(전체 정보) | |
| 실물 | 대표 장면 1~2개로 같은 장치가 실물에서 도는지 확인. 안 되면 한계에 적는다 | 실물 본실험 |

## 3. 순서와 일정

| 때 | 일 | 끝났다고 보는 기준 |
|---|---|---|
| 동결 전 | 확인 실행으로 계획기·실행층이 모든 조건에서 고장 없이 끝나는지 본다. 정답 계획 기준선 40회로 장면이 물리적으로 풀리는지 본다. 사전 등록을 최신으로 고친다 | 동결 기준은 7절 |
| ~11/17 | 동결: 프롬프트, 실행층, 장면 파일, 분석 코드의 해시를 기록한다. 온도, 반복 횟수, 주 검정, 제외·재실행 규칙은 사전 등록에 적는다(10절의 채울 칸). 반나절쯤 밀릴 수 있다 | 동결 뒤 실행 실패는 고치지 않고 그대로 센다 |
| 11/17~19 | 핵심 묶음 348회(5절) | 중간에 프롬프트를 고치지 않는다 |
| 11/20~22 | 선택 묶음(시간 남는 만큼, 5절 순서)과 고장 칸 재실행 | 늦어도 12/11 전에 실험을 끝낸다 |
| 그 뒤 | 분석, 논문 쓰기, 실물 시연 1~2장면 | |

시간은 가정이다: 작업 VM 두 대에서 동시에 7개 안팎을 돌리고 한 실행이 벽시계로 30~60분이면, 기준선을 뺀 핵심 308회에 약 2~2.5일이 걸린다(재실행 15%를 더해서). 실제 처리량은 첫 묶음을 돌려 본 뒤에 다시 적는다.

3대의 관문: 고정 계획(정답 계획)으로 3대 장면 8개를 돌려 7개 이상 통과해야 한다. 3대는 이번 핵심 묶음에 넣지 않고 선택 묶음의 첫 번째로 둔다. 관문을 넘으면 따로 탐색하고, 못 넘으면 실행층 진단을 2단계로 넘긴다. 선택 묶음의 나머지는 5절의 순서로 더한다.

## 4. 과제 유형

| 유형 | 장면 | 무엇을 보나 |
|---|---|---|
| L (주문 집중) | 12 | 한 로봇이 주문 대부분을 안다. 한 로봇 한 상자 규칙에서는 통신 없이 다 덮을 수 없다 |
| C (같은 색 경쟁) | 12 | 같은 색 상자가 있어 목적지를 맞춰야 한다. 주문 보유자와 정답이 첫째 주문인지를 반반으로 맞춘다 |
| K (능력 제한) | 10 | 로봇마다 집을 수 있는 색이 다르다. 정답이 하나뿐이고 자기 주문만으로는 풀 수 없다 |
| X (대조) | 3 | 통신이 해를 끼치지 않는지 본다. 구조 차이가 나지 않는 것이 정상이다 |
| D (대조) | 3 | 주문 없는 상자를 건드리지 않는지 본다. 내려놓기 선택지가 있어서 "구조 차이 없음"이 아니라 "유인 상자를 옮기지 않는가"를 시험한다. 본 비교에 그대로 두고, 대조 6개(X, D)를 뺀 값도 함께 적는다 |
| 무작위 | 20 | 규칙대로 뽑은 장면. 설계 장면과 합쳐 검정하지 않는다 |
| 3대 (선택) | 7 | K 4, L 3. 정답 계획 관문을 넘을 때만 |

2대 본 비교 장면은 L 12 + C 12 + K 10 + X 3 + D 3 = 40개다. 장면은 번호 규칙으로 정했고, 재생 결과나 구조별 성적을 보고 고르거나 빼지 않았다(구조 차이가 나는 장면만 고르면 검정이 순환이 되기 때문이다). 장면이 되는 조건은 기하 검사 통과뿐이다.

한 로봇은 한 번에 상자 하나만 나른다(여러 번 나르게 하면 통신 없음이 혼자 끝내 차이가 시간으로만 남는다). 주문 없는 로봇이 추측으로 옮긴 것은 "근거 있음/추측"으로 사후에 나눠 따로 센다.

## 5. 실행 횟수

장면 단위로 센다. 같은 유형의 장면은 좌표만 다른 변형이라 독립 표본이 아니다. 반복은 온도 0.7 로 **2회**씩 한다.

**핵심 묶음 (빼지 않는다): 348회**

| 묶음 | 장면 | 구조·조건 | 반복 | 회 | 목적 |
|---|---|---|---|---:|---|
| 정답 계획 기준선 | 본 비교 40장면 | 정답 계획. LLM 없이 같은 실행층 | 1 | 40 | 실행층 실패율(분모), 계획 실패 대 물리 실패 분리 |
| 본 비교 A | 2대 40장면 | T0, T1, T2 | 2 | 240 | 주 검정, 원인 분해 |
| 전체 정보 | 본 비교 40장면을 [L, C, X, D, K 순, 번호 순]으로 늘어놓은 홀수 번째 20장면 | T1 + 모든 로봇이 팀 전체 주문을 자기 주문으로 받는다. 과제 문장은 그대로(조건 차이를 정보 하나로 둔다) | 1 | 20 | 정답 계획과의 간격이 정보 전달 탓인가 모델 추론 탓인가 |
| 순서 편향 | C 4장면 | T0. 선택지 목록 순서만 뒤집고 주문 순서는 그대로 | 2 | 8 | 주문 보유자의 첫 선택 편향 |
| 절제 2종 | L 5 + C 5장면 | T1. ① 목적지 재결정 끔 ② 사전 교환(실행 전에 서로 한 번 알림) 각 20회 | 2 | 40 | 늦게 도착이 진짜 원인이면 사전 교환에서 줄어야 한다. 대조는 본 비교 A 의 T1 |

40 + 240 + 20 + 8 + 40 = 348.

**선택 묶음 (시간 남으면): 242회. 뺄 때는 위에서부터**

| 빼는 순서 | 묶음 | 장면 | 구조·조건 | 회 |
|---|---|---|---|---:|
| 1 | 3대 | K 4 + L 3 = 7장면 | T0, T1, T2(팀원은 팀장에게만) × 2. 정답 계획 관문을 넘을 때만 | 42 |
| 2 | 듣기 0초 절제 | L 5 + C 5장면 | T1, 목적지 전 듣기를 끔 × 2 | 20 |
| 3 | 무작위 기준선 | 무작위 20장면 | 정답 계획 × 1 | 20 |
| 4 | 무작위 | 무작위 20장면. 설계 장면과 합치지 않고 따로 보고 | T0, T1, T2 × 1 | 60 |
| 5 | 두 번째 모델 | 전체 정보와 같은 20장면 | T0, T1, T2 × 1, 모델 `qwen/qwen3-235b-a22b-2507` | 60 |
| 6 | 팀장 교대 | L 10 + C 10장면(주문 보유자가 r1, r2 인 장면 각 10) | T2, 팀장을 r2 로 × 2 | 40 |

42 + 20 + 20 + 60 + 60 + 40 = 242. 핵심과 선택을 합치면 590회다. 시간이 남아 더할 때는 위의 반대 순서로 더한다: 팀장 교대, 두 번째 모델, 무작위(와 그 기준선), 듣기 0초.

설계 40, 무작위 20, 3대, 두 번째 모델은 서로 합쳐 검정하지 않는다. 팀장 교대와 3대에서만 "계층 구조"라는 말을 쓴다.

## 6. 재는 것

- **주 지표는 둘이다(사전 등록).**
  - **계획 덮임 C**: 로봇들의 마지막 선택(색, 표식)이 장면 주문과 정확히 같으면 1, 아니면 0. 남는 선택도 0이다. 내려놓고 끝내기는 빈 선택으로 읽는다.
  - **메시지 벌점 점수 SP**: C 에서 "허용보다 많이 보낸 메시지 수"에 비례해 깎는다. 기본 λ=0.02, 민감도 λ=0.05, 0.10. 통신 없음 T0 는 깎이지 않아 SP=C 다. 정의와 판정은 [연구 설계 11절](research_design.md#11-이번-제출의-동결-설계-2026-11-16)에 있다.
- 물리 성공(맞는 표식 앞에 놓음)은 보조로 두고, 계획이 맞았는데 동작이 실패한 실행은 따로 센다.
- 주 비교는 T0 대 T1, T0 대 T2다. 장면 단위로 짝지어, C 는 부호 검정과 Holm 보정, SP 는 평균 차이와 부트스트랩 구간으로 판정한다.
- 2대에서 T1 대 T2 는 팀장 지시문 한 줄 차이라서 기술 통계로만 적고, 우열을 주장하지 않는다. 2대의 T2 는 계층 구조가 아니라 지시문의 효과다.
- 본문의 중심은 네 가지다. ① 정답 계획에 못 미친 몫의 원인 분해(안 보냄, 늦게 도착, 받고도 무시, 추측 등) ② 전체 정보를 준 LLM 과의 대비 ③ 계획 실패와 물리 실패의 분리 ④ 개입으로 원인 확인(사전 교환, 재결정 끔). 통신을 켜면 T0 와 달라지는지(H1, H2)는 "통신 조작이 먹혔는지 확인"으로 한 문단만 쓴다. 정보가 없는 쪽이 못 하는 것은 장면 설계의 성질이라 자명할 수 있기 때문이다.
- 결과는 몇 번 중 몇 번으로 적고, 제외한 것·실패·재실행을 함께 적는다.
- 개발 중에 본 장면(X01, L01, C01, D01, X02)은 표시해 두고 주 분석에서 뺀다.

## 7. 지키는 것

- 상자는 자기 카메라로만 찾는다. 정답 좌표, 정적 지도, 접촉력은 로봇에게 주지 않는다(채점에만 쓴다). 벽의 표식은 목적지 표시이고 위치를 맞추는 데 쓰지 않는다.
- 천장 카메라의 측정값은 동작 코드만 쓰고 LLM 에는 주지 않는다. LLM 이 아는 방 이름은 로봇 자기 진행에서만 나온다. 바꾸기 전과 후의 실행은 합산하지 않는다.
- 원칙: LLM 판단에 들어가지 않고 동작 코드에만 쓰이는 정보는 준다. 경기장 모양(벽, 문)은 동작 코드에 준다. 목적지 표식 위치는 주지 않는다(자기 카메라로 찾는다). 실물에서도 얻을 수 있는 것(고정 배치, 천장 카메라 판독)만 준다.
- 실행 규칙(양보, 앞 로봇 정지, 문 앞 다시 보기, 목적지 전 듣기)은 모든 구조에 같다.
- 하지 않는 것: "메시지를 자기 주문보다 우선하라" 같은 신뢰 규칙, 강제 사전 교환 라운드를 본 조건에 넣는 것(별도 절제로만), 결과를 보고 듣기 시간이나 지연을 바꾸는 것, 실패한 장면에 맞춘 프롬프트 예시. 결함 수정과 결과 맞추기를 가른다.
- 팀장 지시문은 선행 연구(Organized Teams)를 참고했다. 메시지 규칙은 우리 것이라 "CoELA 방식 통신"이라고 부르지 않는다.
- **동결 기준**(전부 충족해야 동결한다): 확인 실행이 고장 없이 끝남(점수는 기준이 아님) / 확인 실행 18회 중 멈춤·형식 오류가 2회 이하(3회 이상이면 온도를 0.0 으로 되돌린다) / 조건 스위치 4종(사전 교환, 순서 뒤집기, 전체 정보, 재결정 끔)이 끝까지 돎 / 분석 코드가 새 기록으로 끝까지 돎 / 사전 등록에 낡은 줄이 없음. 정답 계획 기준선 40 중 물리 실패가 사전 지정 문턱(8) 이상이면 본 비교 전에 멈추고 실행층을 검토한다. 기준선이 실패했다고 장면을 빼지는 않는다(C 는 계획 지표라 물리 실패와 무관하다).
- **변경 중지선**: 동결 전 마지막 확인 뒤에는 프롬프트 문구, 메시지 규칙(상한, 기회 조건, 지연), 벌점의 허용·λ, 행동 선택지, 덮임 판정 규칙, 장면 파일, 정답 계획 코드를 고치지 않는다. 고쳐도 되는 것은 분석 전용 꼬리표와 표, 문서, 스케줄러 고장뿐이다.
- 동결 뒤에는 프롬프트와 실행층을 고치지 않는다. 예외는 구조에 따라 다르게 걸려 실행이 죽는 고장뿐이다. 예외를 쓰면 날짜, 이유, 새 해시를 사전 등록에 더하고 이전 코드 결과와 합치지 않는다.
- **재실행 규칙(사전 고정)**: 재실행은 고장 칸에만 1회 한다(프로세스 충돌, 시간 상한 초과, 계획기 응답 오류로 멈춤, 호출·지출 가드). 점수가 나쁘다는 이유로 재실행하지 않는다. 틀린 선택, 문 교착, 시간 상한 도달, 집기 실패, 메시지 상한 도달은 고장이 아니라 결과다. 첫 기록은 지우지 않고 둘 다 남기고, 또 고장이면 실패로 남긴다. 실패 칸은 기본으로 C=0, 민감도로 "제외"와 "성공으로 셈" 둘을 더 보고한다.
- 새 실행 묶음은 한 번 먼저 돌려 보고 넓힌다. 코드가 바뀌면 그 전 코드의 결과와 섞지 않고, 실행마다 어느 코드로 돌았는지 적는다.
- 직접 확인하지 못한 것은 "확인 안 됨"이라고 적는다.

## 8. 2단계 (예고)

본 실험의 동결 코드와 **따로** 개발한다. 본 실험의 실행 자원을 먼저 쓰게 하고, 2단계에서 찾은 결함을 동결 코드에 되넣지 않는다. 결과는 본 실험과 합치지 않는다. 논문에 넣을지는 핵심 묶음이 끝난 뒤에 정한다.

| 항목 | 내용 |
|---|---|
| 돌아가기, 두 번 나르기 | 한 번 나른 로봇이 자기 방으로 돌아와 다시 나른다. 이번 실험의 "로봇마다 한 번 운반"을 푸는 것이다 |
| 중간 이동 행동 | LLM 이 물러나기, 비켜 주기, 둘러보기, 상자 방으로 돌아가기 같은 중간 단계 행동을 고른다. 실제 움직임은 코드가 한다. 바퀴 명령을 직접 고르게 하지 않는다 |
| 메시지로 넘겨주기 | 상자 일을 메시지로 다른 로봇에게 넘기는 것. 설계는 2단계에서 정한다 |
| 3대 실행 고치기 | 정답 계획으로도 3대가 풀리지 않는 실행층 결함을 찾아 고친다 |

## 10. 동결 기록과 아직 정하지 않은 것

동결 때 채우는 칸이다. 채우기 전에는 이 설계가 동결된 것이 아니다.

| 칸 | 값 |
|---|---|
| 동결 시각 | 동결 때 채움 |
| 실행 코드 판(해시) | 동결 때 채움 |
| 계획기 버전과 해시 | 동결 때 채움 |
| 분석 코드 해시 | 동결 때 채움 |
| 장면 파일과 실행 목록(매니페스트) 해시 | 동결 때 채움 |
| 사전 등록 문서 | 동결 때 채움 |

동결하는 고정값은 다음과 같다.

| 값 | 고정값 |
|---|---|
| 모델 | `z-ai/glm-5.3-flash`. 두 번째 모델(선택 묶음)은 `qwen/qwen3-235b-a22b-2507` |
| 온도 | 0.7, 모든 구조·조건 같음. 0.7 에서 확인 실행 18회 중 멈춤·형식 오류가 3회 이상이면 0.0 으로 되돌린다는 사전 조건을 둔다. 0.0 이면 응답 캐시가 켜진다 |
| 출력·호출 상한 | 한 답 2048 토큰, 로봇당 호출 150, 실행당 호출 300 |
| 시간 상한 | 실행당 900초 |
| 메시지 | 로봇당 8개, 전달 지연 2초, 허용 로봇당 2개, λ 0.02 |
| 목적지 듣기 | 번호가 높은 로봇이 4초씩 더 듣고 고른다. 통신 없음에도 같다 |

- 실물 시연을 할지, 한다면 누가 맡을지.
- 2단계 결과를 논문에 넣을지(핵심 묶음이 끝난 뒤에 정한다).
