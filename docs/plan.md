# 작업 계획

2026-11-14 정하고 2026-11-15 고쳤다(천장 카메라 위치 측정, 과제·규모). 날짜를 정해 두지 않고 아래 순서대로 되는 대로 빨리 진행한다. 실험 수치와 날마다의 진행은 팀 Linear(UGRP 팀)에 적는다.

## 1. 왜 다시 정했나

연구 질문은 그대로다: 각 로봇이 자기가 본 것만 아는 상황에서, LLM 이 짠 작업 계획이 팀 구조에 따라 어떻게 달라지는가. 바뀌는 것은 그 질문에 답하는 길이다. 지금까지의 진행에 세 가지 문제가 있었다.

| 문제 | 내용 |
|---|---|
| 계획 실험이 팀 구조를 가르지 못한다 | 과제 두 개 모두 움직이는 로봇이 한 대뿐이고 나머지는 알려 주기만 한다. 누가 무엇을 맡을지가 갈리지 않아 팀장과 동등 구조에 차이가 날 수 없다. 통신 없음이 지는 것은 제한 시간을 그렇게 잡았기 때문이다 |
| 계획 실험의 시간이 실제 동작과 다르다 | 계획 전용 환경은 집기 8초, 놓기 6초로 두었는데, 시뮬레이션 실측은 집기까지 약 1분, 옮기기 약 1분 40초다 |
| 계획과 동작이 따로 논다 | LLM 의 선택을 실제 동작으로 넘기는 연결과 여러 로봇이 동시에 움직이는 실행이 없다. 로봇 한 대의 이동을 다듬는 데 시간을 더 쓰는 것은 이 위험을 줄이지 못한다 |

선행 연구와 다른 점은 LLM 의 계획을 실제로 움직이는 로봇으로 끝까지 실행하고, 계획의 질과 동작의 성패를 나눠 잰다는 데서 나온다.

## 2. 이번 제출의 범위

2026-11-15 다시 고쳤다. 첫 LLM 실행 세 번(통신 없음, 모두 동등, 팀장 있음)이 모두 동작 실패(먼 상자 집기 실패, 로봇끼리 충돌, 빈손 운반)로 끝나 계획의 차이를 볼 수 없었다. 실패 원인의 대부분은 로봇이 자기 위치·방향을 잘못 알고(상자 둘레를 돈 뒤 50~150° 어긋남) 다른 로봇을 보지 못하는 것(색 규칙으로 17%만 찾음)이었다. 그래서 위치는 천장 카메라로 재고, 연구 질문은 과제 정보에 집중한다. 소형 로봇 여러 대를 쓰는 연구실이 흔히 쓰는 방식이다(천장 카메라와 로봇 몸의 번호 표식).

| 항목 | 한다 | 이번에는 하지 않는다 |
|---|---|---|
| 환경 | MuJoCo 에서 로봇이 실제로 움직인다. 같은 장치를 실물에도 둔다 | 계획 전용 환경의 결과(장면이 구조를 가르는지 미리 걸러 보는 데만 쓸 수 있다) |
| 위치 측정 | 천장 카메라 1대(경기장 가운데 위, 높이 약 2.5 m, 1280×960)가 로봇 윗면의 번호 카드(8.5 cm)를 읽어 모든 로봇의 위치·방향을 잰다. 시뮬레이션도 정답 좌표를 바로 주지 않고, 그린 화면에서 같은 방법으로 읽는다 | 바퀴 명령 기록만으로 자기 위치 추정 |
| 누가 무엇을 아나 | 동작 코드(이동, 문 통과, 충돌 방지)는 자기 위치와 모든 로봇 위치를 쓴다. LLM 은 자기 위치, 자기 카메라로 본 상자, 과제가 준 자기 주문, 받은 메시지만 안다 | LLM 에 다른 로봇의 위치를 주는 것 |
| 팀 구조 | 통신 없음, 모두 동등, 팀장 있음 | 혼합(중앙 초안+검토)은 부록. 계획 전용 환경에서 모든 정보를 줘도 0/12 였다 |
| LLM 이 정하는 것 | 어느 상자, 어느 목적지, 문을 누가 먼저 지날지, 무엇을 알릴지. 코드는 부딪히려 할 때 멈추는 안전장치만 한다 | |
| 목적지 | 벽에 붙인 번호 표식 앞 | 바닥 색 구역 |
| 과제 | 구조 차이가 나도록 만든다: 주문을 아는 로봇이 그 상자에서 멀게 두기, 문을 서로 반대 방향으로 지나야 하게 두기, 한 로봇만 아는 순서·자리 제약, 주문에 없는 상자, 한쪽에 주문을 몰아 주기 | 각자 자기 주문만으로 할 일이 정해지는 장면(첫 실행 장면은 세 구조가 같은 선택을 했다) |
| 기준선 | 모든 정보를 아는 계획자 하나(상한)와 통신 없음(하한). 둘의 차이가 작은 장면은 버린다 | |
| 규모 | 같은 장면 20개를 모든 구조에, 장면마다 3회: 3 × 20 × 3 = 180회. 한 회 30~50분, 작업 VM 1대로 3~4일 | |
| 재는 것 | 맞게 놓은 상자 수, 상한 대비 배정 정확도, 완료 시간, 메시지·LLM 호출 수, 문 앞 대기, 헛걸음(빈손 운반, 겹친 운반), 제약 위반. 전체 실행 기준과 동작 실패를 뺀 계획 기준을 함께 적는다 | 성공/실패 하나만 보기 |
| 실물 | 대표 장면 3~5개로 같은 장치가 실물에서 도는지 확인 | 실물 본실험 |

## 3. 순서

앞 단계가 끝나는 대로 다음으로 넘어간다.

| 순서 | 일 | 끝났다고 보는 기준 |
|---|---|---|
| 1 | 천장 카메라 위치 측정을 실행기에 붙인다 (만드는 기한 3~4일) | 로봇 위치·방향이 실행 내내 측정되고, 동작 코드가 그것으로 움직인다 |
| 2 | 집기 확인과 다시 집기 | 들었는지 자기 카메라로 확인하고, 빈손이면 계획기에 알리고 다시 고른다 |
| 3 | 기준 계획으로 신뢰도 확인 | 고정 계획 2대 실행 10번 중 9번 이상 성공 |
| 4 | 구조가 갈리는 장면 만들기와 파일럿 | 구조마다 3~4장면에서 차이가 나는지 확인 |
| 5 | 본 비교 180회 | 위 지표를 장면별로 짝지어 비교 |
| 6 | 실물 확인과 정리 | 대표 장면 3~5개, 결과·한계·영상 |

## 4. 지키는 것

- 상자는 자기 카메라로만 찾는다. 정답 좌표, 정적 지도, 접촉력은 로봇에게 주지 않는다(채점에만 쓴다). 벽의 표식은 목적지 표시이고 위치를 맞추는 데 쓰지 않는다.
- 천장 카메라의 측정값은 동작 코드만 쓰고 LLM 에는 자기 위치만 준다.
- 팀 구조는 선행 연구의 절차를 따른다(CoELA, Organized Teams, HMAS-2). 이기게 하려고 구조를 손보지 않는다.
- 결과는 몇 번 중 몇 번으로 적고, 실패와 제외한 것을 함께 적는다. 직접 확인하지 못한 것은 "확인 안 됨"이라고 적는다.
- 계획이 맞았는데 동작이 실패한 실행은 계획 평가에서 따로 센다.
- 새 실행 묶음은 한 번 먼저 돌려 보고 넓힌다.

## 5. 아직 정하지 않은 것

- 더 강한 두 번째 모델을 어느 것으로 할지(비용은 잔액 안에서 판단하기로 함).
- 실물 천장 카메라 설치(천장 높이, 카메라 화각, 팔이 윗면 카드를 가리는지).
- 실물 시연을 할지, 한다면 누가 맡을지.
