# 아키텍처 단순화 검토 (2026-11-18, 읽기 전용)

코드는 하나도 고치지 않았다. 작업 서버(2차 코드)와 GitHub main(1차 판)을 읽었다. 근거(파일:줄)는 VM의 `/tmp/arch-review-findings.txt`.

## 결론
복잡한 게 맞다. 다만 복잡한 곳은 대부분 결과에 영향이 없는 겉층(옵션, 사본, 실행 경로 중복, 옛 연구 코드)이다. 그래서 결과를 바꾸지 않고 줄일 여지가 크다.

## 무엇이 불필요한가

| 영역 | 지금 | 불필요한 부분 |
|---|---|---|
| 계획기 | 3,661줄 (1차 1,941줄에서 89% 증가) | `protocol.py` 444줄은 2차에서 한 번도 안 켜짐(RoCo·HMAS 흉내) |
| 계획기 옵션 | 45개 | 약 20개는 2차에서 안 씀(T0/T3, 메시지 한도 8, pre-exchange). 11개는 80행 모두 같은 값 |
| 실행층 옵션 | 37개 | 19개는 2차에서 안 씀. 11개는 80행 모두 같은 값 |
| 실행층 코드 | 실제 불러오는 범위 약 169파일·5.2만 줄(정적 추정) | 옛 연구(pair, solo-cyan, M1/M2) 모듈이 import 사슬로 딸려 옴. 핵심 함수 `run_steps` 하나가 1,106줄·인자 34개, 기본 꺼진 기능마다 파일 경로로 따로 불러옴 |
| 실행 경로 | 디스패처 3겹(cr_dispatch_p2 → cr_dispatch → dispatch) → Cloud Run 작업 스크립트 → 래퍼 → run_team_carry | VM 길이 같은 순서를 셸 스크립트로 한 번 더 구현 |
| 사본 | brain_server.py 24개, run_team_carry.py 18개, worktree 6개, `.bak` 30개 | 어느 게 진짜인지 헷갈리고 한쪽만 고치는 사고 위험 |

## 단순화 제안 (위험 낮은 순)

| # | 제안 | 동작 변화 | 지금 해도 되나 |
|---|---|---|---|
| 1 | 매니페스트를 3대/6대 최종 설정으로 다시 만들기 | 의도대로 맞춤(아래 불일치 해결) | **지금 필요** |
| 2 | 늘 같은 값인 옵션을 기본값으로 굳히고 CLI에서 빼기 | 없음(바이트 동일 확인 가능) | 실험 뒤 |
| 3 | 안 쓰는 1차 경로(protocol, 메시지 한도, T0/T3) 떼기 | 2차 결과엔 없음. 1차 재현은 태그로 | 실험 뒤 |
| 4 | Cloud Run 스크립트와 VM 스크립트가 같은 실행 함수 하나를 부르게 | 없어야 함, 비교 실행 필요 | 실험 뒤 |
| 5 | 사본·`.bak` 정리, 계획기 원본 하나만 | 없음 | 실험 뒤 |
| 6 | 옛 연구 모듈 import 끊기, `run_steps` 쪼개기 | 실행층을 건드림, 바이트 동일 검증 필수 | 실험 뒤, 가장 마지막 |

1번 외에는 11/22 실험이 끝난 뒤가 안전하다. 지금 실행층 폴더(student-opt)에서 다중 운반 작업이 진행 중이라 동시에 고치면 충돌한다.

## 지금 바로 고쳐야 할 불일치 (복잡도와 별개, 실험에 영향)
- 매니페스트가 아직 9대 기준이고, Cloud Run 디스패처는 3대·9대만 알아서 6대 작업이 없다.
- 확정한 옵션 `--zone-confirm-close`, `--multi-carry`가 매니페스트에 없다.
- 커밋이 세 곳에서 다르다: 매니페스트 946d966, 이미지 faf26b9, 다중 운반 작업은 진행 중.
- 매니페스트의 `--leader-bind`는 이름이 틀렸고 파이썬 약어 기능 덕에 우연히 동작한다.
