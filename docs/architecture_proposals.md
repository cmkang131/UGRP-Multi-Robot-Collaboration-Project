# 구조 개선 제안

2026-11-17 [전체 구조](architecture.md)를 동결 판에 맞춰 다시 쓰며 찾은 것이다. 실험이 도는 동안은 실행층 코드, 계획기, 동결 기록을 고치지 않으므로 실험과 실험 사이에 처리한다. 위에서부터 중요한 순서다.

| # | 지금 상태 | 왜 문제인가 | 제안 |
|---|---|---|---|
| 1 | 실행층은 따로 둔 작업 저장소(커밋 `ceed05f`)에서 고치고, GitHub 에는 파일을 손으로 복사해 올린다. `main` 은 v37 이고 v38 의 옆걸음 다시 보기가 없다 | 저장소만 보는 사람은 본 실험이 쓴 코드를 재현할 수 없다. 커밋 번호도 GitHub 에서 찾을 수 없다 | 실험 뒤 v38 을 `main` 에 올리고, 동결 판에 태그(예: `freeze-3r-20261117`)를 단다. 작업 저장소 커밋 번호와 GitHub 커밋의 대응표를 태그 설명에 적는다 |
| 2 | 저장소 `prereg/` 에 D12(과제 문장), D13(주 지표 R), D14(v38)가 없다. 동결 해시를 기록한 사전 등록 문서는 작업 서버에만 있다 | 주 지표가 바뀐 사실과 그 이유가 공개 기록에 없다 | 동결 해시를 기록한 그 문서를 바이트 그대로 `prereg/` 에 올리고, 해시 파일의 sha256 과 같은지 PR 에 적는다 |
| 3 | 계획기가 세 곳에 있다(작업 서버의 1차 원본, 2차 사본, 저장소 `team/` 의 1차 판). 2차 사본의 프로토콜·선출·손실·고장 스위치는 저장소에 없다 | 한쪽만 고치는 사고가 나기 쉽다 | 저장소 `team/` 을 원본으로 삼고 작업 서버는 그것을 받아 쓰게 한다. 기록 폴더는 환경 변수 하나로 고른다(저장소 판이 이미 그렇게 되어 있다) |
| 4 | Cloud Run 길(`cr_dispatch.py`, 컨테이너 진입점 `cr_task.py`, 이미지 빌드)이 저장소에 없다. `cr_task.py` 는 VM 실행 스크립트의 순서를 다시 구현했다 | 두 길이 어긋나도 알아채기 어렵다(지금은 빌드 때 VM 스크립트와 같은지 비교해서 막는다) | `batch/cloudrun/` 으로 올리고, VM 길과 Cloud Run 길이 같은 실행 함수 하나를 부르게 바꾼다. 내부 주소·프로젝트 이름은 설정 파일로 뺀다 |
| 5 | 판마다 스크립트 이름을 바꾸고(`run_team_v36.sh`, `v37`, `v38`), 고치기 전 사본을 `.bak-날짜` 파일로 둔다 | 무엇이 바뀌었는지 git 이력으로 볼 수 없다 | 스크립트는 하나로 두고 판은 git 태그와 실행 기록의 코드 해시로 가린다. `.bak` 파일은 git 이력으로 대신한다 |
| 6 | `docs/` 에 문서가 90개 넘게 있고, 날짜가 지난 현황·계획 문서가 현재 문서와 섞여 있다 | 처음 보는 사람이 무엇이 현재인지 모른다 | 현재 문서(README, 전체 구조, 실행층, 계획기와 메시지 규칙, 연구 설계, 지금 하는 일)만 `docs/` 맨 위에 두고 나머지는 `docs/archive/` 로 옮긴다 |
| 7 | [연구 설계 11절](research_design.md#11-이번-제출의-동결-설계-2026-11-16)과 [작업 계획](plan.md)은 2대 기준 숫자(348회, C·SP)를 아직 담고 있다. 이번에는 연구 설계 11절 머리에 안내만 달았고 작업 계획은 고치지 않았다 | 숫자가 서로 다르다 | 실험 결과를 쓸 때 3대 기준으로 다시 쓴다 |
