# 연구 설계: 부분 관측에서 LLM 다중 로봇 협업의 팀 구조 비교

2026-11-13 초안. 2026-11-16 에 이번 제출의 동결 설계(11절)를 더했다. 1~10절은 넓은 설계이고, 이번 제출에서 실제로 하는 범위와 지표는 [작업 계획](plan.md)과 11절이 우선한다. 가설과 선행 연구와의 차이는 선행 연구 조사가 끝나면 고친다.

## 0. 방향 (2026-11-13 정함)

> 2026-11-16: 이번 제출에서 실제로 하는 범위와 순서는 [작업 계획](plan.md)에서 줄였다. 구조는 T0·T1·T2(혼합 T3 와 미리 정해 주는 구조 W1–W6 은 하지 않는다), 과제는 주문 집중·같은 색 경쟁·능력 제한과 대조 장면, 로봇은 MuJoCo 2대 중심이며 3대는 정답 계획 관문을 넘을 때만 탐색한다. 계획 전용 환경(6절의 L0)은 접었다. 이 문서의 1~10절은 전체 설계로 남긴다.

이 문서의 나머지는 아래 결정을 풀어 쓴 것이다.

- **중심은 LLM 이 짠 작업 계획의 평가다.** 집기·옮기기 동작은 그 실험을 실제로 돌리기 위한 기반이다.
- **바탕 조건은 부분 관측이다.** 물체의 위치를 다 아는 조건이 아닐 때 어떻게 되는지를 본다.
- **질문은 팀 구조다.** 누가 팀장을 맡는 것이 효율적인가, 모두 동등한 것이 효율적인가.
- **팀 구조와 보고 체계를 미리 정해 주는 방식도 비교한다.** 팀장·동등 두 가지에 그치지 않고, 작업 흐름 구조나 팀 운영 요령을 LLM 에 미리 제시한다. LLM 팀이 과제를 보고 구조를 스스로 짜는 방식도 넣는다.
- **협업이 꼭 필요한 과제를 여러 구조로 만든다.** 정보 의존, 좁은 통로, 어려운 길, 순서 제약, 능력 차이, 로봇별 지정 구역, 그리고 그 밖의 것들.
- **로봇 수는 실물 3대, 시뮬레이션은 32대·64대까지 늘린다.**
- **논문보다 도전적인 학생 실험이 목표다.** 안전한 비교 하나보다 새 구조를 넓게 시도한다.
- **두 로봇이 한 물체를 맞잡아 옮기는 과제(Pair)는 연구에서 뺀다.** 위 과제들은 모두 혼자 집어 옮기는 동작만으로 된다.

## 1. 한 줄 요약
각 로봇이 자기가 본 것만 아는 상황에서, LLM 이 짠 작업 계획이 팀 구조(통신 없음, 모두 동등, 팀장 있음, 혼합)에 따라 얼마나 달라지는지를, 협업이 필요한 이유가 서로 다른 과제들에서 비교한다.

## 2. 연구 질문과 가설
| 번호 | 질문 | 가설 (틀릴 수 있음) |
|---|---|---|
| Q1 | 부분 관측에서 어느 팀 구조가 효율적인가 | 전체를 아는 조건에서 보고된 "팀장·중앙 계획 우세"가 부분 관측에서는 줄거나 뒤집힌다. 팀장도 전체를 모르고 보고를 기다려야 하기 때문 |
| Q2 | 협업이 필요한 이유에 따라 유리한 팀 구조가 달라지는가 | 정보를 나눠야 하는 과제는 동등 구조가, 순서와 시간을 맞춰야 하는 과제는 팀장 구조가 유리하다 |
| Q3 | 동작이 실패하거나 상황이 바뀌면 어느 구조가 빨리 회복하는가 | 동등 구조는 빨리 반응하지만 중복이 생기고, 팀장 구조는 느리지만 중복이 적다 |
| Q4 | 위 결론이 실제 동작과 실제 카메라 인식에서도 유지되는가 | 방향은 유지되지만 차이의 크기는 줄어든다 |
| Q5 | 구조를 미리 정해 주면 LLM 끼리 알아서 정하는 것보다 나은가 | 과제에 맞는 구조를 주면 낫고, 맞지 않는 구조를 주면 자유 대화보다 못하다 |
| Q6 | 로봇 수가 늘면 유리한 구조가 바뀌는가 | 동등 구조는 로봇 수가 늘수록 메시지가 급히 늘어 느려지고, 조를 나눈 계층 구조가 유리해진다 |
| Q7 | LLM 팀이 과제를 보고 구조를 스스로 고르면 고정 구조만큼 하는가 | 과제 유형이 섞여 있을 때 스스로 고르는 쪽이 유리하다 |

## 3. 바꾸는 것 (독립 변수)

### 3.1 팀 구조: 기본 4가지
| 기호 | 이름 | 내용 |
|---|---|---|
| T0 | 통신 없음 | 각 로봇의 LLM 이 자기 관측만으로 계획한다. 기준선 |
| T1 | 모두 동등 | 로봇끼리 자유롭게 메시지를 주고받아 정한다 |
| T2 | 팀장 있음 | 한 로봇이 팀장이다. 나머지는 본 것을 보고하고 팀장의 지시를 따른다. 팀장도 자기 카메라만 본다 |
| T3 | 혼합 | 팀장이 계획 초안을 내고, 팀원이 한 번 이의를 낼 수 있다 |

### 3.2 미리 정해 주는 구조와 요령

기본 4가지는 "누가 정하는가"만 다르다. 여기서는 일하는 방식 자체를 미리 정해 LLM 에 준다.

| 기호 | 이름 | 내용 | 유리할 것으로 보는 곳 |
|---|---|---|---|
| W1 | 계층 | 팀장 아래 조장, 조장 아래 조원. 보고는 한 단계 위로만 한다 | 로봇이 많을 때 |
| W2 | 역할 분담 | 찾는 로봇, 옮기는 로봇, 조정하는 로봇으로 나눈다 | 정보 의존, 능력 차이 |
| W3 | 공유 게시판 | 대화 없이 본 것과 맡은 일을 한 게시판에 적고, 거기서 일을 가져간다 | 같은 목표 겹침, 낡은 정보 |
| W4 | 입찰 | 일이 생기면 각자 드는 비용을 내고 가장 적게 드는 로봇이 맡는다 | 일이 많고 서로 독립일 때 |
| W5 | 구역 담당 | 구역마다 책임 로봇을 두고, 경계에서만 대화한다 | 지정 구역, 좁은 통로 |
| W6 | 스스로 짜기 | 팀이 과제를 보고 위 구조 가운데 하나를 고르거나 새로 짠 뒤 시작한다. 도중에 바꿀 수 있다 | 과제 유형이 섞여 있을 때 |

팀 운영 요령은 구조와 따로 켜고 끌 수 있는 짧은 규칙 묶음이다. 예: "새로 본 것은 바로 알린다", "남이 맡은 상자에는 가지 않는다", "정해진 시간 넘게 막히면 보고한다", "받은 정보에는 본 시각을 붙인다". 같은 구조에서 요령이 있을 때와 없을 때를 비교한다.

### 3.3 관측 조건 (2가지)
| 기호 | 내용 | 쓰임 |
|---|---|---|
| P | 부분 관측: 자기가 본 것만 안다 | 본 실험 |
| F | 전체 공개: 모든 상자·로봇 위치를 처음부터 안다 | 선행 연구 조건을 우리 환경에서 재현하는 비교군. Q1 의 "뒤집히는가"를 같은 환경에서 보여 준다 |

### 3.4 협업 구조 (과제 유형)
중심 여섯 가지와 추가 후보. 모두 혼자 집어 옮기는 동작만으로 된다.

| 번호 | 이름 | 협업이 필요한 이유 | 예시 장면 | 통신이 없으면 |
|---|---|---|---|---|
| C1 | 정보 의존 | 한 로봇이 본 것을 다른 로봇이 알아야 일이 된다 | 주문 내용(색, 개수, 구역)을 로봇마다 일부만 안다. 또는 A 가 본 상자를 B 가 옮겨야 한다 | 전부 뒤지거나 틀린 곳에 놓음 |
| C2 | 좁은 통로 | 한 번에 한 대만 지나간다 | 방 사이 문, 좁은 복도에서 마주침 | 서로 막고 기다림 |
| C3 | 어려운 길 | 길이 막혔거나 돌아가야 한다. 누군가 치우거나 길을 알려 줘야 한다 | 통로를 막은 상자, 한 로봇만 본 우회로 | 막힌 쪽이 직접 치우느라 자기 일을 못 함 |
| C4 | 순서 제약 | 정해진 순서로 놓아야 한다 | 빨강이 먼저 놓여야 파랑을 놓을 수 있다 | 들고 기다리거나 규칙 위반 |
| C5 | 능력 차이 | 로봇마다 할 수 있는 일이 다르다 | 빨강만 집는 로봇과 파랑만 집는 로봇. 넓게 보지만 못 집는 로봇 | 자기 것을 찾을 때까지 혼자 탐색 |
| C6 | 로봇별 지정 구역 | 로봇마다 들어갈 수 있는 곳이 다르다. 경계에서 넘겨줘야 한다 | A 는 1번 방, B 는 2번 방만. 문 앞 넘김 자리에 놓으면 다음 로봇이 집어 감 | 넘김 자리를 계속 확인하러 다님 |
| C7 | 시간 맞추기 | 정해진 시간 안에 함께 끝내야 한다 | 빨강과 파랑이 30초 안에 같은 구역에 놓여야 한 묶음 | 하나만 먼저 놓여 무효 |
| C8 | 한정된 자리 | 놓을 자리나 쓸 수 있는 것이 모자란다 | 구역마다 2개까지만. 넘김 자리는 하나 | 꽉 찬 곳으로 들고 감 |
| C9 | 같은 목표 겹침 | 같은 일에 여럿이 몰린다 | 가까운 상자 하나에 두 대가 감 | 한 대는 헛걸음 |
| C10 | 마감과 우선순위 | 전부 할 시간이 없다. 무엇을 포기할지 정해야 한다 | 제한 시간 안에 점수가 높은 상자부터 | 덜 중요한 것에 시간을 씀 |
| C11 | 중간 고장 | 한 대가 멈추거나 집기에 실패한다 | 실행 중 한 로봇 정지 | 그 로봇의 일이 끝까지 남음 |
| C12 | 중간 변화 | 상황이 바뀌고 일부만 그것을 안다 | 상자 추가, 주문 변경, 옮겨진 상자 | 옛 계획대로 움직임 |
| C13 | 낡은 정보 | 예전에 본 것이 더는 맞지 않는다 | A 가 알려 준 상자를 그 사이 C 가 가져감 | 없는 상자를 찾아감 |
| C14 | 통신 제약 | 통신 자체가 제한된다 | 같은 방에 있을 때만 통신. 메시지 횟수 제한 | (통신 조건 자체가 변수) |

본 실험의 중심은 C1–C6 이다. C7–C10 은 여유가 되면 추가한다. C11–C14 는 독립된 과제가 아니라 다른 과제에 겹쳐 쓰는 조건이다.

### 3.5 로봇 수
| 층 | 로봇 수 |
|---|---|
| 실물 | 3대 |
| MuJoCo | 3대부터. 더 늘릴 수 있는 대수는 계산 시간을 재 본 뒤 정한다 |
| 계획 전용 환경 | 2, 3, 8, 16, 32, 64대 |

로봇이 많은 실험은 지도와 상자 수도 함께 키운다.

### 3.6 그 밖에 바꿀 수 있는 것
- LLM 모델: 하나를 기본으로, 가능하면 크기가 다른 것 하나를 더.

## 4. 고정하는 것
- 같은 장면과 같은 시작 상태를 모든 팀 구조에 쓴다(짝지은 비교).
- LLM 에 주는 설명문은 팀 구조에 해당하는 부분만 다르게 한다.
- 통신 한 번에 드는 시간을 정해 두고 모든 조건에 같게 적용한다.
- 각 로봇의 LLM 이 받는 것은 자기가 본 것, 자기가 한 일, 받은 메시지뿐이다. 조건 F 에서만 전체 상태를 준다.

## 5. 재는 것 (종속 변수)
| 종류 | 지표 |
|---|---|
| 결과 | 과제 성공 여부, 끝까지 걸린 시간, 제한 시간 안에 옮긴 개수 |
| 낭비 | 로봇별 이동 거리, 같은 상자·같은 방을 겹쳐 맡은 횟수, 문·구역 앞에서 기다린 시간, 헛걸음 횟수 |
| 통신 | 메시지 수, 토큰 수, LLM 호출 수 |
| 계획의 질 | 틀린 구역·틀린 순서·없는 상자를 가리킨 지시의 수, 다시 계획한 횟수 |
| 회복 | 고장이나 변화 뒤 새 분담이 정해질 때까지의 시간 |
| 믿음 | 각 로봇이 알고 있는 상자 위치와 실제의 차이(평가용으로만 계산) |

실패의 책임 구분: 실행 기록에서 "계획이 가리킨 일이 맞았는가"와 "그 일을 동작이 해냈는가"를 따로 표시한다. 계획은 맞았는데 동작이 실패한 실행은 계획 평가에서 따로 센다.

## 6. 실험의 세 층
| 층 | 환경 | 동작 | 목적 | 규모 (제안) |
|---|---|---|---|---|
| L0 | 계획 전용 환경 | 로봇 64대까지. 이동·집기·놓기를 "정해진 시간이 걸리고 정해진 확률로 성공"으로 단순화. 로봇은 지금 있는 방에서 보이는 것만 통보받음 | 팀 구조와 과제 유형을 넓게 비교. 동작이 불완전해도 바로 시작 가능 | 과제 6종 × 팀 구조 4종 × 관측 2종 × 장면 10개 × 반복 3회 = 1,440회 |
| L1 | MuJoCo | Solo 동작(접근 코드, ACT 집기, 놓기 재생), 지도 없는 이동, 자기 카메라 인식 | L0 의 결론이 실제 동작과 인식에서 유지되는지 | 과제 3종 × 팀 구조 3종 × 장면 6개 = 54회 |
| L2 | 실물 MasterPi | L1 과 같은 구성 | 시연과 방향 확인 | 과제 1–2종 × 팀 구조 2종 × 3회 |

(L0 는 접었고 이번 제출의 규모는 [작업 계획 5절](plan.md#5-실행-횟수)에 있다.)

위 규모는 기본 4가지 구조와 로봇 2–3대 기준이다. 미리 정해 주는 구조(W1–W6)와 로봇 수를 더하면 조합이 크게 늘어나므로, 전부 돌리지 않고 시험 실행에서 차이가 보이는 조합을 골라 넓힌다.

L0 는 LLM 호출 비용이 든다. 로봇 수가 늘면 호출 수도 함께 는다. 한 번의 실행에 드는 호출 수와 토큰을 먼저 10회로 재고 전체 비용을 계산한 뒤 규모를 확정한다.

## 7. 분석
- 같은 장면에서 팀 구조끼리 짝지어 비교한다. 차이와 그 불확실성(구간)을 함께 낸다.
- 결과는 "몇 개 중 몇 개"로 적고, 제외한 실행과 이유를 함께 적는다.
- Q2 는 과제 유형마다 팀 구조의 순위가 바뀌는지를 본다.
- 장면 설계에 쓴 장면과 최종 평가 장면을 나눈다. 설명문을 고치는 데 쓴 장면은 최종 평가에 쓰지 않는다.

## 8. 위험과 대처
| 위험 | 대처 |
|---|---|
| 조건 사이 차이가 작아 구분이 안 됨 | 과제를 정보를 안 나누면 손해가 크도록 설계. L0 에서 먼저 차이가 나는 과제만 골라 L1 로 |
| 동작 실패가 계획 평가를 가림 | L0 로 계획을 따로 평가. L1 에서는 책임 구분 기록 |
| LLM 응답이 실행마다 달라짐 | 같은 장면 반복 3회 이상, 온도 고정 |
| 설명문에 따라 결과가 바뀜 | 설명문을 미리 고정하고 공개. 바꾸면 전부 다시 |
| 선행 연구와 차별점이 약함 | 조건 F 를 같은 환경에 두어 "부분 관측이 결론을 바꾸는가"를 직접 보여 줌 |
| LLM 비용 | 10회 시험 실행으로 비용을 잰 뒤 규모 결정 |

## 9. 진행 순서
1. 선행 연구 조사 결과로 가설과 차별점을 고친다.
2. L0 환경과 과제 C1–C6 을 만든다. 팀 구조 기본 4종과 W1–W6 의 대화 규칙을 정한다.
3. 10회 시험 실행으로 비용과 차이의 크기를 본다. 규모를 확정한다.
4. L0 본 실험.
5. L0 에서 차이가 뚜렷한 과제 3종을 L1 로 옮긴다(Solo 동작이 안정된 뒤).
6. 실물 시연.

## 10. 아직 정하지 않은 것
- LLM 모델과 로봇마다 LLM 을 따로 둘지.
- 팀장을 고정할지, 장면마다 바꿀지.
- 통신 한 번의 시간 비용.
- W1–W6 가운데 먼저 만들 것.

## 11. 이번 제출의 동결 설계 (2026-11-16)

이번 제출에서 실제로 비교하는 것의 정의다. 실행 횟수와 일정은 [작업 계획](plan.md), 메시지 규칙과 내려놓기 행동은 [전체 구조 3절](architecture.md#3-llm-계획기)에 있다. 동결 뒤에는 이 절의 지표와 검정을 바꾸지 않는다.

### 11.1 질문, 가설, 이 연구가 내세우는 것

| 항목 | 내용 |
|---|---|
| 연구 질문 | 로봇마다 자기가 본 것과 받은 주문만 아는 부분 관측에서, LLM 팀 구조(T0 통신 없음, T1 동등, T2 팀장)가 계획의 주문 덮임을 바꾸는가 |
| 가설 H1, H2 | 장면 단위 계획 덮임이 T1 과 T0 사이, T2 와 T0 사이에서 다르다(양측 검정). 정보가 없는 쪽이 못 하는 것은 장면 설계의 성질이라 이 결과는 자명할 수 있다. 그래서 H1, H2 는 "통신 조작이 먹혔는지 확인"으로 한 문단만 쓰고 주 기여로 내세우지 않는다 |
| 주 기여 (본문 표) | ① 통신 구조가 정답 계획에 못 미친 몫의 원인 분해 ② 전체 정보를 준 LLM 과의 대비 ③ 계획 실패와 물리 실패의 분리(계획×물리 4칸과 정답 계획 기준선) ④ 개입으로 원인 확인(사전 교환, 재결정 끔) |
| 주장하지 않는 것 | 2대에서 T1 대 T2 우열(지시문 한 줄 차이이므로 기술 통계만). 2대의 T2 는 계층 구조가 아니라 팀장 지시문의 효과다. 우리 메시지 규칙은 CoELA 의 통신과 다르므로 "CoELA 방식 통신"이라 부르지 않는다 |
| 대조 장면 | X 3, D 3. 40장면 검정에 넣고, 대조 6개를 뺀 값도 함께 적는다. D 는 "구조 차이 없음"이 아니라 "주문 없는 상자를 건드리지 않는가"를 시험한다 |

### 11.2 지표

| 지표 | 정의 |
|---|---|
| **주 1: 계획 덮임 C** (실행마다 0 또는 1) | 로봇들의 마지막 선택 (색, 표식) 모음이 장면 주문(색, 표식, 개수)과 정확히 같으면 1. 남는 선택이 있어도 0. 어느 로봇이 골랐는지는 보지 않는다. 기록이 없으면 NA |
| 빈 선택·내려놓기 | 고르지 않은 것과, 든 상자를 내려놓고 끝낸 것은 모두 빈 선택이다. 내려놓은 상자는 표식 밖에 있어 틀린 배치가 아니고, 주문 없는 상자를 집었다 내려놓은 것 자체는 덮임을 해치지 않는다 |
| **주 2: 메시지 벌점 점수 SP** | `SP = max(0, C − λ × max(0, M − 2R))`. M 은 그 실행에서 모든 로봇이 보낸 메시지 수(받는 로봇 수와 관계없이 한 통이 1), R 은 로봇 수라 2대면 허용 4개다. 기본 λ=0.02, 민감도 λ=0.05, 0.10. T0 는 보내지 않으므로 SP=C |
| 보조: 근거 있는 덮임 G | C=1 이면서 맞은 이유가 "추측이 맞았다"가 아닌 실행. 주문 없는 로봇의 추측 적중이 C=1 로 들어가는 것을 가르기 위해 둔다. 맞은 이유가 받은 메시지 또는 자기 주문일 때만 세는 엄격판(G_strict)도 함께 보고한다 |
| 보조: 내려놓음 분류 | 실행이 아니라 내려놓음 하나하나를 센다. ① 그 색 주문이 장면에 없음(유인 상자를 옮기지 않은 올바른 자제) ② 중복(주문이 있고 이미 채워짐) ③ 손실(주문이 아직 안 채워졌는데 내려놓음). 손실은 그 로봇이 그 주문을 알았나, 팀원만 알았나로 다시 나눈다 |
| 보조: 물리 성공 S | 필요한 상자가 모두 맞는 표식 앞에 놓이고 틀린 곳에 놓인 상자가 없음 |
| 보조: 시간·메시지·호출·비용 | 끝난 시각(성공 실행 중앙값과 전체 중앙값을 따로), 보낸 메시지 수, 계획기 호출 수와 비용 |
| 보고만 | 첫 선택 덮임, 정답 계획 일치(정답 계획과 다른 유효한 분담도 불일치로 세므로 주 지표가 아니다) |
| 계획×물리 4칸 | 계획 맞음/틀림 × 물리 성공/실패. 계획 기록이 없는 칸은 따로 |

C 는 실행 하나가 0 또는 1 이다. 장면 s, 구조 X 의 점수는 그 장면 2회 실행의 평균(0, 0.5, 1)이고, 집계 단위는 장면이다.

### 11.3 메시지 벌점의 이유와 읽는 법

- 메시지를 자유롭게 풀어 주면 많이 보내는 것이 이득이 될 수 있다. 그래서 상한(로봇당 8개)을 두고, 허용을 넘게 말하면 점수를 깎는다. 계획 덮임과 SP 를 함께 주 지표로 둔다.
- λ 는 "상한까지 말해도 완벽히 덮은 팀이 통신 없는 팀의 반반 추측 평균(0.5)보다 높게 남도록" 정했다. 2대는 허용 4개이고 상한까지 쓰면 16개라 12개를 넘기므로 λ < 0.5/12 ≈ 0.042 가 필요하고, 그래서 0.02 다(16개를 보내도 완벽히 덮으면 0.76). 처음에는 0.05 를 썼으나 이 조건을 어겨 바꿨다. 이 결정은 개발 장면에서 메시지 수를 본 뒤에 했다.
- T0 는 벌점을 받을 수 없어 SP 는 한쪽만 깎는 지표다. 그래서 SP 는 "통신이 이득인가"가 아니라 "이 λ 에서 이득인가"로만 읽는다. λ 와 상관없이 어디서 뒤집히는지(손익분기 λ\*)를 함께 보고한다.
- 알려 준 말과 채점이 다르다. LLM 에게는 "최대 8개, 반복하거나 불필요하면 감점"이라 알리고, 채점은 "허용 4개를 넘으면 필요한 메시지도 감점"이다. 문구는 고치지 않았다.

### 11.4 부족분(C=0 실행)의 원인 분해: 본문 표 ①

분모는 C=0 인 실행이다. 칸은 꼬리표가 붙은 실행 수이고 복수가 가능하다. 대표 꼬리표 하나는 아래 순서로 정한다.

| 꼬리표 | 뜻 |
|---|---|
| 정보 없음 | T0 의 모든 부족분. T0 는 이 칸과 추측만 의미가 있다 |
| 받고도 무시 | 맞는 메시지가 결정 전에 도착했는데 반영되지 않음 |
| 늦게 도착 | 맞는 메시지가 그 로봇의 최종 결정 뒤에 도착 |
| 안 보냄 | 필요한 사실을 담은 메시지가 끝내 없음 |
| 추측 | 틀린 목적지가 자기 주문에도 받은 메시지에도 근거가 없음 |
| 필요한 상자 내려놓음 | 주문이 아직 안 채워진 색의 상자를 내려놓음 |
| 기타 | 주문 보유자가 안 고름, 틀린 메시지를 따름, 기록 없음 등 |
| 상한 때문에 못 보냄(분석 전용) | 안 보냄 중, 필요한 사실을 가진 팀원이 이미 상한까지 보낸 칸. 안 보냄의 일부이고 대표 꼬리표가 아니다 |

계획이 맞은 실행은 맞은 이유(추측 적중 / 메시지 근거 / 자기 주문만)도 보고한다. 통신이 계획을 날랐다는 증거는 "메시지 근거"뿐이다. 자동 꼬리표만으로 결론 내지 않고, 사람이 원문을 몇 건 열어 봤는지 적는다. 메시지가 가리킨 상자를 상대가 다른 상자로 읽은 경우(지칭 불일치)는 자동 꼬리표가 없어 사람이 읽고 센다.

### 11.5 검정

| 항목 | 정의 |
|---|---|
| 짝 | 본 비교 40장면마다 D = 점수 평균(T1) − 점수 평균(T0)과 점수 평균(T2) − 점수 평균(T0). T2 − T1 은 기술 통계만 |
| C 판정 | 양측 정확 부호 검정(D=0 인 장면은 제외). 두 검정(T0 대 T1, T0 대 T2)을 Holm 으로 보정한다. 물리 성공 S 와 근거 있는 덮임 G 도 같은 방식 |
| SP 판정 | 부호 검정이 아니라 장면별 평균 차이와, 장면 40개를 복원추출한 부트스트랩 95% 구간(10,000회)으로 읽는다. 구간이 0 을 빼면 차이가 있고, 0 을 포함하면 구분되지 않는다. λ=0.02 가 판정, 0.05·0.10 은 민감도. 부호 검정 값은 참고로만 둔다 |
| SP 를 부호 검정으로 하지 않은 이유 | 부호가 통신의 이득이 아니라 메시지가 허용(4개)을 넘는지로 정해진다. 둘 다 늘 덮는 장면에서 T0 는 SP=C 이고 T1 은 메시지가 4개를 넘으면 SP<1 이라, 그런 장면이 전부 T1 의 패가 된다. 이 변경은 시간 모형으로 돌린 재생 결과를 본 뒤에 정했다 |
| SP 의 한계 | 두 대조 사이의 다중 비교 보정을 하지 않는다. 두 구간을 함께 읽으면 족 오류가 최대 약 10% 라서, 확증 검정은 C 의 Holm 이고 SP 는 통신 비용을 반영한 판단으로 보고한다 |
| 손익분기 λ\* | T1(또는 T2)의 장면 평균 SP 가 T0 와 같아지는 λ. 사전 지정 λ=0.02 가 이 값 위인지 아래인지로 읽는다. 실제 비용(끝난 시각, 호출 수)도 나란히 싣는다 |
| 효과 크기 | 평균 차이(퍼센트포인트), 양·음·동점 장면 수, 유형별 평균(유형 일반화는 안 한다) |
| 하지 않는 것 | 중간 유의성 확인, 결과를 본 뒤 반복 늘리기, 검정·지표 바꾸기. 설계 40, 무작위 20, 3대, 두 번째 모델은 서로 합쳐 검정하지 않는다 |

장면은 같은 유형의 좌표 변형이라 독립이 아닐 수 있다. n=40 이며 반복을 늘려도 표본은 늘지 않는다. 검정력은 가정에서 계산했다: 동점이 아닌 장면 중 양수 비율 p, 동점이 아닌 비율 q 라 할 때 (p=0.75, q=0.8)이면 n=40 에서 검정력이 약 0.71 이고, (p=0.65, q=0.8)이면 약 0.25 다. 작은 효과(p 0.65~0.75)는 못 잡을 수 있다고 미리 적는다. SP 구간 판정의 검정력은 계산하지 않았다.

### 11.6 설계가 바뀐 경위와 노출 공개

동결 전에 개발 장면 몇 개(X01, L01, C01, D01, X02)를 실제로 돌려 보며 아래를 정했다. 이 장면은 주 분석에서 뺀다. 본 비교 40장면은 어느 메시지 규칙 판으로도 실제 LLM 으로 돌린 적이 없다. 장면은 시간 모형으로 돌린 재생 층에서 한 번 시험했지만 구조 차이를 보고 고르거나 빼지 않았고, 재생 결과는 실제의 예고로 읽지 않는다.

| 개발 장면 실행을 본 뒤 정한 것 | 영향 |
|---|---|
| 내려놓기 선택지, 내려놓음을 빈 선택으로 세는 판정 | 모든 구조에 같은 규칙. 유인 상자를 집었다 내려놓은 D 장면도 덮임이 된다 |
| 과제 문장과 운반 끝 보고 문구(LLM 에게 실행 뒤 이유를 물어 보고 고침) | 모든 구조 같은 문구 |
| 메시지 규칙 네 차례(자유롭게 덧붙이기, 예산 알림, 답장 기회 조건, 답장 연쇄 차단) | 개발 장면 한 칸씩 돌려 보고 고쳤으므로 "줄었다"를 확정으로 읽지 않는다. 일반화는 확인 묶음과 본 비교로만 본다 |
| 허용·λ·상한 8 | 연구진의 결정으로 정했다. λ 는 개발 장면의 메시지 수를 본 뒤 바꿨다 |
| SP 의 통계량(부호 검정에서 평균 차이와 구간으로) | 재생 결과를 본 뒤의 변경 |
| 판정 규칙 변경(받은 메시지의 같은 (색, 표식) 짝은 1인칭 문장이어도 근거로 셈) | 모든 구조 같은 규칙 |
| 출력 상한 768 → 2048 토큰 | 재생에서 일부 응답이 숨은 추론으로 상한에 걸려 멈춰 올렸다. 모든 구조 같은 값 |
| 정답 계획이 같은 색 상자 둘 중 가장 가까운 것을 집게 한 수정 | 정답 계획 기준선에만 영향. LLM 조건에는 없다 |
| 다시 집을 때 천장 카메라 기준 화면을 다시 잡는 수정, 실행 벽시계 상한 늘림 | 모든 구조에 같다 |
| 기준선을 동결 전에 돌려 본 뒤의 실행층 수정: 시작 방향에서 많이 기운 상자의 첫 집기, 한 번도 못 본 상자는 ACT 에 넘기지 않기, 들기 확인 후진을 벽 앞까지 | 접근 코드는 모든 구조가 같이 쓴다. 기준선은 고친 코드로 처음부터 다시 돌린다 |
| 같은 기준선에서 정답 계획이 끝난 로봇을 문 대기열에서 빼는 수정 | 정답 계획에만 해당. LLM 조건에는 없다 |

행동 감사는 "연속 메시지를 허용하지 말 것"을 권했으나 연구진은 반대로 허용했다.

### 11.7 위협

1. 장면이 유형별 변형이라 서로 독립이 아니다.
2. 2대의 T2 는 지시문 효과이고 계층 구조가 아니다.
3. T0 에도 같은 충돌 회피 규칙과 4초 듣기가 있어 "작업 정보 통신 없음"이지 조율이 전혀 없는 것은 아니다.
4. 단일 모델, 단일 공급자, 단일 시뮬레이터다. 두 번째 모델은 선택 묶음이다. 실물 전이는 확인하지 않았다.
5. 반복이 2회라 변동 추정이 거칠다.
6. 개발 장면과 재생 층의 노출이 있다(11.6).
7. 시간 모형 재생과 실제 MuJoCo 실행이 얼마나 맞는지 확인하지 않았다.
8. 메시지 규칙이 개발 장면 몇 칸에서 괜찮아 보일 때 확정됐다. 일반화는 확인 묶음과 본 비교로만 본다.
9. SP 는 한쪽(T1, T2)만 깎는 지표다. "통신이 이득인가"가 아니라 "이 λ 에서 이득인가"로 읽는다.
10. 실행층 수정이 개발 중 장면 몇 개에서만 확인됐다. 나머지 장면에서의 효과는 본 실험의 정답 계획 기준선에서 처음 본다.
