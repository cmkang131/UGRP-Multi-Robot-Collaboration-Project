# 연구 설계: 부분 관측에서 LLM 다중 로봇 협업의 팀 구조 비교

2026-11-13 초안. 가설과 선행 연구와의 차이는 선행 연구 조사가 끝나면 고친다.

## 0. 방향 (2026-11-13 정함)

이 문서의 나머지는 아래 결정을 풀어 쓴 것이다.

- **중심은 LLM 이 짠 작업 계획의 평가다.** 집기·옮기기 동작은 그 실험을 실제로 돌리기 위한 기반이다.
- **바탕 조건은 부분 관측이다.** 물체의 위치를 다 아는 조건이 아닐 때 어떻게 되는지를 본다.
- **질문은 팀 구조다.** 누가 팀장을 맡는 것이 효율적인가, 모두 동등한 것이 효율적인가.
- **팀 구조와 보고 체계를 미리 정해 주는 방식도 비교한다.** 팀장·동등 두 가지에 그치지 않고, 작업 흐름 구조나 팀 운영 요령을 LLM 에 미리 제시한다. LLM 팀이 과제를 보고 구조를 스스로 짜는 방식도 넣는다.
- **협업이 꼭 필요한 과제를 여러 구조로 만든다.** 정보 의존, 좁은 통로, 어려운 길, 순서 제약, 능력 차이, 로봇별 지정 구역, 그리고 그 밖의 것들.
- **로봇 수는 실물 3대, 시뮬레이션은 32대·64대까지 늘린다.**
- **논문보다 도전적인 학생 실험이 목표다.** 안전한 비교 하나보다 새 구조를 넓게 시도한다.
- **두 로봇이 한 물체를 맞잡아 옮기는 과제(Pair)는 연구에서 뺀다.** 위 과제들은 모두 혼자 집어 옮기는 동작만으로 된다.

## 1. 한 줄 요약
각 로봇이 자기가 본 것만 아는 상황에서, LLM 이 짠 작업 계획이 팀 구조(통신 없음, 모두 동등, 팀장 있음, 혼합)에 따라 얼마나 달라지는지를, 협업이 필요한 이유가 서로 다른 과제들에서 비교한다.

## 2. 연구 질문과 가설
| 번호 | 질문 | 가설 (틀릴 수 있음) |
|---|---|---|
| Q1 | 부분 관측에서 어느 팀 구조가 효율적인가 | 전체를 아는 조건에서 보고된 "팀장·중앙 계획 우세"가 부분 관측에서는 줄거나 뒤집힌다. 팀장도 전체를 모르고 보고를 기다려야 하기 때문 |
| Q2 | 협업이 필요한 이유에 따라 유리한 팀 구조가 달라지는가 | 정보를 나눠야 하는 과제는 동등 구조가, 순서와 시간을 맞춰야 하는 과제는 팀장 구조가 유리하다 |
| Q3 | 동작이 실패하거나 상황이 바뀌면 어느 구조가 빨리 회복하는가 | 동등 구조는 빨리 반응하지만 중복이 생기고, 팀장 구조는 느리지만 중복이 적다 |
| Q4 | 위 결론이 실제 동작과 실제 카메라 인식에서도 유지되는가 | 방향은 유지되지만 차이의 크기는 줄어든다 |
| Q5 | 구조를 미리 정해 주면 LLM 끼리 알아서 정하는 것보다 나은가 | 과제에 맞는 구조를 주면 낫고, 맞지 않는 구조를 주면 자유 대화보다 못하다 |
| Q6 | 로봇 수가 늘면 유리한 구조가 바뀌는가 | 동등 구조는 로봇 수가 늘수록 메시지가 급히 늘어 느려지고, 조를 나눈 계층 구조가 유리해진다 |
| Q7 | LLM 팀이 과제를 보고 구조를 스스로 고르면 고정 구조만큼 하는가 | 과제 유형이 섞여 있을 때 스스로 고르는 쪽이 유리하다 |

## 3. 바꾸는 것 (독립 변수)

### 3.1 팀 구조: 기본 4가지
| 기호 | 이름 | 내용 |
|---|---|---|
| T0 | 통신 없음 | 각 로봇의 LLM 이 자기 관측만으로 계획한다. 기준선 |
| T1 | 모두 동등 | 로봇끼리 자유롭게 메시지를 주고받아 정한다 |
| T2 | 팀장 있음 | 한 로봇이 팀장이다. 나머지는 본 것을 보고하고 팀장의 지시를 따른다. 팀장도 자기 카메라만 본다 |
| T3 | 혼합 | 팀장이 계획 초안을 내고, 팀원이 한 번 이의를 낼 수 있다 |

### 3.2 미리 정해 주는 구조와 요령

기본 4가지는 "누가 정하는가"만 다르다. 여기서는 일하는 방식 자체를 미리 정해 LLM 에 준다.

| 기호 | 이름 | 내용 | 유리할 것으로 보는 곳 |
|---|---|---|---|
| W1 | 계층 | 팀장 아래 조장, 조장 아래 조원. 보고는 한 단계 위로만 한다 | 로봇이 많을 때 |
| W2 | 역할 분담 | 찾는 로봇, 옮기는 로봇, 조정하는 로봇으로 나눈다 | 정보 의존, 능력 차이 |
| W3 | 공유 게시판 | 대화 없이 본 것과 맡은 일을 한 게시판에 적고, 거기서 일을 가져간다 | 같은 목표 겹침, 낡은 정보 |
| W4 | 입찰 | 일이 생기면 각자 드는 비용을 내고 가장 적게 드는 로봇이 맡는다 | 일이 많고 서로 독립일 때 |
| W5 | 구역 담당 | 구역마다 책임 로봇을 두고, 경계에서만 대화한다 | 지정 구역, 좁은 통로 |
| W6 | 스스로 짜기 | 팀이 과제를 보고 위 구조 가운데 하나를 고르거나 새로 짠 뒤 시작한다. 도중에 바꿀 수 있다 | 과제 유형이 섞여 있을 때 |

팀 운영 요령은 구조와 따로 켜고 끌 수 있는 짧은 규칙 묶음이다. 예: "새로 본 것은 바로 알린다", "남이 맡은 상자에는 가지 않는다", "정해진 시간 넘게 막히면 보고한다", "받은 정보에는 본 시각을 붙인다". 같은 구조에서 요령이 있을 때와 없을 때를 비교한다.

### 3.3 관측 조건 (2가지)
| 기호 | 내용 | 쓰임 |
|---|---|---|
| P | 부분 관측: 자기가 본 것만 안다 | 본 실험 |
| F | 전체 공개: 모든 상자·로봇 위치를 처음부터 안다 | 선행 연구 조건을 우리 환경에서 재현하는 비교군. Q1 의 "뒤집히는가"를 같은 환경에서 보여 준다 |

### 3.4 협업 구조 (과제 유형)
중심 여섯 가지와 추가 후보. 모두 혼자 집어 옮기는 동작만으로 된다.

| 번호 | 이름 | 협업이 필요한 이유 | 예시 장면 | 통신이 없으면 |
|---|---|---|---|---|
| C1 | 정보 의존 | 한 로봇이 본 것을 다른 로봇이 알아야 일이 된다 | 주문 내용(색, 개수, 구역)을 로봇마다 일부만 안다. 또는 A 가 본 상자를 B 가 옮겨야 한다 | 전부 뒤지거나 틀린 곳에 놓음 |
| C2 | 좁은 통로 | 한 번에 한 대만 지나간다 | 방 사이 문, 좁은 복도에서 마주침 | 서로 막고 기다림 |
| C3 | 어려운 길 | 길이 막혔거나 돌아가야 한다. 누군가 치우거나 길을 알려 줘야 한다 | 통로를 막은 상자, 한 로봇만 본 우회로 | 막힌 쪽이 직접 치우느라 자기 일을 못 함 |
| C4 | 순서 제약 | 정해진 순서로 놓아야 한다 | 빨강이 먼저 놓여야 파랑을 놓을 수 있다 | 들고 기다리거나 규칙 위반 |
| C5 | 능력 차이 | 로봇마다 할 수 있는 일이 다르다 | 빨강만 집는 로봇과 파랑만 집는 로봇. 넓게 보지만 못 집는 로봇 | 자기 것을 찾을 때까지 혼자 탐색 |
| C6 | 로봇별 지정 구역 | 로봇마다 들어갈 수 있는 곳이 다르다. 경계에서 넘겨줘야 한다 | A 는 1번 방, B 는 2번 방만. 문 앞 넘김 자리에 놓으면 다음 로봇이 집어 감 | 넘김 자리를 계속 확인하러 다님 |
| C7 | 시간 맞추기 | 정해진 시간 안에 함께 끝내야 한다 | 빨강과 파랑이 30초 안에 같은 구역에 놓여야 한 묶음 | 하나만 먼저 놓여 무효 |
| C8 | 한정된 자리 | 놓을 자리나 쓸 수 있는 것이 모자란다 | 구역마다 2개까지만. 넘김 자리는 하나 | 꽉 찬 곳으로 들고 감 |
| C9 | 같은 목표 겹침 | 같은 일에 여럿이 몰린다 | 가까운 상자 하나에 두 대가 감 | 한 대는 헛걸음 |
| C10 | 마감과 우선순위 | 전부 할 시간이 없다. 무엇을 포기할지 정해야 한다 | 제한 시간 안에 점수가 높은 상자부터 | 덜 중요한 것에 시간을 씀 |
| C11 | 중간 고장 | 한 대가 멈추거나 집기에 실패한다 | 실행 중 한 로봇 정지 | 그 로봇의 일이 끝까지 남음 |
| C12 | 중간 변화 | 상황이 바뀌고 일부만 그것을 안다 | 상자 추가, 주문 변경, 옮겨진 상자 | 옛 계획대로 움직임 |
| C13 | 낡은 정보 | 예전에 본 것이 더는 맞지 않는다 | A 가 알려 준 상자를 그 사이 C 가 가져감 | 없는 상자를 찾아감 |
| C14 | 통신 제약 | 통신 자체가 제한된다 | 같은 방에 있을 때만 통신. 메시지 횟수 제한 | (통신 조건 자체가 변수) |

본 실험의 중심은 C1–C6 이다. C7–C10 은 여유가 되면 추가한다. C11–C14 는 독립된 과제가 아니라 다른 과제에 겹쳐 쓰는 조건이다.

### 3.5 로봇 수
| 층 | 로봇 수 |
|---|---|
| 실물 | 3대 |
| MuJoCo | 3대부터. 더 늘릴 수 있는 대수는 계산 시간을 재 본 뒤 정한다 |
| 계획 전용 환경 | 2, 3, 8, 16, 32, 64대 |

로봇이 많은 실험은 지도와 상자 수도 함께 키운다.

### 3.6 그 밖에 바꿀 수 있는 것
- LLM 모델: 하나를 기본으로, 가능하면 크기가 다른 것 하나를 더.

## 4. 고정하는 것
- 같은 장면과 같은 시작 상태를 모든 팀 구조에 쓴다(짝지은 비교).
- LLM 에 주는 설명문은 팀 구조에 해당하는 부분만 다르게 한다.
- 통신 한 번에 드는 시간을 정해 두고 모든 조건에 같게 적용한다.
- 각 로봇의 LLM 이 받는 것은 자기가 본 것, 자기가 한 일, 받은 메시지뿐이다. 조건 F 에서만 전체 상태를 준다.

## 5. 재는 것 (종속 변수)
| 종류 | 지표 |
|---|---|
| 결과 | 과제 성공 여부, 끝까지 걸린 시간, 제한 시간 안에 옮긴 개수 |
| 낭비 | 로봇별 이동 거리, 같은 상자·같은 방을 겹쳐 맡은 횟수, 문·구역 앞에서 기다린 시간, 헛걸음 횟수 |
| 통신 | 메시지 수, 토큰 수, LLM 호출 수 |
| 계획의 질 | 틀린 구역·틀린 순서·없는 상자를 가리킨 지시의 수, 다시 계획한 횟수 |
| 회복 | 고장이나 변화 뒤 새 분담이 정해질 때까지의 시간 |
| 믿음 | 각 로봇이 알고 있는 상자 위치와 실제의 차이(평가용으로만 계산) |

실패의 책임 구분: 실행 기록에서 "계획이 가리킨 일이 맞았는가"와 "그 일을 동작이 해냈는가"를 따로 표시한다. 계획은 맞았는데 동작이 실패한 실행은 계획 평가에서 따로 센다.

## 6. 실험의 세 층
| 층 | 환경 | 동작 | 목적 | 규모 (제안) |
|---|---|---|---|---|
| L0 | 계획 전용 환경 | 로봇 64대까지. 이동·집기·놓기를 "정해진 시간이 걸리고 정해진 확률로 성공"으로 단순화. 로봇은 지금 있는 방에서 보이는 것만 통보받음 | 팀 구조와 과제 유형을 넓게 비교. 동작이 불완전해도 바로 시작 가능 | 과제 6종 × 팀 구조 4종 × 관측 2종 × 장면 10개 × 반복 3회 = 1,440회 |
| L1 | MuJoCo | Solo 동작(접근 코드, ACT 집기, 놓기 재생), 지도 없는 이동, 자기 카메라 인식 | L0 의 결론이 실제 동작과 인식에서 유지되는지 | 과제 3종 × 팀 구조 3종 × 장면 6개 = 54회 |
| L2 | 실물 MasterPi | L1 과 같은 구성 | 시연과 방향 확인 | 과제 1–2종 × 팀 구조 2종 × 3회 |

위 규모는 기본 4가지 구조와 로봇 2–3대 기준이다. 미리 정해 주는 구조(W1–W6)와 로봇 수를 더하면 조합이 크게 늘어나므로, 전부 돌리지 않고 시험 실행에서 차이가 보이는 조합을 골라 넓힌다.

L0 는 LLM 호출 비용이 든다. 로봇 수가 늘면 호출 수도 함께 는다. 한 번의 실행에 드는 호출 수와 토큰을 먼저 10회로 재고 전체 비용을 계산한 뒤 규모를 확정한다.

## 7. 분석
- 같은 장면에서 팀 구조끼리 짝지어 비교한다. 차이와 그 불확실성(구간)을 함께 낸다.
- 결과는 "몇 개 중 몇 개"로 적고, 제외한 실행과 이유를 함께 적는다.
- Q2 는 과제 유형마다 팀 구조의 순위가 바뀌는지를 본다.
- 장면 설계에 쓴 장면과 최종 평가 장면을 나눈다. 설명문을 고치는 데 쓴 장면은 최종 평가에 쓰지 않는다.

## 8. 위험과 대처
| 위험 | 대처 |
|---|---|
| 조건 사이 차이가 작아 구분이 안 됨 | 과제를 정보를 안 나누면 손해가 크도록 설계. L0 에서 먼저 차이가 나는 과제만 골라 L1 로 |
| 동작 실패가 계획 평가를 가림 | L0 로 계획을 따로 평가. L1 에서는 책임 구분 기록 |
| LLM 응답이 실행마다 달라짐 | 같은 장면 반복 3회 이상, 온도 고정 |
| 설명문에 따라 결과가 바뀜 | 설명문을 미리 고정하고 공개. 바꾸면 전부 다시 |
| 선행 연구와 차별점이 약함 | 조건 F 를 같은 환경에 두어 "부분 관측이 결론을 바꾸는가"를 직접 보여 줌 |
| LLM 비용 | 10회 시험 실행으로 비용을 잰 뒤 규모 결정 |

## 9. 진행 순서
1. 선행 연구 조사 결과로 가설과 차별점을 고친다.
2. L0 환경과 과제 C1–C6 을 만든다. 팀 구조 기본 4종과 W1–W6 의 대화 규칙을 정한다.
3. 10회 시험 실행으로 비용과 차이의 크기를 본다. 규모를 확정한다.
4. L0 본 실험.
5. L0 에서 차이가 뚜렷한 과제 3종을 L1 로 옮긴다(Solo 동작이 안정된 뒤).
6. 실물 시연.

## 10. 아직 정하지 않은 것
- LLM 모델과 로봇마다 LLM 을 따로 둘지.
- 팀장을 고정할지, 장면마다 바꿀지.
- 통신 한 번의 시간 비용.
- W1–W6 가운데 먼저 만들 것.
