# 실행 구조 결정 기록: 판단 LLM + 정답 교사 → ACT 학생 (2026-10-14)

2026-10-14에 사용자와 정한 결정이다. 결정이 바뀌면 이 문서에 날짜와 사용자 원문을 붙여 고친다. 근거가 같은데 이전 방식으로 되돌리지 않는다. 진행 기록은 PR #484(`claude/e2e18-grasp-rootcause`)와 `experiments/2026-10-14-e2e18-grasp-rootcause/`에 둔다.

## 1. 왜 바꿨나

- 손으로 짠 근거리 파지의 색 띠 단계 시험(`experiments/2026-10-14-e2e18-color-detector/evaluation.json`, 브랜치 `codex/e2e18-end-assignment` 커밋 `70af0f97`, PR #483, 12회 = 시작 상태 3개 × 조건 4개)에서 두 로봇 동시 파지는 1/12였다. 그 1회는 검정 v426 조건이고(조건 안에서는 1/3), 293.1 SIM초에 잡았으며 첫 시도가 아니었다. 첫 시도 성공은 0/12였다. 같은 시작 상태로 돌린 approach-recovery 12회의 동시 파지 1회도 같은 v426·같은 시작 상태라 독립 증거가 아니다. 감사가 6개 코호트 72회를 모두 세면 동시 held 표본은 2/72다(한 표본이라도 잡히면 held로 센 낙관적 정의). 후보는 v375→v384–386(2026-10-13-e2e18-grasp1)→v426–431→v434–443으로 이어졌다. 같은 미도달 실패가 두 번 연속 나왔다.
- 크기 확인(Codex 감사, PR #484, 병합 전): 집게 안쪽 폭은 61 mm, 봉 폭은 40 mm다. 그래서 한쪽 여유는 10.5 mm다. 끝 위치 추정 오차 중앙값은 전체 69.5 mm로 여유의 약 6.6배다. 0.3–0.6 m에서는 23.7 mm(약 2.3배)이고, 0.3 m 미만에서도 10.7 mm(여유와 비슷, p95 254 mm)라 근거리도 충분하지 않다. 단서: 오차는 정답으로 사후 계산했고, 가장 가까운 끝과 맞춘 낙관적 값이다. r69·r76·r80은 독립 재측정하지 않았다.
- 사용자: "근본적으로 좀 해결하자". 실행 계층을 정답 기반으로 추상화해 본 연구와 분리하는 제안은 거절됐다("아니다"). **규칙:** 정답으로 실행 계층을 대신한 실험을 본 연구 결과로 쓰지 않고, 다시 제안하지 않는다.

## 2. 구조

| 일 | 맡는 쪽 | 입력 |
|---|---|---|
| 무엇을 먼저·누가·몇 대로·어디로·어느 끝, 기다리기·다시 잡기, 여러 화물의 반복 순서 | 판단 LLM(Gemma 4 31B @DeepInfra fp4, v405) | 자기 RGB·정적 지도·자기 명령 이력·통신 조건의 받은 메시지. **위치 정답 없음** |
| 주행·운반 경로 | 지도 기반 코드(현행) | 정적 지도 + 자기 RGB·명령으로 추정한 자기 위치 |
| 화물 근처 접근·정렬·집기·놓기 | ACT 학생 | 자기 RGB 이력, 자기 발행 명령 이력(팬 포함), 이산 번호표(스킬·물건 종류·자리) |
| 시연 생성(학습용만) | 정답 교사 코드 | 처음 결정은 모든 로봇·물체 위치, 관절/IK, 접촉("모든 위치를 다 아는 느낌으로"). 2026-10-14 이후 행동 결정에는 지금 자기 카메라에 보이는 대상의 정확한 위치만 쓴다(아래 4절 "보이는 것만 아는 교사"). 성공 판정과 평가에는 전체 정답을 쓴다. |

- 사용자 원문: "llm이 판단할 때에는 위치를 모르게, 코드는 위치를 알게 해서 교사 그걸 만들고 ACT를 만들어", "가장 좋은 구성으로 가주고".
- ACT에는 자유 문장을 넣지 않는다. LLM이 고른 스킬을 코드가 형식·안전 검사한 뒤 번호표로 바꾼다.
- ACT는 행동 청크(0.8 SIM초) 단위로 실행한다. 코드는 청크 사이에서 기다리기·멈춤·안전 정지로 끊을 수 있다.
- 종료는 ACT의 완료 출력과 코드의 자기 카메라 확인을 함께 본다. 확인이 안 되면 LLM에 "모름"으로 돌려준다. 정답·접촉 판정은 돌려주지 않는다.
- ACT 구간은 지도 주행이 도착하고, 자기 RGB로 추정한 끝까지 거리가 0.8 m 이하일 때 시작한다. 아래 4절의 0.5–2.0 m 시작 상태는 전체 과정 기록과 지도 주행 구간용이고, ACT 학습 창은 0.8 m 인계 지점부터다.
- **누가 무엇을:** 기다리기·다시 잡기·끝 재배정을 고르는 것은 LLM, 그 동작을 실행하는 것은 ACT다. 집게 이탈은 자기 카메라로 코드가 판단해 LLM과 (통신 조건에 맞게) 짝에게 알린다. 이 판단과 종료 확인은 알림·확인 전용이며 ACT의 행동을 바꾸지 않는다. 두 로봇 동시 들기의 GO/ACK 형식·시한은 기존대로 코드다("역할" 규칙).
- **되돌림 금지:** ACT가 실패하거나 느려도 손으로 짠 근거리 파지 경로로 대체하지 않는다. 실패는 원인을 분류해 교사·데이터·학습에서 고친다.
- 지도 코드 운반이 실패로 확인되면, 같은 교사 데이터로 운반 구간도 ACT에 학습시킨다(아래 4절의 구간 라벨).

## 3. 모델과 학습 자원

- **학생 모델은 ACT 하나**(사용자: "하나로 정해", "ACT로 가자"). 근거는 다음과 같다.
  - 추론은 시뮬레이션 중 시뮬레이션 호스트 CPU에서 한다(당시 Azure VM3: 16 실행 × 로봇 2대, 물리가 이미 코어를 씀). 그래서 수억–수십억 파라미터 VLA는 제외했다.
  - 반복 계산이 필요한 Diffusion 계열은 불리하다.
  - π0/π0.5는 LoRA로도 GPU 메모리가 22.5 GB를 넘게 필요해, 당시 학습 자원이던 Kaggle 16 GB에 맞지 않았다. GCP L4(24 GB)에서는 이 근거만으로는 제외되지 않으며, 나머지 근거(CPU 추론 지연, 사전학습 화면 차이)는 그대로다.
  - VLA의 사전학습은 우리 화면과 다르고, 언어는 LLM이 맡는다.
  - ACT 논문 수치는 조정자가 2026-10-14 논문 HTML에서 열람한 값이다(표가 펼쳐진 형태라 열 대응은 근사). 실물은 작업당 50 시연으로 6개 작업 중 5개가 84–96%(나머지 하나 20%)였다. 시뮬레이션은 각본 시연으로 86%/32%(물체 옮기기/양팔 끼우기)였다.
  - 검토한 후보는 π0.5, GR00T N1.6/N1.7, SmolVLA, X-VLA, MolmoAct2, OpenVLA-OFT, Diffusion Policy, One-Step Flow Policy(2026), Normalizing Flow Policy다.
  - 재검토 조건: 학습에 안 쓴 시작 상태(held-out)에서 성공이 낮고, 그 원인이 모델 표현력으로 확인될 때만 One-Step Flow Policy를 올린다.
- **GPU는 GCP**(2026-10-14 사용자: Modal을 검토한 뒤 "GCP 가자 그냥", 이어서 "GCP를 메인으로, Azure는 보조로 하자"). 이전 결정은 Kaggle이었다(사용자: "Kaggle ㄱㄱ 하자").
  - 2026-10-14 조정자 확인: 프로젝트 `ugrp-act-train-1014`의 GPU 전체 할당량 1이 승인됐다. 지역별 L4·T4는 각 1(us-central1, asia-northeast3).
  - 크레딧을 넘으면 자동 정지한다(순비용 1,000 KRW 기준, 집계 지연 등 한계는 AGENTS.md "GCP 메인" 항목). VM 8시간 상한이 있으므로 중간 저장과 이어 학습을 기본으로 한다.
  - 학습 데이터는 GCP 프로젝트 안에서만 옮긴다. 공개 업로드는 하지 않는다. 모델 키·Kaggle 자격 증명은 VM에 두지 않는다.
  - 대체 경로(사용자 확인 뒤에만): Kaggle. 이 경우 비공개 dataset을 Mac에서 올린다(2026-10-14 조정자 확인: CLI 2.2.4, OAuth 로그인, GPU 30 h/주, 갱신 10/17).
  - 참고: Azure GPU 할당량은 전 계열 0이고 증가 요청은 하지 않았다.
  - Mac(M3 16 GiB)과 시뮬레이션 호스트 CPU는 파이프라인 확인용 작은 학습에만 쓴다.

## 4. 데이터

- **교사 관문:** 단계마다 교사 물리 성공률 ≥95%를 확인한 뒤에만 데이터를 생성한다(weld OFF, 처음 배치 뒤 위치 덮어쓰기·붙이기 금지). 최소 40회(38/40 이상)로 판정한다. 20회(19/20)는 신뢰구간이 너무 넓다.
- **성공 먼저, 기록은 그다음 (2026-10-14 사용자: "일단 성공을 하고, 그 다음에 기록을 해서 학습에 써야지"):** 교사 성공률 측정과 학습 데이터 기록은 별도 단계다. 성공률 측정 실행에서는 학습용 자기 카메라 기록을 끄고, 명령 궤적·판정 원장·전체 파일 sha256 목록과 원인 확인용 저해상도 검토 영상만 남긴다. 검토 영상은 "영상으로 원인 보기" 규칙(최소 6장, 긴 실행은 60 SIM초마다 1장 이상)을 볼 수 있을 만큼이면 되고, 대표 영상 보존 규칙도 따른다. 이 측정 실행에 판단 LLM이 없으면 LLM 텍스트 보존은 해당하지 않는다. 교사가 보이는지 여부는 정답 투영으로 판단하므로 학습용 자기 카메라 기록은 성공 판정에 필요 없다. 학습 데이터는 교사 성공률 ≥95%(최소 40회)를 확인한 뒤에만 기록한다. 원본은 실제 실행 때 학생이 받는 자기 카메라 해상도·주기·화각 그대로 기록하고, 학습 해상도로 줄이는 것은 학습 단계에서 한다(아래 "보존"). 검토용으로 줄인 영상(예: 320×240·5 Hz)을 학습 입력으로 쓰지 않는다.
- **학생이 따라 할 수 있는 교사 (2026-10-14 사용자: "코드는, 위치를 아니까 막 안 보고도 잘 집고 그럴 거잖아. 그걸 ACT는 어떻게 할 수 있지? 코드에서도, ACT가 학습 가능하게 보고 간다거나 해야하는 거 아닌가"):** 교사가 학생 카메라에 안 보이는 정보로 움직이면, 학생은 같은 화면에서 서로 다른 행동을 배우게 되어 학습이 안 된다(정보 차이로 생기는 imitation gap). 그래서 교사는 다음을 지킨다((1)은 사용자 요구, (2)·(3)과 아래 측정·비교는 조정자가 제안하고 사용자가 "그것도 적어둬"로 기록을 승인한 설계다). (1) 접근·정렬 동안 카메라 팬(서보 6, 학생 행동 공간 안)으로 맡은 화물·끝을 자기 화면 안에 둔다. 실제 카메라 위치·화각은 바꾸지 않는다. (2) 집게·화물이 너무 가까워 화면에서 안 보이는 마지막 구간은 짧고 매번 같은 모양으로 한다. (3) 그 구간이 학생이 보는 이력(자기 RGB·명령)보다 길면 학생 입력의 이력 길이를 늘린다. 관문 전에 단계별 가시 비율(맡은 끝이 자기 화면 안에 있고 가려지지 않은 샘플 비율, 정답 투영으로 계산한 평가 전용 값)과 화면 밖 최장 구간 SIM초를 측정해 기록한다. 통과 기준은 아직 근거가 없어 두지 않는다. 첫 측정값을 본 뒤 정하고 이 문서에 적는다. 이 값은 성공률 측정 실행의 명령 궤적과 정답 투영으로 계산하므로 학습용 카메라 기록이 필요 없고(가림 여부는 검토 영상 표본으로 확인), "성공 먼저" 순서를 바꾸지 않는다. 학습 때는 입력 화면을 지운 학생도 함께 학습해 비교한다. 두 학생의 성공률이 n/N으로 차이가 없으면 학생이 화면을 쓰지 않는다는 신호로 보고, 데이터 확대나 평가 전에 원인(교사 가시성·이력 길이)을 먼저 확인한다. 참고(2026-10-14 검색으로 서지 확인, 본문 전체는 읽지 않음): Chen et al. 2019 "Learning by Cheating", CoRL 2019, PMLR 100, pp. 66–75, arXiv 1912.12294 (https://arxiv.org/abs/1912.12294). Warrington et al. 2021 "Robust Asymmetric Learning in POMDPs"(A2D), ICML 2021, PMLR 139, pp. 11013–11023, arXiv 2012.15566 (https://proceedings.mlr.press/v139/warrington21a.html). Walsman et al. 2023 "Impossibly Good Experts and How to Follow Them", ICLR 2023 poster (https://iclr.cc/virtual/2023/poster/11786, https://mlanthology.org/iclr/2023/walsman2023iclr-impossibly/), arXiv 번호는 미확인이다.
- **보이는 것만 아는 교사 (2026-10-14 사용자: "그 교사도.. 눈으로 보고 있는 것에 대한 위치만 알게 하는 게 어때"):** 교사는 행동을 정할 때 지금 자기 카메라에 실제로 보이는 대상의 정확한 위치만 안다(단 잡고 있는 화물은 예외, 바로 아래 항목). 보인다는 것은 화각 안에 있고, 가려지지 않았고, 대상의 상당 부분이 보인다는 뜻이다. 성공 판정, 시연을 학습에 쓸지 고르는 판정, 평가 기록에는 전체 정답을 쓴다(평가 전용). 교사 성공률 관문(≥95%, 최소 40회)은 이 교사로 다시 잰다. 모든 위치를 알던 이전 교사의 성공률을 이어받지 않는다. 다음은 조정자 제안이며 사용자 확인 전이다: (1) 안 보이게 된 대상은 마지막으로 본 위치를 자기 명령으로 계산한 자기 이동으로만 갱신하고, 기억 시간은 학생이 보는 이력 길이와 맞춘다. (2) 자기 위치도 기본은 자기 명령 기반 추정이다. 정답 자기 위치는 기본이 아닌 별도 비교 실행으로만 쓴다. (3) 아무것도 안 보이면 둘러보기로 찾고, 정답 위치 쪽으로 시선을 돌리지 않는다. (4) 짝 정보는 보이는 것과 코드의 GO/ACK 메시지만 쓴다. (5) 집기·놓기 교사 모두 이 방식(프로필 이름 visible_only)을 기본으로 한다. (6) 화면 밖에서 움직이는 마지막 짧은 구간 밖에서 보이는 비율이 100%가 안 되면 버그로 본다.

  - 사용자 결정은 위 인용 범위다: 빔을 들고 옮길 때 빔의 위치를 모르게 한다.
  - 아래는 모두 조정자 해석·설계이며 사용자 확인 전이다.
  - 구간: 로봇이 "잡고 있다"고 믿는 동안이다(자기 집게 명령 이력과 자기 RGB로 판단하며, 접촉·측정 관절·정답 높이로 판정하지 않는다). 시작은 들기 확인 뒤부터, 끝은 놓기 완료까지다. 집게를 닫은 뒤 들기 확인 전의 짧은 틈은 구간 밖(보이는 것만 아는 교사 규칙)으로 두며, 이 틈을 구간에 넣을지는 열린 문제다. long_beam·heavy_crate 같은 공동 운반은 어느 로봇이든 잡은 동안 숨기고, 짝 정보는 보이는 것과 코드의 GO/ACK만 쓴다. 잡기 실패·낙하도 같은 근거(자기 명령 이력·자기 RGB)로 감지하며, 그러면 구간이 끝나고 다시 "보이는 것만 아는 교사"로 돌아간다.
  - 허용: 잡은 자세로 정해지는 자기 기준 고정 상대량(예: 집게에서 빔 중심까지의 거리, 빔 길이와 차지하는 폭), 자기 명령으로 계산한 이동량, 화물을 내려놓은 뒤 주변을 다시 볼 때 실제로 보이는 정적 지형지물·구역 표시의 관측. 지도 코드는 운반 경로를 짤 때 화물 세계 좌표를 읽지 않고 위 상대량과 자기 위치 추정만 쓴다.
  - 구현: 새 프로필 토글(프로필 설정 스위치) `held_object_hidden_v1`로 한다(기본 off, 켠 실행은 이전 결과와 합산하지 않는다). 입력 감사(실행 뒤 입력 기록 점검)로 구간 중 화물 세계 좌표를 읽은 횟수 `held_world_reads`를 실행마다 기록하고 0이어야 한다. 토글을 켜면 교사 성공률 관문(≥95%, 최소 40회)을 이 교사로 다시 잰다. 운반 중 자기 위치 추정 오차가 쌓여 놓기 정확도가 떨어지는지 별도로 본다.
- **내려놓은 뒤에는 진짜 둘러본다 (2026-10-14 사용자, 해제 관문 영상을 본 뒤: "둘러보기 위해서 아래에 뒀으면, 진짜 좀 둘러봐야 할듯"):** 위 "들고 있는 동안은 화물 위치도 모른다"의 허용 항목에 있는 "화물을 내려놓은 뒤 주변을 다시 볼 때 실제로 보이는 정적 지형지물·구역 표시의 관측"을 실제로 하게 하는 규칙이다.

  - 배경(조정자 관측(독립 재검증 아님): 해제 관문(내려놓기 성공 40/40을 잰 관문, 원본 `outputs/e2e18-admin/gcp-reports/release-gate-4a69e6bc.json`, 영상 `release-gate-39-4a69e6bc.mp4`와 `release-gate-39-frames/`) 39번 영상에서 로봇은 빔을 내려놓고 물러난 뒤 자기 끝 색 띠만 보고 바로 다시 잡거나 끝냈고 주변 지형지물은 거의 보지 않았다. 운반 중 내려놓기 진단(G2/G6)에서는 고정 카메라 팬(카메라를 좌우로 돌리는 서보 값) 3개(500/1000/2500, 단위는 원본 확인 전)가 6/6 모두 정보가 없었고, 문에서 가까운 로봇은 구역 표시를 9개 중 0–1개만 봤다.   - 목적과 금지: 목적은 자기 위치를 다시 잡는 것이다. 자기 끝 색 띠만 보고 바로 다시 잡거나 끝내지 않는다.
  - 누가 하나: 지도 코드의 주행 단계 기술(스킬)이다. ACT 학생의 파지 경로를 대신하지 않고, 근거리 파지 경로에 가드를 덧붙이는 것도 아니며(위 "금지"), 화물 세계 좌표를 읽지 않는다. 교사 시연에 이 동작을 넣으면 토글을 켠 교사로 성공률 관문(≥95%, 최소 40회)을 다시 잰다.
  - 방법: 정적 지도와 자기 추정 위치로, 그 자리에서 보일 지형지물(벽 모서리, 문, 구역 표시)의 방향을 계산해 그쪽으로 카메라나 몸을 돌린다. 둘러볼 방향을 정하는 데는 정답을 쓰지 않는다.
  - 두 로봇이 나눠 보기: 그 통신 조건의 채널로만 한다(없음 / 고정 신호 / 자연어). 통신 없음에서는 나눌 수 없으므로 각자 전부 둘러본다. 구조화된 옆길은 쓰지 않는다(AGENTS.md "역할" 항목).

- 화물 v6 (2026-10-14 사용자: "걍 타일같은 건 빼는 게 어떄? 보라 캔도 연구 목적과 상관없는 거 같아", "빠진 자리는 어떻게 할까요?" → "같은 상자로 대체 (Recommended)"): tile·can을 장면에서 미사용/최소 개수 색의 기존 작은 상자로 대체해 화물 수·작업량을 유지한다. v6 결과는 이전과 합산하지 않고 코드·이전 결과는 재생용 보존한다. 1대 교사(`sim/grasp_act_solo_teacher.py`)의 v6 운반 종류는 BOX_KINDS(cyan/red/green/yellow)뿐이다.

- **입력 분리:** 학생 입력·교사 표적·평가 정답 파일을 나누고, loader와 adapter에서 허용 목록을 검사한다.

## 5. 평가

다음을 각각 n/N으로 보고한다.

- 교사 성공
- 데이터 적합도
- 저장 장면 재생
- 학생의 새 시작 상태 성공
- 학습에서 뺀 지도(held-out)에서의 성공
- 명령 따르기(명령받은 끝·물건으로 갔는지)
- 종료 판단(누락·조기 종료)
- 물건 종류별 성공
- 2–3개 연속 반복에서 스킬 호출마다의 성공
- 시뮬레이션 호스트 CPU 추론 지연(당시 Azure VM3)

기준선은 색 띠 단계 시험의 동시 파지 1/12(검정 v426 조건 1/3)이다. 학생 보강용(DAgger) 수집 실행은 teacher-assisted로 표시하고, 학생 독립 평가 분모에서 뺀다.

## 6. 멈춘 것과 유지하는 것

- 빔 추적 비교(v434–v443)는 2026-10-14에 사용자 결정으로 종료했다("빔 추적 비교 시험 이제 안 해도 되는 거 아닌가"). 미완료로 기록했다(PR #483, `f529e078`). 손으로 짠 근거리 인식·기억 가드를 ACT 경로에 덧붙이지 않는다.
- 판단 LLM은 Gemma를 유지한다. DeepSeek V4.1 Flash는 400결정 확인에서 111/400이었다(Gemma 140, 규칙 135). 기본 off 옵션으로만 남긴다.

## 7. 장기 작업 안정성

- 판단 LLM 호출 한 번의 실패·지연은 기존 "역할" 규칙대로 대체 규칙이 맡는다. 429·형식 오류도 한 번 실패로 보되, 기존 계획기 중단 조건(HTTP 오류 연속 5회 정지, 20결정 뒤 형식 오류 관문)을 따른다. 다만 연결 자체가 끊긴 경우(릴레이·터널·공급자 연결 실패가 연속 3회, 또는 30 SIM초 넘게 지속)는 실행을 멈추고 HOST_ERROR로 기록한다. 그 실행을 LLM 실행으로 세지 않는다. 2026-10-14 v440은 릴레이 연결 오류로 Gemma 없이 규칙으로만 돌았다.
- 앱 종료(2026-10-14 10:57)로 Codex·감시가 끊겼다. 작업 상태는 자주 커밋·push해서 바로 이어갈 수 있게 한다.
- VM은 유휴 20분·부팅 8시간 자동 정지를 유지한다. 긴 데이터 생성은 8시간 단위로 끊어서 잇는다.

## 8. ACT 위 강화학습 DEV 시험 (2026-10-16 사용자 결정)

사용자 원문: "그리고 강화학습도 시도해보면 좋을듯 지금부터. ACT가 있긴 하니까 그걸 강화학습하면 과연 좋아질지".
조정자 질문: "강화학습의 보상과 학습용 평가자(critic)에 시뮬레이터 정답(물체 위치·접촉·들린 높이)을 써도 될까요? 로봇 정책의 입력(자기 카메라·자기 명령)은 그대로 두고, 정답은 학습 중에만 씁니다".
사용자 선택: "학습 중에만 허용 (Recommended)".

- 보상(접근·정렬 진척·들기 성공 등)과 비대칭 critic은 **학습 중에만** 시뮬 정답을 읽을 수 있다.
- actor 입력은 기존 ACT의 자기 RGB 이력·자기 발행 명령 이력·스킬/물건 종류/자리 번호표뿐이다.
  critic·보상·접촉·측정 관절·물체 정답을 actor의 행동/종료/스킬/카메라 선택에 전달하지 않는다.
- 평가 실행의 정책 입력에는 정답이 없다. 정답은 별도 성공 판정 전용이다.
- weld OFF·정상 물리·held_object_hidden_v1 유지. 허용된 학습 GT 읽기와 정책 입력 위반 감사를 분리한다.
- ACT+작은 학습 잔차는 기본 off인 별도 DEV 비교다. 3절의 기본 학생 ACT를 자동 대체하지 않는다.
  MJWarp와 C 결과·호스트/장면/모델별 코호트는 합산하지 않는다.
- [rl1 설계·예산·평가 계획](../experiments/2026-10-16-rl1/README.md)에 기준 체크포인트,
  ResFiT식 off-policy 잔차, PPO 대안, 밀집 보상, 같은 시드 짝 평가를 기록했다.

### rl1b 범위 축소 (2026-10-16)

사용자: "흠 니말대로면 ACT를 좀 더 학습하고 하는 게 나을려나? 아니면 너가 좀 휴리스틱을 주면 안돼?",
이어 "자고 올테니까 너가 알아서 계속 진행해줘!".
조정자 결정은 MJWarp 시연으로 ACT를 더 학습하는 act16w를 우선하고 본 RL(rl2)을 그 ACT16 위에서
진행하는 것이다. **rl1b는 고정 ACT15 위의 짧은 신호 확인**이며 이전 rl1의 2h 학습/6h 전체 예산을
이번 실행에 적용하지 않는다. GPU 사용은 준비·측정·학습·평가 합계 최대1시간으로 제한한다.

- 학습 전용 h1(자기 화면 중심 선호·화면 밖 벌점), h2(안정 들기 전 첫 done 벌점),
  h3(정렬 오차의 signed potential 진척), h4(훈련 시작 분포의 쉬운→전체 커리큘럼)를
  각각 기본 off 토글로 둔다. h5 DAgger는 ACT 데이터 작업에 남기며 rl1b에서 수행하지 않는다.
- 휴리스틱은 학습 보상/훈련 reset에만 사용한다. actor 입력·미세 행동·종료·평가 reset에
  정답을 전달하거나 손으로 짠 근거리 경로를 추가하지 않는다. 학습 정답 허용 범위는 위 사용자 선택 그대로다.
- h1은 성공한 교사의 마지막 화면 밖 구간도 벌할 수 있다. 보상 성분의 저장 경로 감사와 정책 개선을
  구분한다. 같은 궤적의 ON/OFF 재채점은 인과적 정책 ablation으로 보고하지 않는다.
- 기존 교정 원본에는 인과적인 done 정답이 없어 done 잔차는0이다. h2 벌점이 즉시 종료 출력을
  바꾸도록 GT 가드를 넣지 않는다. 변화 가능성·제약을 실제 측정과 함께 보고한다.
- warp1 교사 전용 전송기는 actor/reset 검증을 대신하지 않는다. 서로 다른 시작 상태·부분 reset·
  자기 RGB·정답 분리의 실제 backend binding이 준비된 뒤에만 GPU 시험을 제출한다.
- 별도 최종 시작918000–918039 중 사전 고정 첫8개를 ACT15와 짝 비교한다.
  rl1b 구현 설계(개별 값 사용자 확인 전)는 S1 cyan_1/frozen6f 장면의 같은 정적 모델로 좁히고,
  첫 훈련 청크의 처리 시간으로 학습 전에 고정한 SIM prefix를 두 모델에 동일하게 적용한다.
  실제90 SIM초 계약은 유지하며 prefix cap_end는 전체 과제 실패로 해석하지 않는다. 미실행·미완료는
  성공0으로 바꾸지 않는다. 신호/무신호/BLOCKED와 완료·단계 진척을 각각 기록한다.
