# 실행 구조 결정 기록: 판단 LLM + 정답 교사 → ACT 학생 (2026-10-14)

2026-10-14에 사용자와 정한 결정이다. 결정이 바뀌면 이 문서에 날짜와 사용자 원문을 붙여 고친다. 근거가 같은데 이전 방식으로 되돌리지 않는다. 진행 기록은 PR #484(`claude/e2e18-grasp-rootcause`)와 `experiments/2026-10-14-e2e18-grasp-rootcause/`에 둔다.

## 1. 왜 바꿨나

- 손으로 짠 근거리 파지는 두 로봇 동시 파지가 1/12였다(검정 v426, 293.1 SIM초). 첫 시도 성공은 0/12였다. 후보는 v375→v384–386→v426–431→v434–443으로 이어졌다. 같은 미도달 실패가 두 번 연속 나왔다.
- 크기 확인(Codex 감사, PR #484): 집게 안쪽 폭은 61 mm, 봉 폭은 40 mm다. 그래서 한쪽 여유는 10.5 mm다. 원거리에서 추정한 끝 위치 오차는 중앙값 약 65–70 mm로, 여유의 6배가 넘는다. 근거리 정렬 프레임의 오차는 훨씬 작았다.
- 사용자: "근본적으로 좀 해결하자". 실행 계층을 정답 기반으로 추상화해 본 연구와 분리하는 제안은 거절됐다("아니다").

## 2. 구조

| 일 | 맡는 쪽 | 입력 |
|---|---|---|
| 무엇을 먼저·누가·몇 대로·어디로·어느 끝, 기다리기·다시 잡기, 여러 화물의 반복 순서 | 판단 LLM(Gemma 4 31B @DeepInfra fp4, v405) | 자기 RGB·정적 지도·자기 명령 이력·통신 조건의 받은 메시지. **위치 정답 없음** |
| 주행·운반 경로 | 지도 기반 코드(현행) | 정적 지도 + 자기 RGB·명령으로 추정한 자기 위치 |
| 화물 근처 접근·정렬·집기·놓기 | ACT 학생 | 자기 RGB 이력, 자기 발행 명령 이력(팬 포함), 이산 번호표(스킬·물건 종류·자리) |
| 시연 생성(학습용만) | 정답 교사 코드 | 모든 로봇·물체 위치, 관절/IK, 접촉("모든 위치를 다 아는 느낌으로") |

- 사용자 원문: "llm이 판단할 때에는 위치를 모르게, 코드는 위치를 알게 해서 교사 그걸 만들고 ACT를 만들어", "가장 좋은 구성으로 가주고".
- ACT에는 자유 문장을 넣지 않는다. LLM이 고른 스킬을 코드가 형식·안전 검사한 뒤 번호표로 바꾼다.
- ACT는 행동 청크(0.8 SIM초) 단위로 실행한다. 코드는 청크 사이에서 기다리기·멈춤·안전 정지로 끊을 수 있다.
- 종료는 ACT의 완료 출력과 코드의 자기 카메라 확인을 함께 본다. 확인이 안 되면 LLM에 "모름"으로 돌려준다. 정답·접촉 판정은 돌려주지 않는다.
- ACT 구간은 지도 주행이 도착하고, 자기 RGB로 추정한 끝까지 거리가 0.8 m 이하일 때 시작한다.
- 지도 코드 운반이 실패로 확인되면, 같은 교사 데이터로 운반 구간도 ACT에 학습시킨다(아래 4절의 구간 라벨).

## 3. 모델과 학습 자원

- **학생 모델은 ACT 하나**(사용자: "하나로 정해", "ACT로 가자"). 근거는 다음과 같다.
  - 추론은 시뮬레이션 중 VM3 CPU에서 한다(16 실행 × 로봇 2대, 물리가 이미 코어를 씀). 그래서 수억–수십억 파라미터 VLA는 제외했다.
  - 반복 계산이 필요한 Diffusion 계열은 불리하다.
  - π0/π0.5는 LoRA로도 GPU 메모리가 22.5 GB를 넘게 필요해, Kaggle 16 GB에 맞지 않는다.
  - VLA의 사전학습은 우리 화면과 다르고, 언어는 LLM이 맡는다.
  - ACT는 작업당 50 시연으로 정밀 작업 84–96%를 냈고(6개 작업 중 5개), 각본 교사 시뮬레이션에서 86%를 냈다.
  - 검토한 후보는 π0.5, GR00T N1.6/N1.7, SmolVLA, X-VLA, MolmoAct2, OpenVLA-OFT, Diffusion Policy, One-Step Flow Policy(2026), Normalizing Flow Policy다.
  - 재검토 조건: held-out 성공이 낮고, 그 원인이 모델 표현력으로 확인될 때만 One-Step Flow Policy를 올린다.
- **GPU는 Kaggle**(사용자: "Kaggle ㄱㄱ 하자").
  - 학습 데이터는 **비공개** dataset으로 올리는 것을 허용한다. 올린 뒤 서버 메타데이터로 private인지 확인한다.
  - 업로드는 Mac에서 한다. 서버에 Kaggle 자격 증명을 두지 않는다.
  - 2026-10-14 확인: CLI 2.2.4 OAuth, GPU 30 h/주, 갱신 10/17. 세션 9–12시간을 가정해 중간 저장과 이어 학습을 한다.
  - Azure GPU 할당량은 전 계열 0이다. 증가 요청은 하지 않았다(사용자 결정 사항).
  - Mac(M3 16 GiB)과 VM3 CPU는 파이프라인 확인용 작은 학습에만 쓴다.

## 4. 데이터

- **교사 관문:** 단계마다 교사 물리 성공률 ≥95%를 확인한 뒤에만 데이터를 생성한다(weld OFF, 처음 배치 뒤 위치 덮어쓰기·붙이기 금지).
- **넓히는 순서:** (1) long_beam 2대 → (2) 1대 화물 집기·놓기 → (3) heavy_crate 2대 → (4) tri_frame 3대. 최종 E2E는 s1–s8(로봇 3대, 여러 화물 반복)이다. 장면은 현행 하드웨어 대응 v4를 쓴다.
- **개수:** 고정하지 않는다.
  - 50개는 ACT 논문의 근거로 파이프라인 확인에 쓴다. 이전에 말한 500개는 근거 없는 추정이었다.
  - 100/200/400개 크기 곡선에서 held-out 성공이 평평해지는 지점에서 멈춘다.
  - 그 뒤 DAgger로 학생이 실패하는 상태를 보강한다.
- **다양성:** Lin et al. 2024에 따르면 다양성이 시연 수보다 중요하다.
  - 봉 위치·방향 0–360°, 로봇 0.5–2.0 m·방위 0–360°·방향 ±60°·팬 전체, 맡을 끝 50:50.
  - 짝 로봇은 4가지 경우(없음 / 다른 끝 / 다가오는 중 / 내 끝 근처).
  - 주변 방해 화물, 이미 옮긴 중간 상태도 섞는다.
  - 교사 잡음(DART)을 넣되, 라벨은 잡음 없는 교사 행동이다.
- **지도 다양화:** 학습 장면의 벽·문·구역·화물 배치를 절차적으로 바꾼다. 렌더(floor_light_v1)·카메라·외관·물리는 고정한다. 지도마다 파일과 sha256을 남긴다. 연구 지도는 평가용이고, 그중 하나는 학습에서 완전히 뺀다.
- **끝 식별:** 끝 색(청록/파랑) 장면을 기본으로 쓴다. 검정 양끝은 영상만으로 구별되지 않는다. 사용자 허용, 새 장면 버전, 이전 결과와 합산 금지.
- **전체 기록:** 교사 실행 때 집기만이 아니라 주행·운반·문 통과·내려놓기의 학생 입력과 교사 행동을 전부 남긴다. 구간 라벨(주행/접근/집기/운반/놓기)을 붙인다.
- **입력 분리:** 학생 입력·교사 표적·평가 정답 파일을 나누고, loader와 adapter에서 허용 목록을 검사한다.

## 5. 평가

다음을 각각 n/N으로 보고한다.

- 교사 성공
- 데이터 적합도
- 저장 장면 재생
- 학생의 새 시작 상태 성공
- held-out 지도 성공
- 명령 따르기(명령받은 끝·물건으로 갔는지)
- 종료 판단(누락·조기 종료)
- 물건 종류별 성공
- 2–3개 연속 반복에서 스킬 호출마다의 성공
- VM3 CPU 추론 지연

기준선은 검정 v426 동시 파지 1/12다. DAgger 수집 실행은 teacher-assisted로 표시하고, 학생 독립 평가 분모에서 뺀다.

## 6. 멈춘 것과 유지하는 것

- 빔 추적 비교(v434–v443)는 2026-10-14에 사용자 결정으로 종료했다("빔 추적 비교 시험 이제 안 해도 되는 거 아닌가"). 미완료로 기록했다(PR #483, `f529e078`). 손으로 짠 근거리 인식·기억 가드를 ACT 경로에 덧붙이지 않는다.
- 판단 LLM은 Gemma를 유지한다. DeepSeek V4.1 Flash는 400결정 확인에서 111/400이었다(Gemma 140, 규칙 135). 기본 off 옵션으로만 남긴다.

## 7. 장기 작업 안정성

- 판단 LLM 호출이 연속 실패하면 대체 규칙으로 계속 돌지 않는다. 실행을 멈추고 HOST_ERROR로 기록한다. 2026-10-14 v440은 릴레이 연결 오류로 Gemma 없이 규칙으로만 돌았다.
- 앱 종료(2026-10-14 10:57)로 Codex·감시가 끊겼다. 작업 상태는 자주 커밋·push해서 바로 이어갈 수 있게 한다.
- VM은 유휴 20분·부팅 8시간 자동 정지를 유지한다. 긴 데이터 생성은 8시간 단위로 끊어서 잇는다.
