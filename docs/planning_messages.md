# 계획기와 메시지 규칙

로봇마다 LLM 하나가 무엇을 할지 고르고, 그 행동에 메시지를 덧붙일지 답한다. 이 문서는 [전체 구조](architecture.md)의 계획층 세부다. 2026-11-16 동결 직전 설계 기준이다. 고른 행동을 어떻게 실행하는지는 [실행층](execution_layer.md)에 있다.

## 1. 계획기가 받는 것과 받지 않는 것

연구 질문은 "각 로봇이 아는 것이 다를 때 LLM 계획이 팀 구조에 따라 어떻게 달라지나"다. 그래서 위치 측정은 동작에만 쓰고, 계획기가 아는 과제 정보는 로봇마다 나눈다.

| 받는 것 | 내용 |
|---|---|
| 자기 방 이름 | 시작은 "상자 방", 자기가 문을 지난 뒤는 "목적지 방". 천장 카메라가 아니라 자기 진행(실행층의 보고)에서 나온다 |
| 본 상자 | 자기 카메라로 본 목록(색, 거리) |
| 자기 주문 | 과제가 준 자기 몫만 |
| 자기 능력 | 집을 수 있는 색 |
| 받은 메시지 | 다른 로봇이 보낸 것(4절) |
| 자기 진행 | 실행층의 보고: 집기 실패, 문 통과, 운반 끝 |

주문은 팀 전체의 것이고 개수는 팀 합계라는 것, 주문에 없는 상자를 옮기면 감점이고 할 일이 없으면 끝내도 된다는 것은 모든 구조에 같은 과제 규칙으로 준다.

| 받지 않는 것 | 알게 되는 길 |
|---|---|
| 자기 위치와 방향의 좌표 | 방 이름까지만 안다 |
| 다른 로봇의 위치 | 메시지로만 안다 |
| 다른 로봇의 주문, 계획, 진행 | 메시지로만 안다 |
| 벽, 문, 목적지 표식의 위치 | 받지 않는다. 벽과 문은 실행층이 쓰고, 표식은 로봇이 자기 카메라로 번호를 읽어 찾는다 |

## 2. 결정 순서

순서는 CoELA 에서 빌렸다(메시지 초안, 행동 목록, 고르기). 메시지를 행동과 따로 한 차례로 세지 않고 행동에 덧붙이는 점이 다르다. 그래서 이 규칙을 "CoELA 방식 통신"이라고 부르지 않는다. 결정할 때가 되면 실행층이 계획기에 묻는다.

| 순서 | 누가 | 내용 |
|---|---|---|
| 1 메시지 초안 | LLM | 지금 알릴 것이 있으면 메시지를 쓴다. 이 단계에서는 보내지 않는다 (T0 는 이 단계가 없다) |
| 2 행동 목록 | 코드 | 로봇이 아는 것으로 지금 가능한 행동만 넣는다. 든 상자를 내려놓고 끝내는 행동도 들어 있다. 초안은 목록 위에 한 줄로 보여 준다 |
| 3 고르기 | LLM | 행동 하나를 고르고, 그 행동과 함께 초안을 보낼지(send) 답한다. 답은 `{"action": 라벨, "send": true 또는 false}` 꼴이다 |

## 3. 고르는 것

| 결정 지점 | 고르는 것 |
|---|---|
| 집을 상자 | 자기 목록의 몇 번째, 또는 기다리기 |
| 목적지 | 벽의 번호 표식 11·12·13, 기다리기, 또는 내려놓고 끝내기 |
| 문 | 지금 지나기, 기다리기, 또는 내려놓고 끝내기 |
| 내려놓기 | 든 상자를 그 자리에 내려놓고 끝내기(목적지, 문 앞 재결정, 문 결정에서) |
| 덧붙이기 | 위 행동 어느 것에든 메시지를 붙일지 |

### 한 번 운반과 내려놓기

이번 실험의 과제 문장은 "각 로봇은 한 번 운반한다. 상자 하나를 나르고, 그 상자를 내려놓으면 그 로봇의 실행은 끝난다"이다. 돌아가기, 두 번 나르기, 메시지로 상자 넘겨주기는 2단계로 미룬다([작업 계획](plan.md)).

주문에 없는 상자를 옮기면 감점이므로 "하지 않기"도 고를 수 있어야 한다. 그래서 목적지 결정, 문 앞 재결정, 문 결정에서 모든 구조가 같은 선택지 하나를 더 받는다: "든 상자를 여기 내려놓고 끝낸다". 고르면 그 자리에서 상자를 내려놓고 그 로봇의 실행이 끝난다. 상자는 표식 밖에 놓이므로 틀린 배치로 세지 않는다. 채점에서는 이 선택을 빈 배정으로 읽고, 내려놓음을 따로 센다([연구 설계 11절](research_design.md#11-이번-제출의-동결-설계-2026-11-16)).

## 4. 메시지 규칙

T1, T2 에만 해당한다. T0 는 메시지 단계가 없다.

팀 구조는 계획기가 아니라 메시지가 오가는 통로를 바꾼다. 팀장은 지시문으로 지정하고(기본 r1), 팀장도 자기가 본 것과 받은 보고만 안다.

| 구조 | 2대 | 3대 (r1 이 팀장) |
|---|---|---|
| T0 | 보내지 않는다 | 보내지 않는다 |
| T1 | 서로에게 | 누구나 누구에게나 |
| T2 | T1 과 통로가 같고 팀장 지시문만 더한다. 계층 구조가 아니라 지시문 한 줄의 효과이므로 T1 과 우열을 가리지 않는다 | 팀장 r1 은 r2, r3 모두에게, r2 와 r3 은 r1 에게만 |

T0 도 다른 로봇이 있다는 것은 안다. 몸 움직임 규칙(양보, 듣기 4초 등)은 모든 구조에 같으므로 T0 는 "작업 정보 통신 없음"이지 조율이 전혀 없는 것은 아니다.

| 항목 | 규칙 |
|---|---|
| 행동에 덧붙이기 | 메시지는 행동이 아니라 행동에 붙는 것이다. 보내도 차례를 쓰지 않는다. 연속으로 보내는 것도 막지 않는다 |
| 이동 중 답장 기회 | 이동 중에도 상대가 결정·보고 지점에서 쓴 새 메시지가 도착했고 자기 결정 지점이 열려 있지 않을 때만 한 번, 보낼지 판단할 기회가 온다. 기회로 보낸 답장은 상대의 기회를 열지 않는다(답장이 꼬리를 무는 것을 끊는다) |
| 상한 | 로봇당 8개(이동 중 기회와 사전 교환 포함). 넘으면 초안, 보낼지 묻기, 기회가 모두 호출 없이 건너뛰어진다 |
| 예산을 LLM 에 알림 | 과제 설명에 "최대 8개, 반복하거나 불필요하면 감점"을 적고, 상태 줄에 남은 수(`Messages left: N`)를 보여 준다. 채점 기준을 모르는 행위자를 깎는 것은 불공정하기 때문이다 |
| 전달 | 보낸 뒤 2초 뒤에 도착한다. 받는 쪽은 받은 최근 5개와 자기가 보낸 1개를 본다. 누구에게 보내는지는 위 표를 따른다 |
| 알려 준 말과 채점의 차이 | 알려 주는 문구는 "최대 8개, 반복·불필요하면 감점"이고, 채점(SP, [연구 설계 11절](research_design.md#11-이번-제출의-동결-설계-2026-11-16))은 "로봇당 허용 2개를 넘으면 필요한 메시지도 감점"이다. 문구를 채점에 맞춰 고치지 않았고 차이를 그대로 밝힌다 |

이렇게 한 까닭: 옛 규칙은 보내기가 한 차례를 써서, 메시지가 늦게 도착하는 실패가 규칙 탓인지 LLM 판단 탓인지 가를 수 없었다. 그래서 자유롭게 보내게 하되 많이 말하면 점수를 낮춘다. 문구와 규칙은 개발 장면의 실행을 보고 몇 차례 고쳤고(예산 알림, 답장 기회 조건, 답장 연쇄 차단), 동결 뒤에는 고치지 않는다.

## 5. 출력 상한과 계획기 고장 처리

| 항목 | 내용 |
|---|---|
| 출력 상한 | 한 답 2048 토큰. 처음에는 768 이었으나 일부 응답이 숨은 추론으로 상한에 걸려 멈춰 올렸다. 모든 구조에 같은 값이다 |
| 상한에 걸려 멈춘 경우 | 그 실행은 "계획기 응답 오류로 멈춤"이라는 고장으로 본다. 고장 칸에만 1회 다시 돌린다. 첫 기록은 지우지 않고 둘 다 남기며, 또 고장이면 실패로 남긴다 |
| 고장이 아닌 것 | 틀린 선택, 문 교착, 시간 상한 도달, 집기 실패, 메시지 상한 도달은 고장이 아니라 결과다. 점수가 나쁘다는 이유로 다시 돌리지 않는다 |

호출 수 상한과 시간 상한 같은 고정값은 [작업 계획 10절](plan.md#10-동결-기록과-아직-정하지-않은-것), 다시 돌리는 규칙 전체는 [작업 계획 7절](plan.md#7-지키는-것)에 있다.

## 6. 참고한 연구

| 구조 | 따른 선행 연구 |
|---|---|
| T0 | CoELA 의 통신 끔 조건 |
| T1 | CoELA 의 팀 구성(규칙은 다름) |
| T2 | Organized Teams. 팀장 지정 지시문 |
| T3 (부록) | HMAS-2. 중앙에서 계획 초안을 내고 일을 맡은 로봇이 검토한다. 계획 전용 환경의 시험에서 정보를 모두 줘도 풀리지 않아 본 비교에서 뺐다 |

- CoELA: Zhang et al., *Building Cooperative Embodied Agents Modularly with Large Language Models*, arXiv:2307.02485. 계획기의 순서(메시지 초안, 행동 목록, 고르기)와 기억 구성. 우리 메시지 규칙은 이와 다르다(4절). CoELA 원문의 통신 비용과 지표는 확인하지 않았다.
- Organized Teams: Guo et al., *Embodied LLM Agents Learn to Cooperate in Organized Teams*, arXiv:2403.12482. 팀장 지정 지시문.
- HMAS-2: Chen et al., *Scalable Multi-Robot Collaboration with Large Language Models: Centralized or Decentralized Systems?*, arXiv:2309.15943. 중앙 초안과 검토 절차.
