## 외형 계약

2026-11-13 기준이다. 벽은 짙은 초록, 상자는 빨강·파랑만 사용한다. 벽 표식과 AprilTag, 미리 만든 정적 지도, 공용 TOP 입력을 쓰지 않는다. 이 묶음의 측정도 TOP·마커 경로 대신 자·각도기 등의 독립 수기 측정과 자기 카메라를 사용한다. 경기장 치수·바닥 재질·상자 치수와 질량은 현장에서 재고 버전으로 남기며 임의 값을 만들지 않는다.

| 대상 | 시뮬 색 값 | OpenCV HSV 초기 임계 |
|---|---|---|
| 벽 | RGBA `.05 .27 .14 1` | `55 <= H <= 85`, `S > 110`, `V < 140` |
| 빨강 상자 | RGB `.80 .12 .10` | `(H <= 8 or H >= 172)`, `S > 150`, `V > 90` |
| 파랑 상자 | RGB `.10 .25 .85` | `110 <= H <= 124`, `S > 170`, `V > 70` |

H는 OpenCV 8-bit HSV의 0–179, S/V는 0–255다. H의 도 단위 0–360과 섞지 않는다. RGBA/RGB는 렌더 재질 값이지 카메라에서 관측될 픽셀이나 페인트 색상표가 아니다. 빨강·파랑의 alpha 값은 사용자 RGB 지정에 임의로 추가하지 않는다.

## 실물 사진으로 다시 맞추기

1. 실제 장착한 자기 카메라로 RGB 640×480 원본을 보존한다. 조명·노출·화이트밸런스·그림자·거리·시점을 기록한다. 모터를 움직이지 않는 사진 수집은 다른 과제와 병렬 가능하다.
2. 학습/조정용 사진과 최종 확인용 사진을 촬영 세션 단위로 먼저 나눈다. 같은 사진의 인접 프레임을 양쪽에 섞지 않는다. 구분한 파일 목록과 sha256을 보존한다.
3. 사람이 빨강·파랑·벽·배경의 마스크를 만든다. 어두운 벽, 반사, 가려진 상자, 바닥과 로봇 몸체도 포함하고 임의로 실패 사진을 제외하지 않는다.
4. OpenCV로 읽은 BGR은 `COLOR_BGR2HSV`, RGB 배열은 `COLOR_RGB2HSV`를 쓴다. 원본과 모델 입력 320×240 각각에서 마스크를 확인한다. resize 순서와 보간법을 기록하고 학습 전처리를 묵시적으로 바꾸지 않는다.
5. 위 초기 임계를 적용해 대상별 precision/recall과 오분류 표를 낸다. 적합 사진에서 H/S/V 분포와 실패 사진을 보고 경계를 조정한다. 빨강 hue wrap의 두 구간을 유지한다.
6. 잠근 임계를 미사용 사진에 한 번 평가하고 환경 버전·전처리 해시·조정 전후 수치를 남긴다. 재조정하면 새 검증 집합을 마련하며 기존 검증을 미사용이라고 재명명하지 않는다.

실물 통과 후보는 [T01](tasks/T01_environment.md)의 근거와 함께 검토한다. 지금 임계를 실물 보장값으로 쓰지 않는다. 실제 카메라 FOV나 장착 위치를 검출에 유리하게 바꾸지 않는다. calibration board는 **offline 보정 후 제거**하며 실행 랜드마크가 아니다.

## 기존 자료 재사용

[실측 프로토콜](../sim2real_measurement_protocol.md)의 카메라·정적 치수 절과 [측정 템플릿](../../configs/real_measurements_template.json)을 링크로 재사용한다. 옛 문서의 색·지도·마커 예시는 현재 환경의 허용 입력으로 승계하지 않는다. 실물 색 분포와 사진 판정은 **확인 안 됨**이다.
