# T12 Pair 1비트 신호

## 목적
두 로봇 사이 허용된 1비트 신호 송수신과 연결 단절 처리를 검증한다. 통신 통과는 공동 들기 성공이 아니다. 실물 결과는 **확인 안 됨**.

## 준비물
두 endpoint(모의 프로세스부터 가능), 동일 로컬 네트워크, 송수신 로그, 패킷 지연/손실 주입 도구. 주소·인증정보는 공개 결과에 넣지 않는다.

## 병렬 준비와 물리 통합
모터 없는 통신 시험은 완전히 독립이며 다른 과제 완료가 필요 없다. 실제 구동에 연결하는 후속 시험에만 T06/07 정지·기록 계약이 필요하다. 본 카드는 들기 명령을 실행하지 않는다.

## 실행절차
1. 0/1 의미와 초기 상태·재연결·만료 정책을 명세한다. 두 로봇 통신 허용을 상대 위치·GT 전달 허가로 확대하지 않는다.
2. 업무 payload는 1비트로 제한한다. sequence/송수신 시각 같은 transport 감사 정보가 정책 입력 옆길로 들어가지 않도록 분리한다.
3. 양방향 전송·echo/ACK를 시험하고 같은 기기 시계로 RTT를 잰다. 다른 기기의 monotonic 시각 차이를 편도 지연이라고 하지 않는다.
4. 지연·중복·역순·손실·끊김을 주입해 오래된 ready가 새 허가로 받아들여지지 않는지 본다.
5. 통신 실패 시 구동 허가가 생기지 않도록 모의 검사하고 실제 Pair 파지·들기 검증은 별도 과제로 남긴다.

## 수치 통과기준
**초안 제안·실물 미검증·담당자 합의 필요:** 정상 링크에서 방향별 100회, 수신/응답 ≥99/100, RTT P95 ≤0.10 s. 오류 주입 시 오래된/중복 신호에 의한 새 구동 허가 0건. 주입 case별 N·손실·재시도·지연을 별도로 제출한다.

## 기준의 근거
100회·99/100은 초기 링크 파일럿 제안이고 0.10 s는 10 Hz 한 주기와 비교하기 위한 목표다. 네트워크 보장이나 공동 들기 동기 한계가 아니다. 실제 지연 분포와 안전 동기 설계 합의 전 제어 timeout 상수로 쓰지 않는다.

## 시뮬 기준
Pair 폐루프 함께 들기 아직 0, 전체 시도 분모 미제공. 두 로봇 통신 허용, Solo와 같은 단계 분해 적용 계획. 현재 1비트 물리 통신 성능은 확인 안 됨.
