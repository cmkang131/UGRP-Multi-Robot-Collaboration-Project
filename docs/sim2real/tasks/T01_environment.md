# T01 경기장 외형과 색 임계

## 목적
짙은 초록 벽과 빨강·파랑 상자를 자기 RGB에서 구별하고 실물 조명에 맞는 HSV 설정을 만든다. 실물 결과는 **확인 안 됨**.

## 준비물
실제 벽·상자·바닥 재료, 자기 카메라, 조명/노출 기록, 사람이 표시한 대상·배경 마스크. 공용 TOP·지도·AprilTag는 쓰지 않는다.

## 병렬 준비와 물리 통합
다른 과제 완료 없이 사진 수집·라벨링 가능. T02 보정이나 resize가 바뀌면 해당 전처리로 다시 평가한다. 로봇 구동은 필요 없다.

## 실행절차
1. [환경 절차](../01_environment.md)에 따라 색·재질·사진 조건을 기록하고 조정/미사용 확인 사진을 먼저 분리한다.
2. 사용자 HSV 초기값을 적용하고 클래스별 TP/FP/FN과 배경 오검출을 센다.
3. 조정 사진의 분포로만 임계를 바꾸고 설정·전처리 해시를 잠근다.
4. 미사용 사진 전체에서 원본/320×240 마스크를 비교하고 실패 사진도 보존한다.

## 수치 통과기준
**초안 제안·실물 미검증·담당자 합의 필요:** 미사용 사진 30장 이상, 빨강·파랑·벽 각각 등장 사진 10장 이상(한 사진에 여러 클래스 가능); 각 클래스 픽셀 precision와 recall 각각 ≥0.90. 사진·클래스별 결과와 전체 집계 모두 제출한다. 실행 장면의 AprilTag·보정 보드 0개는 입력 제한 준수 항목이다.

## 기준의 근거
30장/클래스 10장과 0.90은 밝기·그림자·시점별 오류를 처음 드러내기 위한 검토 제안이지 검증된 사양이 아니다. 실제 사진 분포와 T08/T11 실패 민감도를 근거로 합의하기 전 코드 수용 상수로 사용하지 않는다.

## 시뮬 기준
벽 RGBA `.05 .27 .14 1`, 빨강 RGB `.80 .12 .10`, 파랑 RGB `.10 .25 .85`. HSV는 빨강 H≤8 또는 ≥172·S>150·V>90, 파랑 H 110–124·S>170·V>70, 벽 H 55–85·S>110·V<140. 모두 사용자 지정 초기값이며 실물 보장 아님.

## PR 결과 상대경로와 형식
`experiments/sim2real-<YYYYMMDD>-T01-<run>/`: [공통 template](../04_tasks.md#result-template)의 네 파일과 `hsv.json`, `color_metrics.csv`를 제출한다. CSV 헤더: `image_id,split,class,tp,fp,fn,precision,recall,lighting,exposure,reason`. `hsv.json`에는 채널 범위·변환 순서·전처리 해시를 담고 사진/마스크는 manifest로 연결한다.
