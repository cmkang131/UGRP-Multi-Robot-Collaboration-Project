# 자기 화면 검사 기준 재정 절차 (floor_light_v1)

2026-10-03 사용자 결정("화면 검사 기준을 지금 조명에 맞게 정식 절차로 다시 정하기")에 따른다. 조명은 `floor_light_v1`로 유지하고 기준을 조명에 맞춘다. 로봇이 보는 입력은 그대로(자기 RGB, 정적 지도, 자기 명령)이며, 정답 좌표는 **오프라인 라벨 붙이기**에만 쓴다.

## 1. 왜 다시 정했나

옛 기준은 이전 조명(그림자·어두운 바닥)에서 정한 값이다. `floor_light_v1`에서는 바닥과 벽이 푸르스름해(채도 S 57~91) 벽 경계의 정상 열이 대부분 "채색 물체"로 버려졌고, 반대로 벽면 음영의 가짜 띠가 통과해 입자 필터가 틀린 위치로 쏠렸다. 평평한 바닥만 보이는 정상 화면은 "질감 없음"으로 무효 판정됐다. 측정은 `docs/execution_versioning.md`의 실행 번들과 함께 기록한다.

검토했으나 바꾸지 않은 기준과 이유:
- 어두운 화소 비율 < 25 %(`zone_pair_vision.py`, 광학 검정 기준): 검정 덮개 30 % 이상은 이미 모두 거부하고, 정상 화면의 거짓 거부가 0이다.
- 설정 시간 0.2 s(`selected_config_v3.json`): MuJoCo 렌더는 움직임 번짐이 없고, 0.2 s 뒤 회전 오차는 0.17° 이하(약 1.8 px)다.
- 측정 채택 기준 `MIN_INLIER_FRACTION` .66(`owncam_recovery_v6.py:18`): 새 관측이 들어오면 정상 동작한다(재생에서 확인).
- `owncam_pair_beam_v2.py:38, 140-142`(빔 색 S 100, 어두운 띠 등): 문턱 문제가 아니라 기하 문제다. 바닥 집기 자세에서 빔이 시야에 없다(18개 빔 점 중 0). 재정으로 고칠 수 없어 PR #363 담당에게 넘긴다.
- 얼린 검출기 `markerless_probe.py:75-93`(대비 6, 띠 표준편차 3 등): 해시로 고정되어 있어 바꾸지 않고, 아래 단차 검사가 뒤에서 거른다.

## 3. 절차

1. **자료 분리.** 보정용과 확인용은 서로 다른 실행, 서로 다른 지도에서 가져온다. 보정: v88 보정 실행(두 문 지도)과 v92 짐 든 실행. 확인: v96 탐침 실행과 PR #363 기록 프레임(문 기하 지도). 보류 자료(v91/v95)는 열지 않는다. 사용한 모든 `frames.jsonl`의 sha256을 기록한다.
2. **라벨 붙이기 (정답은 여기서만).** 정답 위치와 지도에서 기대 경계 행을 계산해 `|관측 − 기대| < 4 px`이면 "맞은 열", 아니면 "틀린 열". 화면은 정상 실행의 모든 프레임이 유효이고, 나쁜 화면은 유효 원의 아래 f를 검정으로 덮거나 단색으로 만들어 오프라인에서 만든다.
3. **규칙(보정 자료의 맞은 열/유효 프레임에서만 계산).**
   - S 한도 = 1.2 × (벽 띠 창 최대 S의 99.9 백분위), 10 단위 반올림 → 117 × 1.2 = 140.
   - 단차 하한 = 0.5 × (맞은 열 단차의 0.5 백분위), 반올림 → 0.5 × 19.5 = 10.
   - 대비 폭 = 0.5 × (유효 프레임 폭의 0.1 백분위), 소수 1자리 → 0.5 × 2.0 = 1.0.
   - 표준편차 = 0.5 × (유효 프레임 표준편차의 0.1 백분위), 소수 2자리 → 0.5 × 0.432 = 0.22.
4. **확인 자료 점수와 합격 기준(값을 정한 뒤에는 바꾸지 않는다).**
   - A1 확인 자료의 맞은 열 보존율 ≥ 99.5 %
   - A2 확인 자료의 통과 열 정밀도 ≥ 0.95이고 옛 기준보다 높다
   - A3 높은 자세(벽이 안 보이고 빔과 바닥뿐인 화면) 열 통과율이 옛 기준을 넘지 않는다
   - A4 확인 자료 유효 프레임 거짓 거부율 ≤ 0.5 %
   - A5 나쁜 프레임 거짓 수락률이 옛 기준을 넘지 않고, 단색 프레임은 모두 거부
5. **적용 범위.** 화면 대비 두 값은 공용 파일 `harness/zone_pair_vision.py`를 고치지 않고 v98 전용 모듈 `harness/zone_pair_highpose_frame_gate.py`로만 적용한다. 공용 파일은 이전 번들이 바이트로 고정하므로 main과 같아야 한다. v98 클래스는 얼린 메서드 코드를 그대로 쓰되, 그 안의 `from harness.zone_pair_vision import ...`가 v98 값을 받도록 개인 builtins로 묶는다(프로세스 전역 상태 없음). 레지스트리 `frame_gate`에 프로필 ID를 고정한다.
6. **기록.** `configs/calibration/own_image_gates_floor_light_v1.json`에 값, 규칙, 자료 sha256, 백분위 표, 결과, 합격 여부를 둔다. 이 파일의 sha256을 번들 레지스트리(`configs/zone_pair_highpose_v98.json`의 `own_image_gates`)에 고정하고, 제공자의 `runtime_contract`에 경로와 해시를 넣어 실행 식별자(`identity_sha256`)가 값에 따라 바뀌게 한다. 기준을 바꾸려면 새 파일, 새 해시, 새 번들 ID로 낸다.

## 5. 한계와 다시 해야 하는 때

- 나쁜 화면은 합성이다. 균일 회색 덮개(30·60 %)는 밝기 검사로 못 잡고, 옛 기준과 새 기준 모두 그대로 통과한다.
- 흐림·가림(REVIEW_363 4차 검토자 오프라인 측정, 추가 조정 없음): 프레임 수준 문턱(대비 폭·표준편차)은 옛 값·새 값 모두
  흐림 σ3/8/16, 가로 움직임 흐림 31/81 px, 세로 41 px, 열 폭 30/50 % 가림을 100 % 통과시킨다. 이 문턱은 흐림·가림 탐지기가
  아니다. 열 수준 오답 열 수(새 대 옛): σ3 96 대 794, σ8 409 대 2734, 가로 31 px 245 대 902, 가로 81 px 781 대 1096. σ8에서는
  남은 592열 중 409열이 오답이고, 가로 81 px에서 19 %, 흐림 없음에서 0.4 %다. 30 % 이상 검은 가림은 바뀌지 않은 어두움
  비율 규칙이 거른다.
- 폐루프(실제 운반 성공)로는 검증하지 않았다. 열 단위와 오프라인 재생까지만이다.
- 보정 자료는 DEV 보정 실행이다. 조명·렌더 프로필·카메라·로봇 외관이 바뀌면 이 절차를 처음부터 다시 한다. `python3 scripts/calibrate_own_image_gates.py --outputs <outputs> --calibration <DEV 보정 json> --out <새 json>`
- 이 기준은 푸른 바닥·벽(S 57~91)을 전제로 정했다. 지도 색이 다른 최종 연구 지도에서는 확인 자료를 새로 만들어 A1~A5를 다시 통과시킨다.
